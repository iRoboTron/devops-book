# Глоссарий

> Термины и выражения книги «Prometheus + Grafana + Loki: Production-мониторинг». В скобках — главы, где термин вводится или активно используется.

---

**Мониторинг (monitoring)** — непрерывный сбор, хранение и анализ данных о состоянии систем, чтобы видеть проблемы во времени, а не только в момент `kubectl`-команды. _(глава 0)_

**Метрика (metric)** — числовой показатель состояния системы (использование памяти, число запросов, задержка), измеряемый во времени. _(главы 0, 1, 2)_

**Time series (временной ряд)** — последовательность пар «временная метка → значение» для одной метрики с конкретным набором labels. _(главы 1, 2)_

**Sample (сэмпл)** — одно измерение временного ряда: значение метрики в конкретный момент времени. _(глава 1)_

**TSDB (Time Series Database)** — встроенное в Prometheus хранилище временных рядов, оптимизированное под запись и выборку метрик. _(глава 1)_

**Prometheus** — система сбора и хранения метрик, работающая по pull-модели и предоставляющая язык запросов PromQL. _(главы 1, 2)_

**Pull-модель** — модель сбора, при которой Prometheus сам периодически запрашивает метрики у таргетов, а не ждёт, пока их пришлют. _(глава 1)_

**Push-модель** — обратная модель, при которой источник сам отправляет данные приёмнику; так работает Promtail при отправке логов в Loki. _(главы 1, 6)_

**Scrape (скрейп)** — однократный HTTP-запрос Prometheus к эндпоинту `/metrics` таргета для сбора текущих значений метрик. _(главы 1, 3)_

**Scrape interval** — периодичность скрейпа (в книге — 15 секунд), с которой Prometheus опрашивает таргеты. _(главы 1, 3)_

**Target (таргет)** — конкретный эндпоинт, который Prometheus скрейпит; в UI виден в `Status → Targets` со статусом `UP`/`DOWN`. _(главы 1, 3)_

**Job** — логическая группа однотипных таргетов с общим именем (label `job`), например `job="myapp"`. _(глава 3)_

**Эндпоинт `/metrics`** — HTTP-путь, по которому приложение или экспортер отдаёт метрики в текстовом формате Prometheus. _(главы 1, 3)_

**Метрика `up`** — служебная метрика Prometheus: `1` если таргет успешно скрейпится, `0` если недоступен. _(главы 1, 3)_

**Exporter (экспортер)** — сервис, который собирает метрики из системы или приложения и отдаёт их в формате Prometheus по `/metrics`. _(главы 1, 3)_

**Node Exporter** — экспортер метрик уровня ноды: CPU, память, диск, сеть, load average. _(главы 1, 4)_

**kube-state-metrics** — компонент, отдающий метрики о состоянии объектов Kubernetes (Pod, Deployment, рестарты и т.д.). _(глава 1)_

**kube-prometheus-stack** — Helm chart, разворачивающий сразу Prometheus, Grafana, Alertmanager, Node Exporter и kube-state-metrics. _(глава 1)_

**Prometheus Operator** — оператор Kubernetes, который превращает ресурсы `ServiceMonitor` и `PrometheusRule` в конфигурацию Prometheus. _(главы 1, 3, 5)_

**ServiceMonitor** — CRD, который по `matchLabels` указывает Prometheus, какие Service скрейпить и по какому пути. _(глава 3)_

**Label (метка)** — пара «ключ=значение», уточняющая временной ряд (например `status="500"`, `pod="myapp-1"`); основа фильтрации и группировки. _(главы 2, 3, 6)_

**Selector / matchLabels** — набор labels, по которому ресурс (ServiceMonitor, Service) выбирает цели; несовпадение labels — частая причина «Prometheus не видит сервис». _(глава 3)_

**PromQL** — язык запросов Prometheus для выборки и агрегации временных рядов. _(главы 2, 4)_

**Counter (счётчик)** — тип метрики, который только растёт (например `http_requests_total`); анализируется через `rate()`. _(главы 2, 3)_

**Gauge** — тип метрики, значение которого может расти и падать (например `container_memory_usage_bytes`). _(главы 0, 2)_

**Histogram (гистограмма)** — тип метрики, распределяющий наблюдения по бакетам (`..._bucket`); из неё считают квантили задержки. _(главы 2, 3)_

**`rate()`** — функция PromQL, вычисляющая среднюю скорость роста counter за интервал (например `rate(http_requests_total[5m])`). _(главы 2, 4)_

**`sum by ()`** — агрегация PromQL, суммирующая ряды с группировкой по указанным labels. _(глава 2)_

**`histogram_quantile()`** — функция PromQL, оценивающая квантиль (например P99 задержки) по бакетам гистограммы. _(главы 2, 3)_

**P99 latency** — 99-й перцентиль времени ответа: задержка, в которую укладывается 99% запросов. _(главы 2, 3, 4)_

**RED метрики** — три ключевых показателя сервиса: Rate (запросы/с), Errors (доля ошибок), Duration (задержка). _(главы 2, 3, 4)_

**Error rate (доля ошибок)** — отношение числа ошибочных ответов (5xx) к общему числу запросов. _(главы 2, 4, 5)_

**Инструментирование (instrumentation)** — добавление в код приложения метрик через клиентскую библиотеку, например `prometheus-client`. _(глава 3)_

**prometheus-client** — Python-библиотека для создания метрик (Counter, Histogram) и отдачи их по `/metrics`. _(глава 3)_

**Grafana** — система визуализации, строящая дашборды по данным из Prometheus, Loki и других datasource. _(глава 4)_

**Datasource (источник данных)** — настроенное в Grafana подключение к системе данных (Prometheus, Loki) по URL. _(главы 4, 6)_

**Dashboard (дашборд)** — набор панелей Grafana, отображающих метрики или логи; может импортироваться по ID. _(глава 4)_

**Panel (панель)** — отдельный элемент дашборда с одним PromQL/LogQL-запросом и визуализацией. _(глава 4)_

**Variable (переменная дашборда)** — параметр (например `$namespace`), подставляемый в запросы, чтобы один дашборд работал для dev/staging/prod. _(глава 4)_

**Alertmanager** — компонент, который принимает firing-алерты от Prometheus, группирует, маршрутизирует и рассылает их по каналам. _(глава 5)_

**Alert rule (правило алерта)** — выражение PromQL с условием и выдержкой `for`, при выполнении которого генерируется алерт. _(глава 5)_

**PrometheusRule** — CRD, в котором описываются группы alert-правил для Prometheus. _(главы 5, приложение)_

**`for`** — длительность, в течение которой условие алерта должно держаться истинным, прежде чем алерт станет `Firing`. _(глава 5)_

**Pending / Firing** — состояния алерта: `Pending` — условие истинно, но `for` ещё не выдержан; `Firing` — выдержка прошла, алерт активен и отправлен. _(глава 5)_

**Receiver (получатель)** — назначение в Alertmanager, описывающее канал доставки (например `telegram_configs`). _(глава 5)_

**Route (маршрут)** — правила Alertmanager, определяющие, какой алерт в какой receiver попадёт и как группируется. _(глава 5)_

**group_by / group_wait / repeat_interval** — параметры группировки Alertmanager: по каким labels объединять, сколько ждать перед отправкой и как часто повторять уведомление. _(глава 5)_

**resolve_timeout** — время, после которого Alertmanager считает алерт решённым, если условие перестало выполняться. _(глава 5)_

**Loki** — система агрегации логов от Grafana, индексирующая логи по labels, а не по содержимому. _(главы 6, 7)_

**Promtail** — агент, который собирает логи с Pod'ов на ноде, добавляет labels и отправляет их в Loki. _(глава 6)_

**loki-stack** — Helm chart для установки Loki вместе с Promtail. _(глава 6)_

**LogQL** — язык запросов Loki для выборки и фильтрации логов по labels и содержимому. _(глава 7)_

**Фильтр по строке (`|=`, `|~`)** — операторы LogQL: `|=` ищет точную подстроку, `|~` — по регулярному выражению. _(глава 7)_

**Парсер `| json`** — этап LogQL, разбирающий JSON-логи на поля для фильтрации (например `| json | level="error"`). _(глава 7)_

**Корреляция метрик и логов** — приём расследования: увидев спайк на дашборде (что и когда), перейти к логам Loki за тот же интервал (почему). _(глава 7)_

**Explore** — режим Grafana для интерактивных ad-hoc запросов к datasource, в том числе к логам Loki. _(главы 6, 7)_

**Memory leak (утечка памяти)** — постепенный неконтролируемый рост потребления памяти; видна в Prometheus как растущий gauge `container_memory_usage_bytes`. _(главы 0, 2)_

**port-forward** — проброс порта сервиса K8s на localhost (`kubectl port-forward`) для доступа к Prometheus UI или Grafana. _(глава 1)_

**StorageClass / PVC** — механизм динамического выделения постоянных томов в K8s; отсутствие подходящего StorageClass оставляет Pod в `Pending`. _(глава 1)_
