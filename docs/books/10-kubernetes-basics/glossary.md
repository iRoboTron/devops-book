# Глоссарий

> Термины и выражения книги «Основы Kubernetes». В скобках — главы, где термин вводится или активно используется.

---

**Kubernetes (K8s)** — платформа оркестрации контейнеров, которая следит за желаемым состоянием приложения на множестве хостов. _(глава 0)_

**Control Plane (управляющий слой)** — набор компонентов, которые управляют кластером: API Server, etcd, Scheduler, Controller Manager. _(глава 0)_

**Worker Node (рабочая нода)** — сервер кластера, на котором реально запускаются Pod'ы. _(главы 0, 1)_

**Node (нода)** — машина (физическая или виртуальная) в составе кластера. _(главы 0, 7)_

**API Server** — единая точка входа в кластер: принимает все команды (в том числе от kubectl) и общается с остальными компонентами. _(главы 0, 7)_

**etcd** — распределённое хранилище ключ-значение, где хранится всё состояние кластера. _(глава 0)_

**Scheduler (планировщик)** — компонент Control Plane, который решает, на какую ноду поставить новый Pod, исходя из `requests` и доступных ресурсов. _(главы 0, 7, 10)_

**Controller Manager** — компонент, запускающий контроллеры, которые следят за соответствием фактического состояния желаемому. _(глава 0)_

**kubelet** — агент на каждой ноде: получает задания от API Server, запускает контейнеры и сообщает их статус. _(главы 0, 7)_

**Reconciliation loop (цикл сверки)** — непрерывный процесс сравнения желаемого и фактического состояния с приведением кластера к желаемому. _(глава 2)_

**Желаемое состояние (desired state)** — описанная в манифесте конфигурация, которую K8s старается постоянно поддерживать. _(главы 0, 2)_

**k3s** — лёгковесный дистрибутив Kubernetes в одном бинарнике, удобный для обучения и запуска на VPS. _(глава 0)_

**kubectl** — консольная утилита для управления кластером: отправляет команды в API Server. _(главы 0, 1, 8)_

**Pod (под)** — минимальная развёртываемая единица в Kubernetes: один или несколько контейнеров с общей сетью и хранилищем. _(главы 1, 2)_

**Контейнер** — изолированный процесс с приложением; внутри Pod может быть один или несколько контейнеров. _(главы 1, 4)_

**Манифест** — YAML-файл с описанием объекта Kubernetes (`apiVersion`, `kind`, `metadata`, `spec`). _(главы 1, 7)_

**Label (метка)** — пара ключ-значение на объекте; по ним группируют и находят объекты. _(главы 1, 3)_

**Selector (селектор)** — правило отбора объектов по их labels; используется Service и Deployment. _(главы 2, 3)_

**Deployment** — контроллер, управляющий репликами Pod через ReplicaSet: самовосстановление, масштабирование, обновления. _(главы 2, 7, 9)_

**ReplicaSet** — объект, поддерживающий заданное число одинаковых Pod; создаётся Deployment'ом. _(глава 2)_

**Replicas (реплики)** — количество одинаковых копий Pod, которое держит Deployment/ReplicaSet. _(главы 2, 7)_

**Самовосстановление (self-healing)** — автоматическое пересоздание упавшего или удалённого Pod контроллером. _(глава 2)_

**Масштабирование (scaling)** — изменение числа реплик командой `kubectl scale`. _(главы 2, 8)_

**Rolling update** — обновление Pod'ов по одному без даунтайма: сначала поднимается новый, потом удаляется старый. _(главы 2, 9)_

**Откат (rollback)** — возврат Deployment к предыдущей ревизии командой `kubectl rollout undo`. _(главы 2, 9)_

**Ревизия (revision)** — сохранённая версия Deployment в истории `kubectl rollout history`. _(главы 2, 9)_

**Service** — объект, дающий стабильный сетевой адрес группе Pod и балансирующий между ними трафик. _(главы 3, 7)_

**ClusterIP** — тип Service по умолчанию: доступен только внутри кластера. _(глава 3)_

**NodePort** — тип Service, открывающий порт на каждой ноде для доступа снаружи. _(главы 3, 7)_

**Endpoints** — фактический список IP:порт Pod'ов, на которые Service шлёт трафик. _(глава 3)_

**targetPort** — порт контейнера, на который Service пересылает трафик. _(главы 3, 7)_

**ConfigMap** — объект для хранения несекретной конфигурации (аналог `.env`). _(главы 4, 7)_

**Secret** — объект для секретов; данные кодируются в base64 (это не шифрование). _(главы 4, 7)_

**base64** — обратимое кодирование, в котором хранятся значения Secret; легко декодируется, шифрованием не является. _(глава 4)_

**envFrom** — способ подключить все ключи ConfigMap или Secret как переменные окружения контейнера. _(главы 4, 7)_

**Volume (том)** — хранилище, подключаемое к контейнеру; обычное volume живёт пока живёт Pod. _(глава 5)_

**PersistentVolume (PV)** — реальный кусок хранилища в кластере, переживающий пересоздание Pod. _(глава 5)_

**PersistentVolumeClaim (PVC)** — запрос на постоянное хранилище заданного объёма и режима доступа. _(главы 5, 7)_

**StorageClass** — описание класса хранилища и провижинера, динамически создающего PV (в k3s — `local-path`). _(глава 5)_

**AccessMode** — режим доступа к тому: `ReadWriteOnce`, `ReadOnlyMany`, `ReadWriteMany`. _(глава 5)_

**Bound** — статус PVC, означающий, что он успешно привязан к PV. _(глава 5)_

**volumeMount** — точка монтирования тома внутрь файловой системы контейнера. _(главы 5, 7)_

**Namespace** — виртуальное разделение кластера для изоляции окружений (dev/prod). _(глава 6)_

**kube-system** — системный namespace для компонентов самого Kubernetes. _(глава 6)_

**DNS-имя сервиса** — адрес вида `<service>.<namespace>.svc.cluster.local` для обращения между namespace. _(глава 6)_

**requests** — гарантированный минимум ресурсов (CPU/память), нужный Scheduler для размещения Pod. _(главы 2, 10)_

**limits** — верхний предел ресурсов контейнера; превышение памяти ведёт к OOMKilled. _(главы 2, 10)_

**millicore (m)** — единица CPU: `1000m` = 1 ядро, `50m` = 5% ядра. _(глава 10)_

**OOMKilled** — статус Pod, убитого за превышение лимита памяти, с последующим перезапуском. _(глава 10)_

**livenessProbe** — проверка «жив ли» контейнер; при провале Pod перезапускается. _(глава 10)_

**readinessProbe** — проверка готовности контейнера принимать трафик; при провале Pod убирается из Service. _(глава 10)_

**Pending** — статус Pod или PVC, ожидающего размещения/ресурсов. _(главы 1, 5)_

**CrashLoopBackOff** — статус Pod, контейнер которого постоянно падает при старте. _(главы 1, 8)_

**ImagePullBackOff** — статус Pod, когда не удаётся скачать образ контейнера. _(главы 1, 8)_

**Running** — статус Pod, означающий, что контейнеры работают. _(главы 1, 7)_

**Events (события)** — раздел в выводе `kubectl describe`, где кластер пишет, что он пытался сделать с объектом и почему не смог; первое, что смотрят при диагностике. _(глава 11)_

**`kubectl describe`** — команда, показывающая подробности объекта и его Events; основной инструмент диагностики. _(главы 8, 11)_

**`logs --previous`** — логи предыдущего, уже упавшего запуска контейнера; нужны при `CrashLoopBackOff`. _(глава 11)_

**`kubectl debug` / ephemeral container** — временный отладочный контейнер, подсаживаемый в работающий Pod без перезапуска (полезен для «тонких» образов без shell). _(глава 11)_

**Node NotReady** — статус ноды, на которой сломался `kubelet` или пропала сеть/диск; Pod'ы на неё не ставятся. _(глава 11)_

**CoreDNS** — внутренний DNS кластера, резолвящий имена сервисов; живёт в namespace `kube-system`. _(главы 11, 12)_

**CNI (Container Network Interface)** — плагин сети между Pod'ами (Flannel/Calico/Cilium); отвечает за то, видят ли Pod'ы друг друга. _(главы 11, 12)_

**crictl** — низкоуровневая CLI для container runtime на ноде (аналог `docker` уровнем ниже kubelet). _(глава 11)_

**RBAC (Role-Based Access Control)** — система прав в кластере: `Role`/`ClusterRole` описывают разрешения, `RoleBinding` выдаёт их субъекту. _(глава 12, подробно — Том 11)_

**ServiceAccount** — «учётная запись» для приложений в кластере, которой выдаются права через RBAC. _(глава 12)_

**NetworkPolicy** — правила, ограничивающие сетевой трафик между Pod'ами (модель «default deny»). _(глава 12, подробно — Том 11)_

**taint / toleration** — «пометка» на ноде (taint), отталкивающая обычные Pod'ы, и разрешение (toleration), позволяющее Pod'у на неё попасть. _(глава 12)_

**node affinity** — правило «притянуть» Pod к нодам с нужными метками (`required` — обязательно, `preferred` — желательно). _(глава 12)_

**SecurityContext** — настройки безопасности контейнера: `runAsNonRoot`, `readOnlyRootFilesystem`, сброс `capabilities`. _(глава 12, подробно — Том 18)_

**Pod Security Standards (PSS)** — три уровня политики безопасности Pod: `privileged`, `baseline`, `restricted`. _(глава 12)_

**DaemonSet** — контроллер, запускающий по одному Pod на каждой ноде (агенты логов/мониторинга, сетевые плагины). _(глава 12)_

**Job** — задача, которая должна выполниться один раз и завершиться (миграция, разовый расчёт). _(глава 12)_

**CronJob** — `Job` по расписанию (как `cron`). _(глава 12)_

**kubeadm** — инструмент сборки «ванильного» кластера Kubernetes своими руками (в т.ч. HA, multi-master). _(глава 12)_

**Managed Kubernetes** — кластер как услуга: control plane и etcd обслуживает провайдер (Yandex MK, VK Cloud, SberCloud). _(глава 12)_

**Dynamic provisioning (динамическое выделение)** — автоматическое создание PV под запрос PVC через StorageClass (без ручного создания дисков). _(глава 5)_

**reclaimPolicy** — что станет с диском при удалении PVC: `Delete` (удалить данные) или `Retain` (сохранить). _(глава 5)_

**QoS-класс** — класс качества обслуживания Pod (`Guaranteed`/`Burstable`/`BestEffort`), определяющий порядок «выселения» при нехватке памяти. _(глава 10)_
