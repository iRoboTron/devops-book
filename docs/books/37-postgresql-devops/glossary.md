# Глоссарий

> Термины и выражения книги «PostgreSQL для DevOps». В скобках — главы, где термин вводится или активно используется.

---

**PostgreSQL** — реляционная СУБД с открытым кодом, частый выбор для production. _(глава 0)_

**Кластер БД** — инстанс PostgreSQL со своим каталогом данных (не путать с «кластером серверов»). _(глава 1)_

**`postgresql.conf`** — основной файл конфигурации сервера. _(глава 1)_

**`data directory` (PGDATA)** — каталог, где физически лежат данные кластера. _(глава 1)_

**Роль (role)** — пользователь или группа в PostgreSQL; объединяет логин и права. _(глава 2)_

**Привилегии / `GRANT`** — выдача прав роли на объекты (таблицы, схемы). _(глава 2)_

**Схема (schema)** — пространство имён внутри базы для группировки объектов. _(глава 2)_

**`pg_hba.conf`** — файл правил аутентификации: кто, откуда и как может подключиться. _(глава 3)_

**SSL/TLS-подключение** — шифрованный канал к базе. _(глава 3)_

**`pg_dump` / `pg_restore`** — логический бэкап и восстановление базы. _(глава 4)_

**`pg_basebackup`** — физический бэкап всего кластера на уровне файлов. _(глава 4)_

**WAL (Write-Ahead Log)** — журнал предзаписи: все изменения сначала пишутся в него. _(глава 5)_

**PITR (Point-In-Time Recovery)** — восстановление на произвольный момент времени из базового бэкапа + WAL. _(глава 5)_

**`archive_mode` / archiving** — архивирование WAL-сегментов для PITR. _(глава 5)_

**Checkpoint** — момент сброса изменений из памяти на диск. _(глава 5)_

**VACUUM / autovacuum** — очистка «мёртвых» строк (dead tuples) и обновление статистики. _(глава 13)_

**MVCC** — модель версионирования строк, позволяющая читателям не блокировать писателей. _(глава 13)_

**Dead tuple / bloat** — устаревшие версии строк и «распухание» таблиц/индексов из-за них. _(глава 13)_

**`pg_stat_statements`** — расширение со статистикой по запросам (поиск медленных). _(глава 7)_

**`EXPLAIN` / `EXPLAIN ANALYZE`** — план выполнения запроса (и реальные тайминги). _(глава 7)_

**Seq Scan / Index Scan** — последовательное чтение таблицы vs чтение по индексу. _(глава 7)_

**Индекс** — структура для быстрого поиска по столбцам. _(глава 7)_

**Connection Pooling** — переиспользование соединений к БД вместо открытия нового на каждый запрос. _(глава 8)_

**PgBouncer** — лёгкий пул соединений перед PostgreSQL. _(глава 8)_

**Репликация (streaming replication)** — потоковая передача WAL на реплики. _(глава 9)_

**Primary / Standby** — основной сервер (пишет) и реплика (повторяет за ним). _(глава 9)_

**Read replica** — реплика для чтения, разгружающая основной сервер. _(глава 9)_

**Replication lag** — отставание реплики от основного сервера. _(глава 9)_

**Hot standby** — реплика, доступная для чтения во время репликации. _(глава 9)_

**`shared_buffers` / `work_mem`** — ключевые параметры памяти PostgreSQL. _(глава 13)_

**`pgbench`** — встроенный инструмент нагрузочного тестирования. _(глава 13)_

**Миграция expand/contract** — безопасное изменение схемы без даунтайма в два этапа. _(глава 11)_

**Транзакция** — атомарная группа операций (всё или ничего). _(глава 0)_
