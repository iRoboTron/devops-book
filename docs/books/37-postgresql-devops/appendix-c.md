# Приложение C: Чеклист production PostgreSQL

Перед выходом в production пройдите по каждому пункту. Если пункт не выполнен — у вас есть задача на ближайший спринт.

## Бэкапы и восстановление

- [ ] Бэкапы настроены и протестированы (ежедневный pg_dump или pg_basebackup)
- [ ] WAL-архивирование настроено (для PITR)
- [ ] Тест восстановления проведён и записан результат (дата, время, версия бэкапа)
- [ ] Бэкапы хранятся на другом сервере или в S3 (не на том же диске, что данные)

## Мониторинг и алерты

- [ ] postgres_exporter + Grafana дашборд настроены
- [ ] Алерт на pg_up = 0 (PostgreSQL недоступен)
- [ ] Алерт на replication lag > 60s
- [ ] Алерт на disk usage > 80% на диске с данными
- [ ] Алерт на idle in transaction > 20
- [ ] log_min_duration_statement = 1000 (медленные запросы логируются)

## Соединения и пулинг

- [ ] PgBouncer настроен, если ожидается > 20 одновременных соединений
- [ ] Пользователь postgres не используется приложением (только для администрирования)
- [ ] max_connections соответствует реальным потребностям (не больше, чем нужно)
- [ ] superuser_reserved_connections = 3 (запас для админа)

## Безопасность

- [ ] SSL включён (hostnossl reject в pg_hba.conf)
- [ ] В pg_hba.conf нет правил с методом `trust` для внешних адресов

## Производительность

- [ ] autovacuum включён (никогда не выключать)
- [ ] shared_buffers = 25% RAM (макс. 8GB)
- [ ] work_mem рассчитан: work_mem x max_connections <= RAM - shared_buffers

## Инфраструктура

- [ ] Версия PostgreSQL зафиксирована (не `latest` в Docker, а конкретный минор)
- [ ] Пароль postgres изменён с дефолтного
- [ ] pg_stat_statements включён
