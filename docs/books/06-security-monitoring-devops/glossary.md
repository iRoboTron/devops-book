# Глоссарий

> Термины и выражения книги «Безопасность и мониторинг для DevOps». В скобках — главы, где термин вводится или активно используется.

---

## Безопасность: модель угроз

**Модель угроз** — описание того, кто и зачем атакует систему, и какие защитные слои этому противопоставляются. Помогает не защищаться «вообще», а закрывать реальные риски. _(глава 0)_

**Поверхность атаки** — совокупность всех точек, через которые систему можно атаковать: открытые порты, запущенные сервисы, пользователи, версии ПО. Чем она меньше, тем меньше уязвимостей. _(главы 0, 4)_

**Бот-сканер** — автоматическая программа, круглосуточно сканирующая интернет в поисках открытых портов и слабых паролей. Основной источник атак на небольшие серверы. _(глава 0)_

**Брутфорс** — перебор паролей (или ключей) методом «грубой силы»: бот пробует тысячи комбинаций, пока не угадает. Защита — ключи и fail2ban. _(главы 0, 1, 2)_

**Криптомайнер** — вредоносная программа, которая после взлома использует CPU сервера для майнинга криптовалюты в пользу атакующего. _(глава 0)_

**Ransomware** — программа-шантажист: шифрует данные и требует выкуп. Главная защита — рабочие бэкапы. _(глава 0)_

**Zero-day (нулевой день)** — уязвимость, для которой ещё нет патча. Для маленьких серверов почти не актуальна — слишком дорогой инструмент. _(глава 0)_

**Защита в глубину (слои)** — принцип, при котором безопасность строится из нескольких независимых слоёв: SSH-ключи, fail2ban, ufw, мониторинг, бэкапы. Пробить нужно каждый. _(главы 0, 9)_

**Hardening** — укрепление системы: отключение лишнего, ужесточение настроек, закрытие портов — приведение сервера к безопасной конфигурации. _(главы 4, 9)_

## SSH и доступ

**SSH** — протокол защищённого удалённого доступа к серверу по шифрованному каналу. _(главы 1, 5, 9)_

**sshd_config** — файл конфигурации SSH-сервера (`/etc/ssh/sshd_config`), где задаются правила входа. _(глава 1)_

**SSH-ключ** — пара криптографических ключей (приватный + публичный) для входа без пароля. Подобрать перебором практически невозможно. _(главы 1, 9)_

**authorized_keys** — файл со списком публичных ключей, которым разрешён вход под данным пользователем. _(глава 1)_

**PermitRootLogin** — параметр sshd, запрещающий (`no`) прямой вход под root. Заходят как обычный пользователь, затем `sudo`. _(главы 1, 9)_

**PasswordAuthentication** — параметр sshd; `no` отключает вход по паролю, оставляя только ключи. _(главы 1, 9)_

**MaxAuthTries** — максимальное число попыток аутентификации за одно соединение SSH. Усложняет брутфорс. _(главы 1, 9)_

**AllowUsers** — параметр sshd, ограничивающий список пользователей, которым разрешён вход по SSH. _(глава 1)_

**reload vs restart** — `reload` применяет новый конфиг без обрыва текущих соединений; `restart` обрывает все сессии. Для sshd важно использовать `reload`. _(глава 1)_

## fail2ban и фаервол

**fail2ban** — сервис, который читает логи, находит подозрительную активность и автоматически блокирует IP через iptables. _(главы 2, 6, 9)_

**jail (тюрьма)** — единица конфигурации fail2ban: связка «лог + фильтр + правила бана» для конкретного сервиса (например `sshd`, `nginx-http-auth`). _(глава 2)_

**jail.local** — пользовательский файл настроек fail2ban, который не перезаписывается при обновлении (в отличие от `jail.conf`). _(глава 2)_

**bantime** — время, на которое IP блокируется после превышения лимита попыток. _(глава 2)_

**findtime** — окно времени, за которое fail2ban считает неудачные попытки. _(глава 2)_

**maxretry** — число неудачных попыток за `findtime`, после которого IP банится. _(глава 2)_

**ignoreip (whitelist)** — список IP, которые fail2ban никогда не блокирует. Сюда обязательно добавляют свой адрес. _(глава 2)_

**filter (фильтр fail2ban)** — набор регулярных выражений (`failregex`), по которым fail2ban распознаёт атаку в строках лога. _(глава 2)_

**iptables** — подсистема ядра Linux для фильтрации сетевых пакетов; fail2ban добавляет в неё правила DROP для забаненных IP. _(глава 2)_

**ufw** — упрощённый фронтенд для фаервола: открывает только нужные порты (22, 80, 443), закрывая остальное. _(главы 0, 9)_

## Обновления

**unattended-upgrades** — пакет, автоматически устанавливающий обновления безопасности системы по расписанию. _(главы 3, 9)_

**Фиксированный тег** — точное указание версии Docker-образа (например `python:3.12.3-slim`) вместо `latest` ради предсказуемости и контроля обновлений. _(глава 3)_

**Сканирование уязвимостей** — проверка Docker-образа на известные CVE инструментами вроде Trivy или Docker Scout. _(глава 3)_

## Аудит системы

**SUID/SGID** — особые права файла, при которых он запускается от имени владельца (часто root), а не запустившего пользователя. Нестандартные SUID-файлы подозрительны. _(глава 4)_

**lynis** — инструмент автоматического аудита безопасности Linux, выдающий рекомендации и оценку. _(главы 4, 9)_

**Hardening Index** — итоговая оценка защищённости системы по версии lynis (0–100); цель курса — выше 70. _(главы 4, 9)_

**nmap** — сетевой сканер, показывающий с внешней машины, какие порты сервера реально открыты наружу и какие сервисы за ними. _(глава 4)_

## Мониторинг

**Мониторинг** — непрерывное наблюдение за состоянием сервера, заменяющее круглосуточный взгляд человека в терминал. _(главы 5, 6, 9)_

**Метрика** — числовой показатель состояния системы во времени: загрузка CPU, использование RAM, занятость диска, сетевой трафик. _(глава 5)_

**Дашборд** — наглядная панель с графиками метрик в реальном времени (в Netdata — веб-интерфейс на порту 19999). _(глава 5)_

**Netdata** — лёгкий инструмент мониторинга, разворачиваемый одной командой и показывающий метрики сервера, Docker, Nginx и PostgreSQL. _(главы 5, 9)_

**SSH-туннель** — проброс порта через зашифрованное SSH-соединение (`ssh -L`), позволяющий безопасно открыть локально сервис, закрытый от интернета. _(главы 5, 9)_

**Порог (threshold)** — граничное значение метрики, при пересечении которого срабатывает алерт (например диск > 80%). _(главы 5, 6)_

## Алертинг

**Алерт** — автоматическое уведомление о проблеме (упавший сервис, переполненный диск, бан IP), отправляемое в Telegram или email. _(главы 5, 6, 9)_

**health-monitor.sh** — скрипт, который по cron каждые 5 минут проверяет ключевые показатели сервера и шлёт алерт в Telegram только при наличии проблем. _(главы 6, 9)_

**Healthcheck** — проверка работоспособности приложения через специальный endpoint (например `/health`), возвращающий код 200, если всё в порядке. _(главы 6, 8)_

**Telegram-бот** — бот, созданный через @BotFather, который по своему токену отправляет алерты в указанный чат. _(глава 6)_

**Токен бота** — секретный ключ доступа к Telegram-боту; фактически пароль, его нельзя коммитить в git. _(глава 6)_

**cron** — планировщик задач Linux, запускающий скрипты по расписанию (например health-monitor каждые 5 минут, отчёт в 9:00). _(глава 6)_

**Ежедневный отчёт** — регулярное сводное сообщение в Telegram о состоянии сервера (аптайм, диск, RAM, бэкап, баны). _(главы 6, 9)_

## Логи

**Лог** — журнал событий системы или сервиса (`auth.log`, `syslog`, логи Nginx), основной источник информации о происходящем. _(главы 0, 7)_

**auth.log** — лог аутентификации Linux, где видны попытки входа, успешные сессии и действия sudo. _(главы 0, 7)_

**logwatch** — инструмент, агрегирующий объёмные логи в краткий читаемый дайджест (топ IP, число неудачных входов, коды ответов). _(главы 7, 9)_

**goaccess** — анализатор логов Nginx, дающий статистику по IP, URL, кодам ответов и трафику — «аналитика для своего сервера». _(глава 7)_

**User-Agent** — заголовок HTTP, идентифицирующий клиента; значения вроде `sqlmap` или `nikto` выдают инструменты атаки. _(глава 7)_

## Восстановление

**Runbook** — заранее написанная пошаговая инструкция действий при типовых авариях; читается в панике вместо размышлений с нуля. _(главы 8, 9)_

**Эскалация** — последовательность шагов реагирования от самого простого (рестарт) к самому тяжёлому (восстановление из бэкапа), где каждый следующий применяют, если предыдущий не помог. _(глава 8)_

**Rollback (откат)** — возврат приложения или данных к предыдущему рабочему состоянию, в том числе восстановление из бэкапа. _(глава 8)_

**OOM killer** — механизм ядра Linux, который при нехватке памяти принудительно завершает процессы; частая причина «упавшего» сервиса. _(глава 8)_
