# Глоссарий

> Термины и выражения книги «Terraform для DevOps». В скобках — главы, где термин вводится или активно используется.

---

**IaC (Infrastructure as Code)** — подход, при котором инфраструктура описывается кодом в файлах, версионируется в git и применяется автоматически. Главное — воспроизводимость, а не скорость. _(главы 0, 1)_

**Terraform** — инструмент IaC от HashiCorp, который декларативно создаёт и изменяет инфраструктуру по описанию на языке HCL. _(глава 0)_

**HCL (HashiCorp Configuration Language)** — декларативный язык конфигурации Terraform, на котором пишут файлы `.tf`. _(главы 0, 1)_

**Декларативность** — подход «описываешь что должно быть», а не «как сделать»; разницу между желаемым и реальным Terraform вычисляет сам. _(глава 0)_

**Идемпотентность** — свойство, при котором повторный запуск даёт тот же результат: если ресурс уже соответствует коду, Terraform ничего не делает (`No changes`). _(главы 0, 1, 4)_

**Provider (провайдер)** — плагин, через который Terraform общается с сервисом (Hetzner, AWS, локальные файлы). Скачивается командой `terraform init`. _(главы 0, 1, 4)_

**Resource (ресурс)** — основной блок Terraform, описывающий один управляемый объект инфраструктуры (сервер, firewall, файл). _(главы 0, 1)_

**Data source** — блок `data`, который читает существующий объект (например образ ОС), но не создаёт его. _(главы 2, 4)_

**`null_resource`** — ресурс без реальной инфраструктуры; используется для запуска провижинеров и тестов. _(глава 1)_

**`local_file`** — ресурс провайдера `local`, создающий файл на диске; удобен для практики без облака. _(главы 1, 2)_

**`terraform init`** — первая команда в проекте: скачивает провайдеры и модули в `.terraform/`. Запускается при добавлении нового провайдера или модуля. _(главы 0, 1, 6)_

**`terraform plan`** — показывает diff между кодом, state и облаком, не меняя ничего. Самый важный шаг — всегда читается перед apply. _(главы 0, 1)_

**`terraform apply`** — применяет план: вызывает API облака и обновляет state. _(главы 0, 1)_

**`terraform destroy`** — удаляет все ресурсы, которыми управляет Terraform. Такой же штатный инструмент, как `apply`. _(главы 1, 9)_

**`terraform show`** — выводит текущее состояние ресурсов из state-файла. _(глава 1)_

**Символы плана** — обозначения изменений: `+` создать, `~` изменить на месте, `-` удалить, `-/+` удалить и создать заново. _(главы 1, 9)_

**`-auto-approve`** — флаг, выполняющий apply/destroy без запроса подтверждения; опасен в production. _(главы 1, 9)_

**Provisioner (провижинер)** — блок внутри ресурса (`local-exec`, `remote-exec`), запускающий команды при создании ресурса. _(глава 1)_

**`local-exec`** — провижинер, выполняющий команду на локальной машине, где запущен Terraform. _(глава 1)_

**Variable (переменная)** — входной параметр конфигурации (блок `variable`) с полями `type`, `description`, `default`. _(глава 2)_

**`default`** — значение переменной по умолчанию; без него Terraform спросит значение при apply. _(глава 2)_

**Типы переменных** — `string`, `number`, `bool`, `list`, `map`, `object`; задают форму и валидируют значение. _(глава 2)_

**`terraform.tfvars`** — файл со значениями переменных, загружается автоматически. Не коммитится в git (может содержать секреты). _(главы 2, 4)_

**`.tfvars.example`** — шаблон tfvars без секретов; его можно безопасно коммитить в git. _(главы 2, 4)_

**`TF_VAR_`** — префикс переменных окружения; `TF_VAR_name` подставляется в переменную `name` с высшим приоритетом. _(главы 2, 8)_

**Приоритет значений переменных** — порядок от низшего к высшему: `default` → `terraform.tfvars` → `*.auto.tfvars` → `-var` → `TF_VAR_`. _(глава 2)_

**Output (выходное значение)** — блок `output`, который возвращает значение после apply и доступен через `terraform output`. _(главы 2, 4, 6)_

**`sensitive`** — флаг, скрывающий значение переменной или output в выводе (для паролей и токенов). _(главы 2, 4)_

**`.gitignore` для Terraform** — список исключаемых файлов: `.terraform/`, `*.tfstate`, `*.tfvars`; в git попадает `.terraform.lock.hcl`. _(глава 2)_

**`.terraform.lock.hcl`** — lock-файл версий провайдеров; рекомендуется коммитить, чтобы зафиксировать версии. _(глава 2)_

**Locals (`locals`)** — вычисляемые внутри кода значения; в отличие от переменных, их нельзя переопределить извне. _(глава 3)_

**`count`** — мета-аргумент для создания N копий ресурса; `count.index` — порядковый номер копии (0, 1, 2…). _(глава 3)_

**Условный ресурс** — приём `count = condition ? 1 : 0` для включения/выключения ресурса по условию. _(глава 3)_

**`for_each`** — мета-аргумент для создания экземпляров ресурса по множеству или map; `each.value` — текущий элемент. _(глава 3)_

**`for`-выражение** — цикл внутри выражения для трансформации списков и map (`[for n in list : upper(n)]`). _(глава 3)_

**Функции** — встроенные выражения Terraform: `join`, `lookup`, `try`, `merge`, `length`, `jsonencode`, `file` и др. _(главы 3, 4)_

**`file()`** — функция, читающая содержимое файла с локальной машины (например публичный SSH-ключ). _(глава 4)_

**`path.module`** — путь к директории, где лежит текущий `.tf`-файл. _(главы 1, 2)_

**Hetzner / `hcloud`** — облачный провайдер и его Terraform-провайдер `hetznercloud/hcloud`, используемый в книге как реальная инфраструктура. _(глава 4)_

**Граф зависимостей** — граф, который Terraform строит по ссылкам между ресурсами и использует для определения порядка их создания. _(глава 4)_

**`HCLOUD_TOKEN`** — переменная окружения с API-токеном Hetzner для аутентификации провайдера. _(главы 4, 8)_

**State (состояние)** — файл `terraform.tfstate` (JSON), хранящий маппинг «ресурс в коде → ресурс в облаке» (ID и атрибуты). Сердце Terraform. _(главы 0, 5)_

**`terraform.tfstate.backup`** — автоматический бэкап предыдущей версии state-файла. _(глава 5)_

**`terraform state list` / `show`** — команды для просмотра ресурсов в state и их деталей. _(глава 5)_

**`terraform state mv` / `rm`** — команды для переименования ресурса в state или удаления его из state (без удаления в облаке). _(глава 5)_

**Backend** — место хранения state; `local` (по умолчанию) или remote (S3, GCS, Terraform Cloud). _(главы 5, 8)_

**Remote state** — хранение state в облаке с бэкапом и блокировкой; защищает от потери и конфликтов. _(главы 5, 8)_

**State locking (блокировка)** — механизм, не дающий двум процессам менять state одновременно; защищает от поломки инфраструктуры. _(глава 5)_

**`terraform refresh`** — синхронизация state с реальным состоянием облака; встроена в `plan`. _(глава 5)_

**Drift (дрейф)** — расхождение между state и реальной инфраструктурой, возникающее при ручных изменениях в консоли облака. _(глава 5)_

**`terraform import`** — добавляет уже существующий (созданный вручную) ресурс в state; требует затем дописать его код в `.tf`. _(главы 5, 9)_

**Module (модуль)** — переиспользуемый набор ресурсов (`main.tf`, `variables.tf`, `outputs.tf`); DRY для инфраструктуры. _(глава 6)_

**`source`** — аргумент вызова модуля, указывающий откуда брать код (локальный путь или registry). _(глава 6)_

**Terraform Registry** — публичный каталог готовых модулей и провайдеров на `registry.terraform.io`. _(глава 6)_

**Workspace** — изолированный state для одного и того же кода; позволяет держать dev/staging/prod без копирования конфигов. _(глава 7)_

**`terraform.workspace`** — встроенная переменная с именем активного workspace; используется для выбора параметров окружения. _(глава 7)_

**CI/CD для Terraform** — практика «plan на PR, apply на merge»: изменения проверяются автоматически, человек не делает apply вручную. _(глава 8)_

**GitHub Secrets** — защищённое хранилище токенов (например `HCLOUD_TOKEN`) для использования в CI-пайплайнах. _(глава 8)_

**`lifecycle`** — блок управления жизненным циклом ресурса: `prevent_destroy`, `create_before_destroy`. _(глава 9)_

**`prevent_destroy`** — флаг `lifecycle`, запрещающий удаление ресурса; страховка для production-серверов и баз данных. _(глава 9)_

**`create_before_destroy`** — флаг `lifecycle`, при котором новый ресурс создаётся до удаления старого (без даунтайма). _(глава 9)_

**`taint` / `untaint`** — пометка ресурса для пересоздания при следующем apply (план показывает `-/+`) и её отмена. _(глава 9)_

**`-target`** — флаг для применения или удаления только указанного ресурса вместо всего конфига. _(глава 9)_
