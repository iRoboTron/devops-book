# Глава 2: Reverse proxy и веб

> ⏱ Время чтения: ~6 мин.

## Что вы узнаете

- что ставить перед приложением чтобы получить HTTPS и маршрутизацию;
- в чём принципиальная разница между Caddy и Nginx и когда брать каждый;
- когда хватает простого GUI, а когда он только мешает.

---

## Категория 1: Reverse proxy / веб-сервер

### Зачем

Приложение слушает на локальном порту — 3000, 8080, что угодно. Пользователь приходит на домен по 443/HTTPS. Reverse proxy стоит между ними: принимает запрос снаружи, проксирует внутрь, добавляет TLS-терминацию, заголовки безопасности и маршрутизацию между несколькими сервисами на одном сервере. Без него либо открываешь порты напрямую, либо занимаешься сертификатами вручную. Обе опции плохие.

---

### Главная развилка главы

```
Новый проект?
  └─→ Caddy. Авто-HTTPS, Caddyfile три строки, работает из коробки.

Уже на Nginx — команда знает, конфиги написаны?
  └─→ Nginx. Не мигрируй ради миграции.
```

**Если сомневаешься и начинаешь с нуля — бери Caddy. Если проект уже на Nginx — не мигрируй ради миграции.**

---

### Дефолт: Caddy (новый проект)

**Caddy** `self-hosted` `★` `Docker: да`
Единственный reverse proxy с автоматическим HTTPS из коробки: сам получает сертификат Let's Encrypt, сам обновляет его, без certbot и cron. Минимальный Caddyfile — три строки. Потребление памяти сопоставимо с Nginx. Нет привычки к Nginx-конфигам — Caddy сэкономит вечер.

```
# Пример Caddyfile — это всё что нужно для HTTPS
example.com {
    reverse_proxy localhost:3000
}
```

---

### Дефолт: Nginx (легаси и экосистема)

**Nginx** `self-hosted` `★★` `Docker: да`
Стандарт де-факто уже 15 лет. Тысячи готовых конфигов, ответы на Stack Overflow на любой случай, глубокая интеграция с Let's Encrypt через certbot. Если в команде уже есть экспертиза по Nginx или проект начался на нём — оставайся на нём. Сложность конфигурации выше чем у Caddy: location-блоки, upstream, proxy_pass — всё пишется руками.

---

### Альтернативы

| Инструмент | Метки | RAM (прим.) | Когда брать |
|-----------|-------|-------------|-------------|
| HAProxy | `self-hosted` `★★★` `Docker: да` | ~5 МБ | Серьёзный балансировщик нагрузки: sticky sessions, health checks, ACL, L4+L7. Enterprise и высоконагруженные сервисы. |
| Nginx | `self-hosted` `★★` `Docker: да` | ~10 МБ | Стандарт де-факто, тысячи готовых конфигов. Оставайся если уже на нём. |
| Caddy | `self-hosted` `★` `Docker: да` | ~30 МБ | Авто-HTTPS из коробки, минимальный конфиг. Дефолт для нового проекта. |
| Traefik | `self-hosted` `★★` `Docker: да` | ~50 МБ | Docker или Kubernetes: читает labels/annotations и настраивает маршруты автоматически, Let's Encrypt встроен. Если контейнеры — первый кандидат после Caddy. |
| Envoy | `self-hosted` `★★★` `Docker: да` | ~200 МБ | Основа Istio и service mesh в Kubernetes. Нужен только если уже в K8s и настраиваешь mesh. |
| BunkerWeb | `self-hosted` `★★` `Docker: да` | ~200 МБ | Nginx с встроенным WAF (ModSecurity), rate limiting и фильтрацией ботов. Берёшь когда нужна защита из коробки без ручной настройки ModSecurity. |

---

### Когда НЕ нужно

**Когда НЕ нужно (homelab / стартап):** HAProxy и Envoy — оверкилл для одного приложения на одном сервере. HAProxy оправдан когда есть несколько backend-серверов с нетривиальной балансировкой и требованием zero-downtime. Envoy вне Kubernetes почти не применяется. Для одного pet-проекта или стартапа с тремя сервисами — Caddy закроет всё.

**Когда НЕ нужно вообще:** если приложение одно и ты открываешь один порт наружу через облачный load balancer (AWS ALB, Cloudflare Proxy) — reverse proxy на самом сервере может быть лишним слоем. Облачный LB сам занимается TLS.

## Категория 2: GUI для прокси (homelab)

### Зачем

Nginx мощный, но конфиги пишутся вручную. Для homelab где нет желания разбираться в синтаксе `server { location / { proxy_pass ... } }` — существуют GUI-обёртки. Ты добавляешь хост мышкой, указываешь куда проксировать, жмёшь «Save» — SSL получается автоматически.

---

### Дефолт

**Nginx Proxy Manager** `self-hosted` `★` `Docker: да`
Nginx под капотом, управление через браузер. Добавление proxy hosts, SSL через Let's Encrypt, базовая аутентификация — всё без единой строки конфига. Идеален для homelab где живёт 5–10 сервисов и нет желания держать в голове синтаксис Nginx.

---

### Альтернативы

| Инструмент | Метки | RAM (прим.) | Когда брать |
|-----------|-------|-------------|-------------|
| Caddy | `self-hosted` `★` `Docker: да` | ~30 МБ | Если не боишься текстового конфига — Caddy проще NPM и без лишнего слоя. |
| Traefik | `self-hosted` `★★` `Docker: да` | ~50 МБ | Если уже используешь Docker compose — labels в compose-файле вместо GUI. |
| Nginx Proxy Manager | `self-hosted` `★` `Docker: да` | ~150 МБ | Nginx с полноценным UI: proxy hosts, SSL, базовая аутентификация без конфигов. |

---

### Когда НЕ нужно

**Когда НЕ нужно (если умеешь в конфиги):** Nginx Proxy Manager добавляет слой абстракции. Если ты знаешь Nginx — NPM скрывает конфиги, затрудняет тонкую настройку и создаёт дополнительный контейнер. Caddy или Nginx напрямую дадут больше контроля с меньшими накладными расходами.

**Когда НЕ нужно (стартап / enterprise):** GUI-обёртки не пригодны для версионирования конфигурации в Git, не поддаются Ansible/Terraform-автоматизации. В production-среде где конфиги должны быть в репозитории — только Caddy или Nginx с нормальными конфиг-файлами.

## Как выбрать за 30 секунд

```
1. Это новый проект или у тебя нет экспертизы по Nginx?
   - Да → Caddy. Авто-HTTPS, минимальный конфиг. Стоп.
   - Нет, уже на Nginx → Nginx. Не меняй ради изменения.

2. Используешь Docker compose или Kubernetes?
   - Да, и хочу автообнаружение сервисов → Traefik.
   - Нет → возвращайся к пункту 1.

3. Нужен серьёзный L7-балансировщик: sticky sessions, ACL, несколько backend-пулов?
   - Да → HAProxy.
   - Нет → ты смотришь не в ту сторону. Caddy или Nginx.

4. homelab, не хочу разбираться в конфигах вообще?
   - Да → Nginx Proxy Manager. Мышкой, SSL автоматически.
   - Нет → Caddy — короче и прямее.

5. Нужна защита из коробки: WAF, rate limiting, фильтрация ботов?
   - Да → BunkerWeb. Nginx с ModSecurity без ручной настройки.
   - Нет → Caddy или Nginx.
```

## Ключевые тезисы

- Caddy — дефолт для нового проекта: авто-HTTPS, минимальная конфигурация.
- Nginx — дефолт если проект уже на Nginx или нужна огромная база примеров.
- Traefik нужен только когда используешь Docker/K8s с динамическим добавлением сервисов.
- HAProxy — выбор для серьёзного балансировщика в enterprise, не для homelab.
- Nginx Proxy Manager — для тех кто хочет Nginx без конфигов, через UI.
