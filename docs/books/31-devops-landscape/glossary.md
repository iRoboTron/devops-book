# Глоссарий

> Термины и выражения книги «Карта DevOps-ландшафта». В скобках — главы, где термин вводится или активно используется.

---

**homelab** — контекст: один человек, один сервер (VPS или Raspberry Pi), цель — учёба и личная инфраструктура. Приоритет: простота, минимум RAM, бесплатно, запуск за вечер. _(главы 0, 8)_

**стартап** — контекст: команда 2–10 человек, быстрый рост, ограниченный бюджет. Приоритет: скорость запуска, managed-сервисы вместо self-host, масштабирование позже. _(главы 0, 8)_

**enterprise** — контекст: команда, compliance, масштаб. Приоритет: аудит, RBAC, отказоустойчивость, интеграция с корпоративным SSO. _(главы 0, 8)_

**self-hosted** — инструмент, который ставится на собственный сервер; данные и управление остаются у тебя. Противопоставляется SaaS. _(глава 0)_

**SaaS (Software as a Service)** — облачный сервис, за который платишь или регистрируешься; инфраструктуру обслуживает провайдер. _(глава 0)_

**VPN / mesh-сеть** — способ объединить машины за NAT в единую защищённую сеть, где каждая получает стабильный адрес и шифрованный канал. _(глава 1)_

**WireGuard** — VPN-протокол с минимальным кодом и шифрованием на уровне ядра Linux; лежит в основе Tailscale, Headscale и NetBird. _(главы 1, 8)_

**Tailscale** — SaaS mesh-VPN на базе WireGuard с MagicDNS; объединяет устройства за NAT за пять минут без своего сервера-координатора. Дефолт для homelab и стартапа. _(главы 1, 8)_

**обратный туннель** — механизм, дающий локальному процессу публичный URL без открытия портов и проброса NAT; пример — Cloudflare Tunnel, ngrok, frp. _(глава 1)_

**reverse proxy** — сервер между интернетом и приложением: принимает внешний запрос, проксирует внутрь, добавляет TLS-терминацию, заголовки безопасности и маршрутизацию. _(главы 2, 8)_

**Caddy** — reverse proxy с автоматическим HTTPS из коробки: сам получает и обновляет сертификаты Let's Encrypt; декларативный Caddyfile. Дефолт для нового проекта. _(главы 2, 8)_

**Nginx** — веб-сервер и reverse proxy, стандарт де-факто с огромной базой готовых конфигов и интеграцией с Let's Encrypt через certbot. _(главы 2, 8)_

**Let's Encrypt** — бесплатный центр сертификации, выдающий TLS-сертификаты автоматически; используется Caddy, Traefik, certbot. _(глава 2)_

**балансировщик нагрузки (load balancer)** — распределяет трафик между несколькими backend-серверами; в L4/L7-варианте умеет sticky sessions, health checks и ACL (HAProxy). _(главы 2, 8)_

**observability (наблюдаемость)** — способность понять состояние системы по её внешним сигналам; традиционно описывается через три столпа: метрики, логи, трейсы. _(главы 3, 8)_

**метрики** — числовые показатели во времени (CPU, память, RPS); основа графиков и алертов. _(глава 3)_

**логи** — текстовые события с указанием что, когда и в каком компоненте произошло; незаменимы при разборе инцидента. _(глава 3)_

**трейсы (распределённая трассировка)** — путь одного запроса через цепочку сервисов; нужны при микросервисной архитектуре с 10+ компонентами. _(глава 3)_

**Prometheus** — система мониторинга с pull-моделью сбора метрик, локальным хранением временных рядов и языком запросов PromQL. _(главы 3, 8)_

**Grafana** — система визуализации и алертов поверх источников метрик и логов (Prometheus, VictoriaMetrics, Loki). _(главы 3, 8)_

**Grafana Loki** — система хранения логов, индексирующая только метаданные (labels); дешевле ELK по ресурсам, запросы через LogQL. _(глава 3)_

**ELK / OpenSearch** — стек Elasticsearch + Logstash + Kibana (и его форк OpenSearch) для full-text поиска по логам; требует 4+ ГБ RAM. _(глава 3)_

**OpenTelemetry Collector** — vendor-neutral агент сбора метрик, логов и трейсов; промежуточный слой доставки телеметрии в несколько систем. _(глава 3)_

**Alertmanager** — компонент экосистемы Prometheus: принимает алерты, группирует, подавляет дубликаты и маршрутизирует в каналы уведомлений. _(глава 3)_

**менеджер паролей** — зашифрованное хранилище учётных данных людей с синхронизацией, генерацией паролей и контролем доступа; пример — Vaultwarden. _(глава 4)_

**Vaultwarden** — self-hosted сервер протокола Bitwarden на Rust (~20 МБ RAM), совместимый со всеми официальными Bitwarden-клиентами. _(главы 4, 8)_

**управление секретами** — хранение, версионирование, выдача по запросу, ротация и audit trail секретов приложений; стандарт — HashiCorp Vault. _(глава 4)_

**HashiCorp Vault** — отраслевой стандарт управления секретами: AppRole, dynamic secrets, интеграция с Kubernetes, полный audit trail. _(главы 4, 8)_

**dynamic secrets** — временные учётные данные (например пользователь БД), которые Vault создаёт под запрос и удаляет после использования. _(глава 4)_

**SOPS + age** — секреты как зашифрованные файлы прямо в Git: SOPS шифрует YAML/JSON/ENV, age — алгоритм шифрования; без отдельного сервера. _(главы 4, 8)_

**SSO (Single Sign-On)** — единая точка входа: один аккаунт даёт доступ ко всем приложениям через токен по OAuth2/OIDC. _(главы 4, 8)_

**IAM / IdP (Identity Provider)** — система управления идентификацией и доступом: аутентификация, роли, LDAP, MFA, provisioning; примеры — Authentik, Keycloak. _(главы 4, 8)_

**RBAC (Role-Based Access Control)** — управление доступом на основе ролей; требование enterprise, поддерживается Keycloak и Kubernetes. _(главы 4, 6, 8)_

**бэкап** — заранее проверенный план восстановления данных (не просто копия); без теста восстановления бэкапа не существует. _(глава 5)_

**правило 3-2-1** — три копии данных, на двух типах носителей, одна из которых off-site (за пределами основного сервера). _(глава 5)_

**restic** — инструмент бэкапа с дедупликацией и шифрованием по умолчанию: поддерживает S3, SFTP, Backblaze B2, локальный диск; один бинарник. _(главы 5, 8)_

**PostgreSQL** — реляционная СУБД с транзакциями ACID, JSONB, полнотекстовым поиском и богатой экосистемой расширений; дефолтная база. _(главы 5, 8)_

**объектное хранилище** — HTTP-доступный бакет для файлов, масштабируемый горизонтально; де-факто стандарт API — Amazon S3. _(глава 5)_

**MinIO** — self-hosted объектное хранилище с S3-совместимым API в одном контейнере: версионирование, lifecycle policies, event notifications. _(главы 5, 8)_

**Docker** — стандарт де-факто для контейнеров: образы, Docker Hub, команды `docker run` и `docker compose up`. _(главы 6, 8)_

**Docker Compose** — декларативный запуск нескольких контейнеров из одного `compose.yml`; версионируется в Git, достаточно для одного хоста. _(главы 6, 8)_

**Podman** — контейнерный runtime без привилегированного демона: rootless-запуск, совместимость с Docker CLI, стандарт на RHEL/CentOS Stream 9+. _(главы 6, 8)_

**оркестрация** — управление десятками контейнеров на нескольких серверах с автоперезапуском, балансировкой и rolling update. _(главы 6, 8)_

**Kubernetes (K8s)** — система оркестрации контейнеров для нескольких нод: автоскейлинг, rolling/canary, самовосстановление, RBAC. _(главы 6, 8)_

**k3s** — облегчённый дистрибутив Kubernetes от Rancher: один бинарник, менее 512 МБ RAM, полный K8s API; дефолт для homelab. _(главы 6, 8)_

**Forgejo** — лёгкий self-hosted Git-хостинг (форк Gitea) с GitHub-совместимым интерфейсом: issues, pull requests, webhooks, встроенный CI. _(главы 6, 8)_

**CI/CD** — автоматическое выполнение тестов, сборки и деплоя при push в репозиторий (continuous integration / continuous delivery). _(главы 6, 8)_

**GitHub Actions** — встроенная в GitHub CI/CD-система: пайплайны в YAML, маркетплейс готовых actions, бесплатный лимит для публичных репозиториев. _(главы 6, 8)_

**IaC (Infrastructure as Code)** — описание инфраструктуры кодом в репозитории: повторяемо, версионируется, проходит ревью. _(главы 6, 8)_

**Terraform / OpenTofu** — декларативный инструмент провизионирования через HCL: описываешь конечное состояние, инструмент рассчитывает план изменений. OpenTofu — открытый форк после смены лицензии в 2023 году. _(главы 6, 8)_

**Ansible** — agentless-инструмент конфигурирования серверов по SSH: YAML-плейбуки описывают желаемое состояние, агенты не нужны. _(главы 6, 8)_

**GitOps** — модель деплоя, где желаемое состояние кластера описано в Git, а контроллер (ArgoCD, Flux) непрерывно синхронизирует кластер с репозиторием. _(глава 8)_

**ArgoCD** — UI-first GitOps-инструмент для Kubernetes: синхронизирует состояние кластера с описанием в Git. _(глава 8)_

**Keycloak** — enterprise Identity Provider от Red Hat с полной поддержкой LDAP, Active Directory, SAML 2.0 и fine-grained RBAC. _(главы 4, 8)_

**coding-агент** — AI-инструмент, который читает весь репозиторий, понимает задачу и выполняет её автономно в терминале или IDE (Claude Code, Aider). _(глава 7)_

**Ollama** — инструмент запуска LLM локально одной командой с OpenAI-совместимым API для подключения к Aider, Continue и другим инструментам. _(главы 7, 8)_

**локальная модель (local LLM)** — языковая модель, запускаемая на своей машине ради конфиденциальности, offline-работы или compliance. _(глава 7)_

**RAG (Retrieval-Augmented Generation)** — генерация ответов с опорой на твои документы (runbook'и, ADR, постмортемы), а не только на обучающие данные. _(глава 7)_

**AIOps** — применение ML к мониторингу: обнаружение аномалий и предиктивный скейлинг (Grafana ML, Netdata Anomaly Advisor). _(глава 7)_

**стек (стартовый стек)** — готовый набор инструментов под конкретный сценарий (Minimal, Homelab, Стартап, Enterprise), эволюционирующий по мере роста. _(глава 8)_

**Yandex Cloud** — наиболее зрелое российское облако: Managed Kubernetes, managed БД, Object Storage (S3-совместимое), Lockbox для секретов. _(глава 9)_

**Cloud.ru (SberCloud)** — крупное российское облако с упором на масштаб, GPU/AI и госсегмент. _(глава 9)_

**VK Cloud** — российское облако с простым входом и managed-сервисами (Kubernetes, БД, S3). _(глава 9)_

**Selectel** — российский провайдер с сильным IaaS, bare-metal и собственными дата-центрами. _(глава 9)_

**S3-совместимое хранилище** — объектное хранилище с API, совместимым с Amazon S3; навыки и инструменты переносятся между провайдерами сменой endpoint и ключей. _(глава 9)_

**152-ФЗ** — закон «О персональных данных»: первичные базы ПДн граждан РФ должны физически располагаться на территории России. _(глава 9)_

**Персональные данные (ПДн)** — данные, по которым можно идентифицировать человека (ФИО, телефон, email, паспорт и т.п.). _(глава 9)_

**ИСПДн** — информационная система, обрабатывающая персональные данные; к ней предъявляются требования по защите. _(глава 9)_

**ФСТЭК** — регулятор требований к защите информации; его требования и сертифицированные СЗИ нужны для ГИС, КИИ и серьёзных ИСПДн. _(глава 9)_

**КИИ (критическая информационная инфраструктура)** — системы важных отраслей (банки, энергетика, транспорт, связь) с особыми требованиями к защите. _(глава 9)_

**Аттестация / аттестованный сегмент** — формальное подтверждение соответствия системы требованиям регулятора; облака держат под это отдельные защищённые зоны. _(глава 9)_
