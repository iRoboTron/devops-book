# Глоссарий

> Термины и выражения книги «Сеть для DevOps». В скобках — главы, где термин вводится или активно используется.

---

**HTTP (HyperText Transfer Protocol)** — текстовый протокол запрос-ответ, по которому браузер общается с сервером. Передаётся в открытом виде. _(главы 0, 1)_

**HTTPS** — тот же HTTP, но внутри зашифрованного TLS-канала. Работает на порту 443. _(главы 1, 5)_

**Статус-код** — трёхзначный код в ответе HTTP: 2xx успех, 3xx редирект, 4xx ошибка клиента, 5xx ошибка сервера. _(глава 1)_

**Заголовки (HTTP headers)** — пары «ключ: значение» в запросе и ответе (например `Host`, `Content-Type`). _(главы 1, 4)_

**TLS/SSL** — протокол шифрования трафика. SSL — устаревшее название, сейчас используется TLS (1.2, 1.3). _(главы 1, 5)_

**TLS handshake (рукопожатие)** — обмен сообщениями в начале HTTPS-соединения, где стороны согласуют шифрование и проверяют сертификат. _(глава 5)_

**Сертификат** — файл, подтверждающий, что домен принадлежит владельцу сервера. Содержит публичный ключ. _(глава 5)_

**Приватный ключ (privkey.pem)** — секретная часть пары ключей сертификата. Никому не передаётся. _(глава 5)_

**fullchain.pem** — сертификат вместе с цепочкой промежуточных CA. Именно его указывают в Nginx. _(глава 5)_

**CA (Certificate Authority)** — удостоверяющий центр, выдающий сертификаты (например Let's Encrypt). _(глава 5)_

**Let's Encrypt** — бесплатный удостоверяющий центр, выдающий сертификаты на 90 дней через протокол ACME. _(главы 5, 8, 10)_

**ACME** — протокол автоматической выдачи и продления сертификатов. Использует HTTP-challenge на порту 80. _(главы 5, 8, 10)_

**ACME challenge** — проверка владения доменом: CA запрашивает файл по `/.well-known/acme-challenge/` на порту 80. _(главы 5, 8)_

**certbot** — клиент Let's Encrypt: получает сертификат, правит конфиг Nginx и настраивает автопродление. _(глава 5)_

**certbot.timer** — systemd-таймер, автоматически продлевающий сертификаты до истечения. _(глава 5)_

**Self-signed сертификат** — сертификат, выпущенный самим сервером без CA. Подходит для тестов; браузер ему не доверяет (нужен флаг `-k` у curl). _(главы 5, 9)_

**HSTS (Strict-Transport-Security)** — заголовок, заставляющий браузер всегда ходить на сайт по HTTPS. _(главы 5, 8)_

**DNS (Domain Name System)** — система, переводящая доменное имя в IP-адрес. _(глава 2)_

**A-запись** — DNS-запись, сопоставляющая домену IPv4-адрес. _(глава 2)_

**CNAME** — DNS-запись-псевдоним: указывает на другой домен вместо IP. _(глава 2)_

**TTL (Time To Live)** — время жизни DNS-записи в кэше резолверов. Высокий TTL = медленное распространение изменений. _(глава 2)_

**Резолвер** — сервер, выполняющий DNS-запросы по цепочке от корневых серверов до авторитативного. _(глава 2)_

**dig** — утилита для DNS-запросов. `dig domain.ru +short` показывает IP домена. _(главы 2, 7)_

**/etc/hosts** — локальный файл сопоставления имя→IP, проверяется до DNS. Удобен для тренировки без реального домена. _(главы 2, 9)_

**Nginx** — высокопроизводительный веб-сервер и обратный прокси. _(главы 3, 4)_

**nginx -t** — проверка синтаксиса конфига Nginx перед перезагрузкой. _(главы 3, 7)_

**sites-available / sites-enabled** — каталоги конфигов Nginx: доступные сайты и включённые (через симлинк). _(главы 3, 9)_

**server-блок** — секция конфига Nginx, описывающая один виртуальный сайт. _(главы 3, 4)_

**server_name** — директива Nginx: домен(ы), на которые отвечает данный server-блок. Маршрутизация по заголовку `Host`. _(главы 3, 4, 10)_

**location** — блок Nginx, задающий правила обработки для определённого пути URL. _(глава 4)_

**Reverse proxy (обратный прокси)** — сервер, принимающий запросы клиентов и перенаправляющий их бэкендам. _(главы 0, 4, 8, 10)_

**proxy_pass** — директива Nginx, пробрасывающая запрос на бэкенд (например `http://127.0.0.1:8000`). _(глава 4)_

**upstream** — именованная группа бэкенд-серверов в Nginx для балансировки нагрузки. _(глава 4)_

**proxy_set_header** — директива Nginx, добавляющая/переопределяющая заголовки при проксировании. _(глава 4)_

**X-Real-IP / X-Forwarded-For** — заголовки, передающие бэкенду реальный IP клиента через прокси. _(главы 4, 8, 9)_

**X-Forwarded-Proto** — заголовок, сообщающий бэкенду исходный протокол (http/https). _(главы 4, 9)_

**Таймауты (proxy_read_timeout и др.)** — сколько Nginx ждёт ответа от бэкенда. Превышение даёт 504. _(главы 4, 7)_

**Бэкенд** — приложение за прокси, которое реально обрабатывает запрос (Python на `127.0.0.1:8000`). _(главы 4, 7, 9)_

**Фаервол** — система фильтрации сетевого трафика по правилам. _(глава 6)_

**ufw (Uncomplicated Firewall)** — простой интерфейс к iptables в Ubuntu. _(глава 6)_

**Профиль ufw (Nginx Full / OpenSSH)** — готовый набор портов для приложения (`Nginx Full` = 80+443). _(глава 6)_

**Порт** — числовой идентификатор сетевой службы (80 — HTTP, 443 — HTTPS, 22 — SSH). _(главы 0, 6, 7)_

**ss** — утилита показа слушающих сокетов. `ss -tlnp` — кто слушает порты. _(глава 7)_

**nc (netcat)** — утилита проверки открытости порта. `nc -zv host port`. _(глава 7)_

**tcpdump** — анализатор сетевых пакетов. Инструмент последнего средства при диагностике. _(глава 7)_

**curl** — консольный HTTP-клиент и диагностический прибор. `curl -v` показывает весь обмен. _(главы 1, 7, 9)_

**502 Bad Gateway** — Nginx жив, но бэкенд не ответил или упал. Чинить нужно приложение. _(главы 7, 8, 10)_

**504 Gateway Timeout** — Nginx не дождался ответа бэкенда за отведённое время. _(глава 7)_

**Connection refused** — никто не слушает порт (сервис не запущен). _(глава 7)_

**Connection timeout** — сервер не отвечает вовсе: пакеты теряются (часто фаервол). _(глава 7)_

**Caddy** — веб-сервер и прокси с автоматическим HTTPS из коробки. _(глава 8)_

**Caddyfile** — конфиг Caddy. Блок `домен { reverse_proxy ... }` заменяет десятки строк Nginx. _(глава 8)_

**caddy validate / reload** — проверка конфига и применение без даунтайма (аналоги `nginx -t` и reload). _(глава 8)_

**network_mode: host** — режим Docker, где контейнер использует сетевой стек хоста напрямую (только Linux). _(глава 8)_

**Nginx Proxy Manager (NPM)** — веб-интерфейс поверх Nginx для управления прокси и сертификатами через браузер. _(глава 10)_

**Proxy Host** — правило в NPM: «домен X → бэкенд Y». _(глава 10)_

**Access List** — список логин/пароль в NPM для HTTP Basic Auth поверх Proxy Host. _(глава 10)_

**Streams (TCP/UDP проксирование)** — проброс произвольного TCP/UDP трафика в NPM (без SSL). _(глава 10)_

**systemd-сервис** — управляемый юнит для автозапуска приложения с рестартом при падении. _(глава 9)_

**virtualenv (.venv)** — изолированное окружение Python с собственными библиотеками. _(глава 9)_

**requirements.txt** — список Python-зависимостей проекта для установки через `pip`. _(глава 9)_

**gunicorn** — WSGI-сервер, через который Flask-приложение слушает `127.0.0.1:8000`. _(глава 9)_

**SSH** — протокол защищённого удалённого доступа к серверу (порт 22). _(глава 9)_
