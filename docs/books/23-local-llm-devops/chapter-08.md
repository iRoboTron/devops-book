# Глава 8: Безопасность локального AI

> **Цель:** не превратить удобный AI-сервис в открытый публичный инструмент для всех.

---

## 8.1 Главная ошибка

Опасная публикация:

```yaml
ports:
  - "11434:11434"
```

Так Docker слушает на всех интерфейсах. Если firewall открыт, любой человек может обращаться к твоему Ollama API.

Правильно для локального сервера:

```yaml
ports:
  - "127.0.0.1:11434:11434"
```

---

## 8.2 Что может случиться

Если Ollama открыт наружу:

- чужие люди используют твои ресурсы;
- сервер тормозит;
- дисковое место расходуется моделями и логами;
- в API могут попадать приватные запросы;
- сервис становится частью чужой автоматизации.

---

## 8.3 Минимальный чеклист

```bash
sudo ufw deny 11434
sudo ufw deny 3000
sudo ufw allow 443/tcp
sudo ufw status verbose
```

# Пример вывода sudo ufw status verbose:
```
Status: active
Logging: on (low)
Default: deny (incoming), allow (outgoing), disabled (routed)
New profiles: skip

To                         Action      From
--                         ------      ----
443/tcp                    ALLOW IN    Anywhere
11434                      DENY IN     Anywhere
3000                       DENY IN     Anywhere
22/tcp                     ALLOW IN    Anywhere
443/tcp (v6)               ALLOW IN    Anywhere (v6)
11434 (v6)                 DENY IN     Anywhere (v6)
3000 (v6)                  DENY IN     Anywhere (v6)
```

Порты 11434 и 3000 заблокированы снаружи — это правильный результат.

Проверка снаружи:

```bash
curl http://PUBLIC_IP:11434/api/tags
curl http://PUBLIC_IP:3000
```

Ожидаемый результат: соединение не проходит или порт закрыт.

---

## 8.4 Как проверить что Ollama не слушает на 0.0.0.0

```bash
ss -tlnp | grep 11434
```

# Пример безопасного вывода:
```
LISTEN  0       4096     127.0.0.1:11434    0.0.0.0:*    users:(("ollama",pid=12345,fd=3))
```

Строка начинается с `127.0.0.1:11434` — это значит, что Ollama слушает только локально. Это хорошо.

# Пример опасного вывода:
```
LISTEN  0       4096     0.0.0.0:11434      0.0.0.0:*    users:(("ollama",pid=12345,fd=3))
```

Если видишь `0.0.0.0:11434` — порт открыт на всех интерфейсах. Нужно исправить конфигурацию (см. раздел 8.1) и перезапустить сервис.

---

## 8.5 Приватность данных

Локальный запуск не означает, что всё автоматически безопасно. Спроси себя:

- кто имеет SSH-доступ к серверу;
- где Open-WebUI хранит историю;
- попадают ли prompts в логи;
- есть ли backup этих данных;
- можно ли отправлять туда персональные данные.

Не отправляй в модель полные `.env`, приватные ключи, токены, дампы БД и чужие персональные данные.

---

## 8.6 Практика

1. Проверь, какие порты слушают:

```bash
ss -tlnp | grep -E '11434|3000|443'
```

2. Проверь firewall.
3. Проверь доступ с другого устройства.
4. Запиши результат в чеклист.

Практика завершена, когда ты можешь доказать: WebUI защищён логином, Ollama API не открыт напрямую, HTTPS работает, лишние порты закрыты.

---

> **Если что-то пошло не так:**
>
> **Симптом:** `ss -tlnp | grep 11434` показывает `0.0.0.0:11434` — порт открыт на всех интерфейсах.
>
> Исправление для нативного Ollama:
> ```bash
> # Добавить переменную окружения в systemd unit
> sudo systemctl edit ollama
> ```
> Добавить:
> ```ini
> [Service]
> Environment="OLLAMA_HOST=127.0.0.1"
> ```
> Затем:
> ```bash
> sudo systemctl daemon-reload
> sudo systemctl restart ollama
> ss -tlnp | grep 11434
> # Теперь должно быть 127.0.0.1:11434
> ```
>
> Для Docker — исправить строку в `ports` с `"11434:11434"` на `"127.0.0.1:11434:11434"` и пересоздать контейнер:
> ```bash
> docker compose up -d --force-recreate ollama
> ```
>
> **Симптом:** `sudo ufw status` показывает `Status: inactive`.
>
> UFW не включён. Включить и настроить правила:
> ```bash
> sudo ufw enable
> sudo ufw allow 22/tcp   # обязательно, иначе потеряешь SSH
> sudo ufw allow 443/tcp
> sudo ufw deny 11434
> sudo ufw deny 3000
> ```
