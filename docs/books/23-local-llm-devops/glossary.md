# Глоссарий

> Термины и выражения книги «Локальные LLM: Ollama, Open-WebUI и API в своём стеке». В скобках — главы, где термин вводится или активно используется.

---

**LLM (Large Language Model, большая языковая модель)** — модель, которая получает текст и предсказывает его наиболее вероятное продолжение. Не база знаний, а вероятностный автодополнитель, обученный на больших массивах текста. _(глава 0)_

**Inference (инференс, вывод)** — процесс генерации ответа уже обученной моделью: prompt токенизируется, модель считает продолжение, сервер собирает текст. В отличие от обучения, не меняет веса модели. _(главы 0, 7)_

**Token (токен)** — кусочек текста: слово, часть слова или знак. Модель работает не с символами, а с токенами, поэтому скорость и стоимость считают в токенах. _(глава 0)_

**Tokenization (токенизация)** — разбивка входного текста на токены перед подачей в модель. Первый шаг конвейера инференса. _(глава 0)_

**Параметры / B (billion)** — приблизительное число настраиваемых весов модели; число перед «B» в названии (3B, 7B, 70B) означает миллиарды параметров. Больше параметров — выше шанс на качество, но больше потребление памяти. _(глава 2)_

**Weights (веса)** — числовые коэффициенты модели, полученные при обучении и хранящиеся в файле модели. Именно их загружают в RAM или VRAM при запуске. _(главы 0, 2)_

**Quantization (квантизация)** — снижение точности весов (например до 4 бит) ради меньшего размера файла и меньшего потребления памяти ценой небольшой потери качества. _(главы 1, 2)_

**Q4_K_M / Q4_0** — обозначения уровней квантизации в Ollama/GGUF; «Q4» означает 4-битную квантизацию. Такие варианты легче по памяти и подходят для слабого железа. _(главы 1, 2)_

**GGUF** — формат файла модели, в котором Ollama хранит веса (виден в поле `format` ответа API). _(главы 1, 3)_

**Ollama** — программа-сервер для запуска локальных языковых моделей: берёт на себя скачивание, хранение, запуск модели и предоставляет CLI и HTTP API. _(главы 1, 3)_

**ollama pull** — команда скачивания модели в локальное хранилище по её тегу (например `llama3.2:3b`). _(глава 1)_

**ollama run** — команда запуска интерактивного диалога с моделью в терминале. _(глава 1)_

**ollama list** — команда вывода списка скачанных локально моделей с размером и датой. _(главы 1, 10)_

**Тег модели** — идентификатор модели и её варианта в библиотеке Ollama, например `llama3.2:3b`, где после двоеточия указан размер/вариант. _(главы 1, 2)_

**Instruct / chat-модель** — модель, дообученная следовать инструкциям и вести диалог; именно её берут для учебного старта, а не «сырую» базовую модель. _(главы 1, 2)_

**Coder-модель** — модель, специализированная на коде и командах; выбирается, когда задача — помощь с программированием. _(глава 2)_

**Контекст (история диалога)** — предыдущие сообщения, которые скрипт должен сам передавать в `messages`, чтобы модель «помнила» разговор; сама по себе история между запросами не сохраняется. _(глава 3)_

**RAM (оперативная память)** — память, в которую загружается модель при CPU-инференсе; её нехватка приводит к ошибке `out of memory` или медленной работе. _(главы 1, 2, 7)_

**VRAM (видеопамять)** — память видеокарты, куда загружают модель для быстрого GPU-инференса; её объём ограничивает размер запускаемой модели. _(главы 2, 7)_

**CPU-инференс** — запуск модели на процессоре без видеокарты: проще в установке и работает почти везде, но медленнее, особенно на первом ответе. _(глава 7)_

**GPU-инференс** — запуск модели на видеокарте; нужен для интерактивности, нескольких пользователей и более крупных моделей. _(глава 7)_

**Offload (выгрузка слоёв)** — перенос слоёв модели на GPU; в логах Ollama `offload=32` означает, что все слои загружены на видеокарту, `offload=0` — что используется только CPU. _(глава 7)_

**CUDA** — технология NVIDIA для вычислений на GPU; в логах Ollama строка `CUDA initialized` подтверждает, что видеокарта задействована. _(глава 7)_

**nvidia-smi** — утилита для проверки состояния NVIDIA GPU: модель карты, объём VRAM, загрузка и список процессов (включая `ollama`). _(глава 7)_

**NVIDIA Container Toolkit** — набор для проброса GPU внутрь Docker-контейнера; нужен вместе с флагом `--gpus all`, чтобы Ollama в контейнере видела видеокарту. _(глава 7)_

**Prompt (промпт, запрос)** — текст, который пользователь или скрипт отправляет модели; от его качества и контекста сильно зависит ответ. _(главы 0, 3, 9)_

**Ollama API** — HTTP-интерфейс Ollama на порту `11434` для обращения к модели из любых скриптов, а не только из чата. _(глава 3)_

**Порт 11434** — порт по умолчанию, на котором слушает Ollama; его нельзя открывать в интернет напрямую. _(главы 1, 3, 8)_

**/api/generate** — endpoint Ollama для одиночной генерации текста по одному prompt; ответ возвращается в поле `response`. _(главы 3, 6)_

**/api/chat** — endpoint Ollama для диалогов: принимает массив `messages` с ролями и возвращает сообщение ассистента. _(глава 3)_

**OpenAI-совместимый endpoint** — путь `/v1/chat/completions`, повторяющий формат OpenAI API, чтобы сторонние программы работали с Ollama; совместимость формата, а не качества. _(глава 3)_

**Streaming (потоковый ответ)** — режим, при котором ответ приходит по мере генерации токенов (`stream: true`); требует корректной передачи WebSocket-заголовков через Nginx. _(главы 3, 5)_

**eval_count** — поле ответа API: сколько токенов сгенерировала модель; вместе с `total_duration` помогает оценить скорость. _(глава 3)_

**total_duration** — поле ответа API: общее время обработки запроса (в наносекундах). _(глава 3)_

**Open-WebUI** — браузерный веб-интерфейс к локальным моделям: история чатов, пользователи, настройки, промпты; подключается к Ollama. _(глава 4)_

**Volume (том)** — постоянное хранилище Docker, в котором Open-WebUI держит историю и настройки (`open-webui`), а Ollama — модели (`ollama`); переживает перезапуск контейнера. _(главы 4, 8)_

**OLLAMA_BASE_URL** — переменная окружения Open-WebUI с адресом Ollama; в Docker Compose должна указывать на имя сервиса (`http://ollama:11434`), а не на `localhost`. _(глава 4)_

**Docker Compose** — способ описать стек Ollama + Open-WebUI в одном YAML-файле и поднять его командой `docker compose up -d`. _(глава 4)_

**Admin-пользователь** — первый зарегистрированный в Open-WebUI пользователь, который обычно получает права администратора; его создают сразу после запуска. _(главы 4, 10)_

**Reverse proxy (обратный прокси)** — сервер (Nginx), принимающий внешние запросы и перенаправляющий их на внутренний сервис; скрывает и защищает бэкенд. _(глава 5)_

**Nginx** — веб-сервер, который в этом стеке принимает HTTPS на порту 443 и проксирует трафик на локальный Open-WebUI. _(глава 5)_

**proxy_read_timeout** — настройка Nginx, увеличивающая время ожидания ответа от бэкенда; для долгих ответов LLM нужно 120–300 секунд вместо стандартных 60. _(глава 5)_

**Upgrade / Connection заголовки** — HTTP-заголовки, которые Nginx должен передавать для WebSocket; без них streaming-ответ в Open-WebUI зависает. _(глава 5)_

**Firewall (UFW)** — межсетевой экран; в книге используется для запрета портов 11434 и 3000 снаружи и разрешения только 443 и SSH. _(главы 5, 8)_

**0.0.0.0 vs 127.0.0.1** — адреса прослушивания: `0.0.0.0` означает «все интерфейсы» (опасно, виден из сети), `127.0.0.1` — только локально (безопасно). _(главы 1, 8)_

**OLLAMA_HOST** — переменная окружения, задающая адрес прослушивания Ollama; `127.0.0.1` ограничивает доступ локальной машиной. _(глава 8)_

**ss -tlnp** — команда проверки, на каких адресах и портах слушают сервисы; используется, чтобы убедиться, что Ollama не торчит на `0.0.0.0`. _(главы 8, 10)_

**WireGuard / VPN** — способ дать доступ к сервису через защищённый туннель вместо публикации в интернет; рекомендуется, если сервис нужен только тебе. _(главы 5, 8)_

**Облачный API** — внешний сервис сильной модели (например ChatGPT): высокое качество и скорость, но данные уходят провайдеру и есть плата за токены. _(главы 0, 9)_

**Гибридный подход** — стратегия, при которой приватные и простые задачи идут на локальную модель, а сложные публичные — в облако; выбор делают после классификации данных. _(глава 9)_

**Классификация данных** — оценка приватности данных перед выбором модели: можно ли вообще отправлять их во внешний сервис. _(главы 0, 8, 9)_

**Очистка секретов** — удаление IP, токенов, ключей и паролей из логов и конфигов перед отправкой их в модель. _(главы 6, 8)_
