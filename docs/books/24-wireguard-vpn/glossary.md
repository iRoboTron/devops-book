# Глоссарий

> Термины и выражения книги «WireGuard VPN». В скобках — главы, где термин вводится или активно используется.

---

**WireGuard** — современный VPN-протокол и набор инструментов (`wg`, `wg-quick`) с коротким конфигом, высокой скоростью и встроенной криптографией; для личного сервера обычно проще OpenVPN и IPsec. _(главы 0, 1, 2)_

**VPN (Virtual Private Network)** — частная сеть поверх интернета; в этой книге служит не для анонимности, а чтобы закрыть внутренние сервисы от всех и оставить доступ только через туннель. _(глава 0)_

**Туннель (tunnel)** — зашифрованный канал между двумя peer'ами, по которому ходят IP-пакеты так, будто устройства в одной локальной сети. _(главы 0, 3)_

**Peer** — любой участник WireGuard-сети; в WireGuard нет жёсткого деления на «клиент» и «сервер», все стороны технически равноправны. _(глава 1)_

**Сервер (server peer)** — peer, который слушает публичный UDP-порт и к которому подключаются остальные; в книге имеет VPN-адрес `10.0.0.1`. _(главы 1, 3)_

**Клиент (client peer)** — peer (телефон, ноутбук), который инициирует подключение к серверу по его `Endpoint`. _(главы 1, 3, 6)_

**Приватный ключ (private key)** — секретный ключ peer'а, который никогда не покидает устройство; его нельзя показывать никому. _(глава 1)_

**Публичный ключ (public key)** — ключ, вычисленный из приватного; его передают другому peer и вставляют в его конфиг. Обратное вычисление приватного из публичного невозможно. _(главы 1, 3)_

**Пара ключей (key pair)** — связанные приватный и публичный ключи; генерируются командой `wg genkey | wg pubkey`, представляют собой base64-строки из 44 символов. _(главы 1, 3)_

**`wg genkey`** — команда генерации приватного ключа WireGuard. _(главы 1, 3)_

**`wg pubkey`** — команда, вычисляющая публичный ключ из приватного (читает приватный из stdin). _(главы 1, 3)_

**AllowedIPs** — список IP/подсетей, которые маршрутизируются через туннель к конкретному peer; одновременно фильтр входящих пакетов. На сервере для клиента обычно `/32`, на клиенте задаёт, какой трафик идёт в VPN. _(главы 1, 3)_

**Split tunnel** — режим, когда через VPN идёт только VPN-сеть (например `AllowedIPs = 10.0.0.0/24`), а остальной трафик — напрямую в интернет. _(главы 1, 6)_

**Full tunnel** — режим `AllowedIPs = 0.0.0.0/0`, когда через VPN идёт почти весь IPv4-трафик клиента; требует NAT и forwarding на сервере. _(главы 1, 2, 6)_

**`[Interface]`** — секция конфига, описывающая локальный peer: его приватный ключ, адрес, порт, DNS, MTU. _(главы 3, 7)_

**`[Peer]`** — секция конфига, описывающая удалённого peer'а: публичный ключ, AllowedIPs, Endpoint, keepalive. _(главы 3, 6)_

**PrivateKey** — поле в `[Interface]`, содержащее приватный ключ данного peer'а. _(глава 3)_

**PublicKey** — поле в `[Peer]`, содержащее публичный ключ удалённого peer'а. _(глава 3)_

**Address** — VPN-адрес интерфейса в секции `[Interface]`, например `10.0.0.1/24`. _(глава 3)_

**ListenPort** — UDP-порт, на котором peer (обычно сервер) принимает входящие соединения; по умолчанию `51820`. _(главы 3, 4)_

**Endpoint** — публичный IP и порт сервера (`SERVER_PUBLIC_IP:51820`) в конфиге клиента; адрес, по которому клиент находит сервер. _(главы 3, 7)_

**Handshake** — процесс установления туннеля между peer'ами с обменом ключами и созданием сеансового ключа; `latest handshake` в `wg show` показывает, когда он был. _(главы 3, 7)_

**`latest handshake`** — поле вывода `wg show`, показывающее, сколько прошло с последнего успешного обмена; свежий (секунды) означает активный туннель. _(главы 3, 5, 7)_

**PersistentKeepalive** — интервал (обычно `25` секунд) отправки пустых пакетов, чтобы держать открытым проход через NAT; важен для телефонов и домашних подключений. _(главы 3, 7)_

**NAT traversal** — способность WireGuard работать через NAT: сервер отвечает на тот адрес/порт, с которого пришёл пакет, а keepalive не даёт NAT-записи протухнуть. _(главы 3, 7)_

**NAT (маскарадинг)** — подмена адреса источника на адрес сервера (`iptables -t nat -A POSTROUTING ... MASQUERADE`), нужна для full tunnel, чтобы клиент мог выходить в интернет через сервер. _(главы 2, 6)_

**IP forwarding** — режим ядра (`net.ipv4.ip_forward = 1`), разрешающий серверу пересылать чужие пакеты дальше; нужен, когда клиент ходит через сервер. _(главы 2, 6)_

**Интерфейс wg0** — виртуальный сетевой интерфейс WireGuard, создаваемый `wg-quick up wg0`; через него идёт зашифрованный трафик. _(главы 3, 5)_

**`wg-quick`** — утилита для подъёма/спуска туннеля по конфигу `/etc/wireguard/wg0.conf` (`wg-quick up/down wg0`), автоматически настраивает адрес, маршруты и правила. _(главы 3, 5)_

**`wg show`** — команда статуса WireGuard: показывает интерфейс, peer'ов, их endpoint, allowed ips, handshake и объём трафика. _(главы 3, 5, 7)_

**`wg set`** — команда живого изменения интерфейса (например добавить peer) без полного перезапуска; изменения не сохраняются в конфиг автоматически. _(глава 6)_

**`/etc/wireguard/wg0.conf`** — основной файл конфигурации туннеля на сервере; правки в нём, в отличие от `wg set`, переживают перезапуск. _(главы 3, 5, 6)_

**`wg-quick@wg0` (systemd)** — systemd-юнит для автозапуска туннеля после перезагрузки; статус `active (exited)` для него нормален. _(глава 5)_

**`active (exited)`** — нормальное состояние systemd-сервиса wg-quick: он поднял интерфейс и завершился, а сам `wg0` продолжает работать. _(глава 5)_

**MTU** — максимальный размер пакета; в WireGuard по умолчанию `1420`. При зависании HTTPS и крупных страниц помогает уменьшение до `1380` или `1280`. _(глава 7)_

**DNS (в конфиге)** — поле `[Interface]` клиента (`DNS = 1.1.1.1`), задающее DNS-сервер при поднятом туннеле; помогает против DNS leak и неработающего разрешения имён. _(главы 3, 6, 7)_

**DNS leak** — утечка DNS-запросов мимо VPN, из-за которой используется не тот резолвер; решается явным указанием DNS на клиенте. _(глава 7)_

**QR-код (клиента)** — закодированный конфиг клиента (`qrencode`), удобный для импорта в мобильное приложение; содержит приватный ключ, поэтому его нельзя слать в общий чат. _(главы 1, 6)_

**`qrencode`** — утилита, превращающая клиентский конфиг в QR-код (ANSI в терминале или PNG-файл). _(глава 6)_

**Отзыв доступа (revoke)** — удаление `[Peer]` потерянного устройства из конфига и безопасное применение; скомпрометированный ключ больше не используют. _(главы 6, 8)_

**Правило одного устройства** — практика выдавать каждому устройству отдельный ключ и отдельный VPN-адрес, чтобы понимать, кто подключается, и точечно отзывать доступ. _(главы 6, 8)_

**Hub-and-spoke** — топология «сервер в центре, клиенты по краям»: все клиенты подключаются к серверу, а между собой общаются через него. _(глава 6)_

**Site-to-site** — соединение целых сетей (офис↔офис) через VPN, а не отдельных устройств; в этой книге не рассматривается, упомянут как граница темы. _(глава 0)_

**ufw** — простой фронтенд для firewall; используется, чтобы разрешить `51820/udp` и доступ к сервисам только на интерфейсе `wg0`. _(глава 4)_

**Безопасный порядок действий** — правило не менять SSH и firewall одновременно, держать второй SSH-сеанс и доступ к консоли провайдера, чтобы не отрезать себя. _(главы 2, 4, 5)_

**Консоль провайдера (VNC/KVM)** — веб-доступ к серверу, не зависящий от SSH и firewall; спасает, если правило ufw заблокировало SSH. _(глава 4)_

**Внешний интерфейс** — сетевой интерфейс сервера, смотрящий в интернет (`eth0`, `ens3`, `enp1s0` и т. п.); определяется по `ip route show default` и используется в NAT-правилах. _(главы 2, 7)_

**Runbook** — короткий документ (`WIREGUARD-RUNBOOK.md`) с описанием сети, таблицей peers, командами проверки и процедурой отзыва. _(глава 8)_
