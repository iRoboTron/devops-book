# Глава 11: Удалённый доступ через Tailscale

## Что вы узнаете

## 11.1 Почему нельзя открывать порт 8006 в интернет

После установки Proxmox первый инстинкт — пробросить порт 8006 на роутере, чтобы заходить в веб-интерфейс из любой точки. Это плохая идея, и вот почему.

Боты в интернете сканируют все популярные порты 24 часа в сутки. Порт 8006 — известный порт Proxmox. Через несколько минут после проброса ты увидишь в логах попытки входа:

```bash
grep "pvedaemon" /var/log/syslog | grep "authentication failure"
# Пример: May 22 03:14:07 proxmox pvedaemon[1234]: authentication failure; rhost=185.220.101.5 user=root
```

Это не паранойя — это факт. IP 185.220.101.5 принадлежит известной сети атакующих.

Что может пойти не так при открытом порте:
- Если пароль слабый или стандартный — сервер взломают.
- Даже со сложным паролем — DDoS на порт 8006 нагружает CPU и мешает работе.
- Уязвимость в Proxmox (как в любом ПО) — мгновенный эксплойт со всего интернета.

```text
Плохо:
Интернет → роутер → порт 8006 → Proxmox
Любой знает адрес → пытается войти → 24/7 атаки

Лучше:
Интернет → Tailscale (зашифрованный туннель) → Proxmox
Только твои устройства знают адрес → чужие не видят сервер вообще
```

Tailscale решает эту проблему кардинально: порт 8006 вообще не нужно открывать на роутере. Proxmox просто не виден снаружи.

## 11.2 Как работает Tailscale — WireGuard под капотом

Tailscale — это оверлейная сеть поверх интернета. Каждое устройство в сети получает виртуальный IP вида `100.x.x.x` (диапазон 100.64.0.0/10). С телефона ты обращаешься к Proxmox не по публичному IP, а по этому виртуальному адресу.

Под капотом работает WireGuard — современный VPN-протокол с несколькими важными свойствами:

- **Скорость:** WireGuard работает на уровне ядра Linux, заметно быстрее OpenVPN.
- **Простота:** весь протокол — около 4000 строк кода (у OpenVPN — сотни тысяч). Меньше кода — меньше уязвимостей.
- **Криптография:** только современные алгоритмы (Curve25519, ChaCha20, BLAKE2). Нет устаревших режимов.
- **Peer-to-peer:** Tailscale пытается установить прямое соединение между устройствами (hole punching). Если не получается — трафик идёт через relay-серверы (DERP), но это редкость.

Что делает Tailscale поверх WireGuard:
- Управление ключами через облачный control plane (app.tailscale.com).
- Авторизация устройств через Google, GitHub, Microsoft или email.
- Маршрутизация: subnet routing, exit nodes.
- ACL (правила доступа между устройствами).

После установки Tailscale на два устройства они видят друг друга по `100.x.x.x` адресам независимо от того, за каким NAT находятся. Ни один порт на роутере открывать не нужно.

## 11.3 Установка Tailscale на хост Proxmox

Установка выполняется в Shell хоста Proxmox (не внутри контейнера).

```bash
# Официальный установочный скрипт — скачивает и настраивает репозиторий, затем устанавливает пакет
curl -fsSL https://tailscale.com/install.sh | sh
```

После установки запустить Tailscale и авторизовать устройство:

```bash
# Команда запускает Tailscale и выводит ссылку для авторизации
tailscale up
```

Вывод будет примерно таким:

```
To authenticate, visit:

        https://login.tailscale.com/a/xxxxxxxxxxxxxxxx
```

Открыть ссылку на любом устройстве — телефоне, ноутбуке, браузере. Войти через Google или GitHub-аккаунт. Устройство появится в консоли Tailscale под именем `proxmox`.

Проверить что всё работает:

```bash
# Показывает Tailscale IP этого устройства (вида 100.x.x.x)
tailscale ip -4

# Показывает статус: подключён ли, какие устройства видны
tailscale status
```

Пример вывода `tailscale status`:

```
100.101.102.103 proxmox              linux   -
100.101.102.50  my-phone             android -
100.101.102.75  my-laptop            windows -
```

Tailscale запускается автоматически при старте системы через systemd:

```bash
systemctl status tailscaled    # проверить что сервис работает
```

## 11.4 Доступ к Proxmox через Tailscale IP

После авторизации хоста Proxmox в Tailscale — заходить в веб-интерфейс можно по Tailscale IP. Никакого проброса портов на роутере не нужно.

Узнать Tailscale IP:

```bash
tailscale ip -4
# Например: 100.101.102.103
```

Открыть веб-интерфейс с любого устройства в сети Tailscale:

```
https://100.101.102.103:8006
```

Браузер предупредит о самоподписанном сертификате — это нормально для Proxmox. Добавить исключение и зайти.

С телефона это выглядит так:
1. Установить приложение Tailscale (iOS / Android) и войти в тот же аккаунт.
2. Включить Tailscale в приложении.
3. Открыть браузер и перейти на `https://100.101.102.103:8006`.

Proxmox теперь доступен с телефона, ноутбука, из другого города — где угодно, где есть интернет и установлен Tailscale.

SSH тоже работает через Tailscale IP:

```bash
ssh root@100.101.102.103
```

## 11.5 Subnet routing — доступ ко всей домашней сети

По умолчанию Tailscale открывает доступ только к тем устройствам, на которых он установлен. Но дома часть устройств не поддерживает Tailscale: роутер, NAS, принтер, камеры, умные устройства, другие серверы.

Subnet routing решает эту задачу: Proxmox становится шлюзом (gateway) для целой подсети. Через Tailscale можно обращаться ко всем устройствам домашней сети, даже если на них нет Tailscale.

Включить subnet routing на хосте Proxmox:

```bash
# Proxmox анонсирует маршрут к домашней сети 192.168.1.0/24
# Заменить 192.168.1.0/24 на свою подсеть (узнать через: ip route | grep default)
tailscale up --advertise-routes=192.168.1.0/24
```

Включить IP forwarding на хосте (нужно для routing):

```bash
echo 'net.ipv4.ip_forward = 1' >> /etc/sysctl.d/99-tailscale.conf
sysctl -p /etc/sysctl.d/99-tailscale.conf
```

После этого — одобрить маршрут в консоли Tailscale:

1. Открыть https://login.tailscale.com/admin/machines
2. Найти устройство `proxmox`
3. Нажать на три точки → Edit route settings
4. Включить маршрут `192.168.1.0/24`

На клиентских устройствах разрешить использование анонсируемых маршрутов:

```bash
# На ноутбуке или другом устройстве с Tailscale
tailscale up --accept-routes
```

После этого с ноутбука через Tailscale можно обращаться ко всем устройствам домашней сети:

```text
С ноутбука (в кафе, с Tailscale):
192.168.1.1   → роутер домашней сети (веб-интерфейс)
192.168.1.200 → NAS
192.168.1.150 → IP-камера
192.168.1.101 → LXC с Nextcloud

Ни один порт на роутере не открыт — всё через Tailscale.
```

Проверить что маршруты работают:

```bash
# Ping к устройству в домашней сети (с удалённого устройства)
ping 192.168.1.1

# Посмотреть активные маршруты Tailscale
tailscale status --peers
```

## 11.6 Tailscale внутри LXC-контейнера

Иногда нужно установить Tailscale не на хост Proxmox, а внутрь конкретного LXC-контейнера. Например, чтобы дать отдельный Tailscale IP конкретному сервису, или чтобы сервис внутри LXC сам был точкой входа в сеть.

Для работы Tailscale внутри LXC нужны дополнительные права. Добавить в конфиг контейнера на хосте:

```bash
# /etc/pve/lxc/100.conf — добавить строки:
lxc.cgroup2.devices.allow: c 10:200 rwm
lxc.mount.entry: /dev/net/tun dev/net/tun none bind,create=file
```

Или через веб-интерфейс проще — включить через опции контейнера нет прямого пункта, поэтому редактировать файл конфига предпочтительнее.

Установка внутри LXC:

```bash
# Войти в контейнер
pct enter 100

# Установить Tailscale (та же команда что и на хосте)
curl -fsSL https://tailscale.com/install.sh | sh

# Запустить
tailscale up
```

Использование Community Scripts для Tailscale на хосте:

```bash
# На хосте Proxmox — скрипт устанавливает Tailscale на сам хост
bash -c "$(curl -fsSL https://raw.githubusercontent.com/community-scripts/ProxmoxVE/main/tools/tailscale.sh)"
```

Когда ставить Tailscale в LXC, а не на хост:

```text
На хост Proxmox — если нужен доступ к веб-интерфейсу и subnet routing для всей сети.
Это основной и рекомендуемый вариант.

В LXC — если нужно дать отдельный Tailscale IP конкретному сервису,
или если хост Proxmox уже занят другим VPN.
Осторожно: два Tailscale (хост + LXC) на одном сервере — конфликт маршрутов.
```

## 11.7 Типичные ошибки

| Симптом | Причина | Решение |
|---------|---------|---------|
| `tailscale up` висит, ссылка не появляется | Нет интернета | Проверить `curl https://tailscale.com` |
| Устройство видно в консоли, но 8006 не открывается | Tailscale не установлен на клиентском устройстве | Установить Tailscale и подключиться |
| Subnet routing не работает | Маршрут не одобрен в admin-консоли | Открыть admin → Machines → Edit route settings |
| `Permission denied` при Tailscale в LXC | Нет доступа к `/dev/net/tun` | Добавить `lxc.mount.entry` в конфиг LXC |
| Tailscale работает, но связь медленная | Используется relay (DERP), нет прямого соединения | Обычно проходит само через несколько минут |

Проверить через какой путь идёт трафик:

```bash
tailscale ping 100.101.102.50
# pong from my-phone (100.101.102.50) via 192.168.1.50:41641 in 2ms  ← прямое соединение
# pong from my-phone (100.101.102.50) via DERP(fra) in 35ms          ← через relay
```

## Практика

1. Установить Tailscale на хост Proxmox командой `curl -fsSL https://tailscale.com/install.sh | sh`.
2. Авторизовать устройство через `tailscale up` и ссылку в браузере.
3. Узнать Tailscale IP командой `tailscale ip -4`.
4. Зайти в веб-интерфейс Proxmox через `https://<tailscale-ip>:8006` с телефона (Tailscale должен быть установлен и на телефоне).
5. Опционально: включить subnet routing и попробовать пинговать домашний роутер через Tailscale с другого устройства.
