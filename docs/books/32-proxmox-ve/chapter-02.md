# Глава 2: Знакомство с веб-интерфейсом

> **Цель:** ориентироваться в интерфейсе не методом тыка — знать где что находится и сразу идти в нужное место.

---

**Что вы узнаете:**
- где находятся ключевые разделы интерфейса;
- как пользоваться Shell хоста прямо из браузера;
- как создавать VM и LXC, управлять ими, открывать консоль;
- где смотреть логи задач и ошибки;
- как сделать снапшот и запустить бэкап вручную.

---

## 2.1 Структура интерфейса

Открываешь `https://IP:8006`, логинишься как `root` / `pam` — и видишь три зоны.

**Левая панель — дерево объектов:**
```
Datacenter          ← глобальные настройки: Storage, Backup, Firewall, Users
└── proxmox         ← имя твоего узла (node)
    ├── local (pve) ← хранилище для ISO и шаблонов
    ├── local-lvm   ← хранилище для дисков VM и LXC
    ├── 100 (myct)  ← LXC-контейнер
    └── 200 (myvm)  ← виртуальная машина
```

**Центральная область** — вкладки выбранного объекта. У Node это Summary, Shell, Storage, Network и т.д. У VM/LXC — Console, Hardware, Options, Snapshots, Backup и т.д.

**Верхняя панель** — кнопки действий для выбранного объекта: Start, Shutdown, Reboot, Migrate, Clone.

Всё управление делается через левую панель: сначала выбираешь объект, потом вкладку, потом действие.

---

## 2.2 Shell: SSH прямо в браузере

Выбери узел (proxmox) → вкладка **Shell**.

Открывается полноценный терминал с подключением к хосту Proxmox. Никакого PuTTY — можно работать сразу.

Первые команды для знакомства:
```bash
pveversion          # версия Proxmox и ядра
pveversion --verbose  # подробная версия всех компонент

uptime              # сколько работает и средняя нагрузка
free -h             # RAM: использование и своп
df -h               # место на дисках
```

Пример вывода `pveversion`:
```
pve-manager/8.2.2/9355359cd4e0688b (running kernel: 6.8.12-5-pve)
```

**Важный нюанс:** `Ctrl+C` в консоли браузера передаётся внутрь системы, а не копирует текст. Для копирования — выделяй и нажимай правую кнопку мыши → Copy.

---

## 2.3 Summary: мониторинг в реальном времени

Узел → вкладка **Summary**.

Здесь видишь:
- нагрузку CPU в реальном времени (обновляется каждые 3 секунды);
- использование RAM и своп;
- заполненность дисков по каждому хранилищу;
- uptime.

Это первое место, куда смотришь если что-то тормозит. Если CPU 100% — сразу видно. Если RAM почти кончилась — тоже.

---

## 2.4 Tasks/Logs: лог всех операций

Справа снизу в интерфейсе всегда висит вкладка **Tasks** (иногда открывается как панель внизу экрана).

Здесь хранится история всех операций: создание контейнеров, бэкапы, миграции, обновления. Каждая задача показывает статус и время.

Если что-то пошло не так — сначала сюда:
1. Найди задачу с красным статусом.
2. Кликни по ней — откроется подробный лог с текстом ошибки.

Например, при неудачном бэкапе там будет точная причина: нет места, хранилище недоступно, LXC не остановился.

## 2.5 Создание VM и LXC

### Создать LXC-контейнер

Кнопка **Create CT** — в правом верхнем углу при выбранном узле.

Мастер проведёт через шаги:
1. **General** — ID (например 100), имя, пароль root.
2. **Template** — выбрать скачанный шаблон (Debian 12, Ubuntu 22.04 и т.д.).
3. **Disks** — размер корневого диска и хранилище (local-lvm).
4. **CPU** — количество ядер.
5. **Memory** — лимит RAM и своп.
6. **Network** — DHCP или статический IP.
7. **Confirm** — галочка «Start after created» если нужно сразу запустить.

Если шаблонов нет — сначала скачай: Datacenter → узел → local → **CT Templates** → кнопка Templates → выбрать из списка → Download.

### Создать VM

Кнопка **Create VM** — рядом с Create CT.

Шаги те же, но добавляется выбор ISO-образа. ISO загружается через: Datacenter → узел → local → **ISO Images** → Upload.

## 2.6 Управление VM и LXC: запуск, стоп, консоль

Выбери VM или LXC в левой панели.

**Кнопки в верхней панели:**
- **Start** — запустить.
- **Shutdown** — корректная остановка (посылает сигнал ОС).
- **Stop** — жёсткое выключение (как выдернуть питание).
- **Reboot** — перезагрузка.

`Shutdown` предпочтительнее `Stop` — ОС завершает процессы корректно. Но если система зависла — используй `Stop`.

### Консоль

Вкладка **Console** — открывает терминал прямо в браузере.

Для LXC это bash внутри контейнера. Для VM — экран с VNC или SPICE подключением.

Альтернатива для LXC через Shell хоста:
```bash
pct enter 100       # войти в LXC 100 (аналог docker exec -it)
```

## 2.7 Снапшот: быстрый откат перед рискованным действием

Снапшот фиксирует состояние контейнера или VM в текущий момент. Если что-то сломаешь — откатываешься за секунды.

Правило: **делай снапшот перед каждым обновлением или экспериментом**.

Через интерфейс: VM/CT → вкладка **Snapshots** → кнопка **Take Snapshot** → дать имя (например `before-nginx-update`).

Через CLI на хосте:
```bash
# Снапшот LXC 100
pct snapshot 100 before-nginx-update --description "Before nginx 1.26 upgrade"

# Откатиться
pct rollback 100 before-nginx-update

# Список снапшотов
pct listsnapshot 100
```

Снапшот хранится на том же диске — это не бэкап. Если диск умрёт, снапшот тоже пропадёт. Но для быстрого отката при экспериментах — идеален.

## 2.8 Бэкап вручную

Если хочешь сделать полный бэкап прямо сейчас, не дожидаясь расписания:

Через интерфейс: VM/CT → вкладка **Backup** → кнопка **Backup now** → выбрать хранилище и режим (Snapshot / Suspend / Stop).

Через CLI:
```bash
# Бэкап LXC 100 в хранилище local, режим snapshot, сжатие zstd
vzdump 100 --storage local --compress zstd --mode snapshot
```

Файл бэкапа сохраняется в Datacenter → узел → local → **Backups**. Там же можно восстановить контейнер из файла кнопкой **Restore**.

## 2.9 Практика: ориентация в интерфейсе

Выполни эти действия сам:

1. Открой Shell узла, выполни `pveversion` и `free -h`.
2. В Summary найди текущую нагрузку CPU и объём свободной RAM.
3. В разделе Storage посмотри сколько свободно места на `local` и `local-lvm`.
4. Открой Tasks — найди последнюю выполненную задачу.
5. Скачай шаблон Debian 12 через CT Templates.
6. Создай тестовый LXC (ID 999, 512MB RAM, 4GB диск, DHCP).
7. Запусти его, открой Console, выполни `hostname`.
8. Сделай снапшот с именем `first-snapshot`.
9. Сделай бэкап вручную через вкладку Backup.
10. Останови и удали тестовый LXC (More → Remove).
