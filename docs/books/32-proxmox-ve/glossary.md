# Глоссарий

> Термины и выражения книги «Proxmox VE: домашний и корпоративный гипервизор с нуля». В скобках — главы, где термин вводится или активно используется.

---

## Платформа и базовые понятия

**Proxmox VE (PVE)** — гипервизор типа 1 (bare-metal) на базе Debian: ставится на чистое железо и сам является базовой операционной системой, поверх которой запускаются виртуальные машины и контейнеры. _(главы 0, 1)_

**Гипервизор** — программное обеспечение, которое управляет виртуальными машинами и разделяет физические ресурсы сервера (CPU, RAM, диски) между изолированными окружениями. _(глава 0)_

**Гипервизор типа 1 (bare-metal)** — гипервизор, работающий прямо на железе без промежуточной ОС; сам является операционной системой. Примеры: Proxmox, ESXi, Hyper-V. _(глава 0)_

**Гипервизор типа 2 (hosted)** — гипервизор, работающий поверх обычной ОС (Windows, Ubuntu). Примеры: VirtualBox, VMware Workstation, Parallels. _(глава 0)_

**Хост (host)** — физический сервер с установленным Proxmox; базовая система, под управлением которой работают все VM и контейнеры. _(главы 0, 1)_

**Нода (node)** — отдельный сервер Proxmox. Самостоятельная единица, которая может работать в одиночку или входить в кластер. _(главы 15, 23)_

**Datacenter** — верхний уровень веб-интерфейса Proxmox, объединяющий все ноды; здесь настраиваются хранилища, HA, пользователи и общие параметры. _(главы 2, 15)_

**Веб-интерфейс (8006)** — графическая панель управления Proxmox, доступная по HTTPS на порту 8006. _(главы 1, 2)_

**pveproxy** — служба Proxmox, обслуживающая веб-интерфейс на порту 8006. _(глава 1)_

**No-Subscription репозиторий** — бесплатный репозиторий обновлений Proxmox для тех, у кого нет платной подписки; включается вместо Enterprise-репозитория. _(главы 1, 24, 25)_

**Enterprise репозиторий** — платный репозиторий обновлений, требующий подписки; в домашних сценариях отключается. _(главы 1, 25)_

## Виртуализация: VM, контейнеры, образы

**VM (виртуальная машина)** — изолированное окружение со своим полным ядром и эмулированным «железом»; позволяет запускать любую ОС, включая Windows. _(главы 0, 5)_

**KVM (Kernel-based Virtual Machine)** — технология аппаратной виртуализации в ядре Linux, на которой Proxmox запускает полноценные виртуальные машины. _(главы 0, 5)_

**QEMU** — эмулятор/виртуализатор, который совместно с KVM предоставляет VM виртуальные устройства (диски, сеть, дисплей). _(глава 5)_

**LXC (контейнер)** — лёгкий контейнер, разделяющий ядро с хостом; полноценная мини-система с systemd, cron и SSH, но без overhead отдельного ядра. _(главы 0, 3)_

**Контейнер (CT)** — экземпляр LXC в Proxmox; обозначается ID вида CT 100. _(главы 0, 3)_

**Privileged-контейнер** — LXC, в котором root внутри совпадает с root хоста; нужен для некоторых сценариев (например, Docker), но менее изолирован. _(главы 3, 4, 12)_

**Unprivileged-контейнер** — LXC с маппингом UID/GID, где root внутри не равен root хоста; безопаснее, вариант по умолчанию. _(главы 3, 4)_

**Nesting** — флаг LXC, разрешающий запускать внутри контейнера вложенную виртуализацию/контейнеризацию, в частности Docker. _(главы 4, 12)_

**Docker внутри LXC** — рекомендуемый в книге способ запускать Docker-сервисы: не на хосте Proxmox напрямую, а внутри LXC-контейнера. _(главы 0, 4, 12)_

**CT-шаблон (template)** — tarball готовой системы для быстрого создания LXC-контейнеров; хранится в Directory-хранилище. _(главы 3, 7)_

**Шаблон VM (template)** — VM, преобразованная в неизменяемый образец, из которого клонируются новые машины (особенно с Cloud-Init). _(главы 21)_

**Клонирование (clone)** — создание новой VM/LXC из шаблона: полное (full clone) или связанное (linked clone). _(глава 21)_

**ISO-образ** — установочный образ ОС; в Proxmox хранится в Directory-хранилище и монтируется к VM. _(главы 1, 7)_

**Cloud-образ (cloud image)** — готовый образ диска с предустановленным cloud-init, рассчитанный на автоматическую настройку при первом запуске вместо ручной установки из ISO. _(глава 21)_

**Balloon (memory ballooning)** — механизм динамического выделения RAM виртуальной машине в заданных пределах (например, 1–2 ГБ). _(глава 0)_

**Overhead** — накладные расходы по CPU/RAM, которые добавляет уровень виртуализации; у LXC минимален, у VM выше. _(глава 0)_

## Хранилища

**Хранилище (storage)** — в Proxmox это абстракция над дисками: место, куда складываются образы VM, rootfs контейнеров, бэкапы и ISO. _(глава 7)_

**local** — стандартное Directory-хранилище на `/var/lib/vz/`, создаётся при установке; для ISO и CT-шаблонов. _(глава 7)_

**local-lvm** — стандартное LVM-Thin хранилище, создаётся при установке; сюда идут диски VM и LXC. _(глава 7)_

**Directory** — хранилище-папка на файловой системе; подходит для ISO, бэкапов, CT-шаблонов и образов qcow2. _(глава 7)_

**LVM (Logical Volume Manager)** — стандартный менеджер логических томов Linux; нарезает диск на тома, в базовом режиме без снапшотов. _(глава 7)_

**LVM-Thin** — LVM с thin provisioning: тома занимают реальное место по мере записи, поддерживают снапшоты через CoW и overcommit. _(глава 7)_

**Thin provisioning** — выделение дискового пространства «по факту записи»: том обещает размер, но реально потребляет место только под записанные данные. _(глава 7)_

**Overcommit** — выделение виртуально большего объёма, чем есть физически; за реальным заполнением пула нужно следить (`lvs`, колонка `Data%`). _(глава 7)_

**ZFS** — продвинутая файловая система и менеджер томов: датасеты и zvol, снапшоты CoW, RAID, контроль целостности и сжатие. _(главы 7, 23)_

**ZFS pool (zpool)** — пул из одного или нескольких дисков, на котором ZFS размещает данные; mirror из двух дисков = RAID1. _(глава 7)_

**Datasets / zvol** — единицы ZFS: датасет (файловая система) и zvol (блочное устройство для дисков VM/LXC). _(глава 7)_

**Copy-on-Write (CoW)** — принцип, при котором изменения пишутся в новые блоки, а старые сохраняются; основа быстрых снапшотов в LVM-Thin и ZFS. _(главы 7, 8)_

**RAID1 (mirror)** — зеркалирование данных на два диска для отказоустойчивости; реализуется ZFS-пулом типа mirror. _(глава 7)_

**SMART** — система самодиагностики дисков; предупреждает о приближающемся отказе накопителя. _(глава 18)_

**Volume Group (VG) / Logical Volume (LV)** — группа физических томов LVM и логический том внутри неё; thin pool — особый LV. _(глава 7)_

## Резервное копирование

**Снапшот (snapshot)** — мгновенный «слепок» состояния VM/LXC в текущий момент; позволяет быстро откатиться, но хранится на том же диске и не заменяет бэкап. _(глава 8)_

**Бэкап (backup)** — полная независимая копия VM/LXC в виде файла, которую можно восстановить даже при потере исходного диска. _(глава 8)_

**vzdump** — встроенный инструмент Proxmox для создания полных бэкапов VM и контейнеров в файлы `.tar.zst`. _(главы 8, 19)_

**Дамп (dump)** — файл бэкапа, созданный vzdump. _(глава 8)_

**Proxmox Backup Server (PBS)** — отдельный продукт Proxmox для хранения бэкапов с дедупликацией и инкрементальными обновлениями. _(главы 8, 25)_

**Инкрементальный бэкап** — бэкап, сохраняющий только изменения с прошлого раза; в PBS резко уменьшает занимаемое место. _(глава 8)_

**Дедупликация** — хранение одинаковых блоков данных один раз; основа экономии места в PBS. _(глава 8)_

**Chunked storage / Chunk Store** — хранилище PBS, где данные разбиты на блоки (chunks), что позволяет дедупликацию и инкрементальность. _(глава 8)_

**Восстановление (restore)** — воссоздание VM/LXC из файла бэкапа, в том числе под новым или прежним ID. _(главы 8, 19)_

## Сеть

**Виртуальный мост (bridge)** — программный коммутатор внутри ядра Linux, к которому подключаются интерфейсы хоста, контейнеров и VM. _(глава 9)_

**vmbr0** — основной виртуальный мост, создаваемый при установке Proxmox; на нём хост получает свой IP, к нему подключены VM и LXC. _(глава 9)_

**veth** — пара виртуальных интерфейсов LXC: один конец в хосте (`veth100i0`), другой внутри контейнера как `eth0`. _(глава 9)_

**tap-интерфейс** — виртуальный сетевой интерфейс VM, подключаемый к мосту (`tap102i0`). _(глава 9)_

**enp3s0** — пример имени физического сетевого порта хоста; добавляется как порт моста и теряет собственный IP. _(глава 9)_

**/etc/network/interfaces** — файл, в котором хранится вся сетевая конфигурация хоста Proxmox. _(глава 9)_

**DHCP** — автоматическая выдача IP-адресов; для серверов книга рекомендует статику. _(главы 9, 22)_

**Статический IP** — фиксированный адрес, заданный вручную; предпочтителен для серверов и сервисов. _(глава 9)_

**VLAN** — логическое разделение одной физической сети на изолированные сегменты по тегам (VLAN tag). _(главы 9, 17, 22)_

**VLAN-aware bridge** — мост, умеющий пропускать тегированный VLAN-трафик и назначать VLAN отдельным контейнерам/VM. _(глава 9)_

**Bonding** — объединение нескольких физических портов в один логический для отказоустойчивости или пропускной способности. _(глава 9)_

**Firewall Proxmox** — встроенный многоуровневый файрвол (Datacenter / Node / VM) для ограничения доступа. _(главы 9, 17)_

**Reverse proxy** — сервис (например, Nginx Proxy Manager), принимающий внешние запросы и направляющий их к нужным внутренним сервисам. _(главы 12, 20)_

**Nginx Proxy Manager (NPM)** — веб-инструмент для управления reverse proxy и SSL-сертификатами через UI. _(главы 12, 20)_

**Let's Encrypt** — бесплатный центр сертификации для автоматического получения SSL-сертификатов (в книге — через DuckDNS). _(главы 12, 20)_

## Удалённый доступ

**Tailscale** — VPN-сеть на базе WireGuard, дающая безопасный доступ к Proxmox без открытия порта 8006 в интернет. _(глава 11)_

**WireGuard** — современный быстрый VPN-протокол, лежащий в основе Tailscale. _(глава 11)_

**Subnet routing** — функция Tailscale, открывающая доступ не к одному узлу, а ко всей домашней подсети через узел-маршрутизатор. _(глава 11)_

**Tailscale IP** — адрес из диапазона 100.x.x.x, по которому узел доступен внутри tailnet. _(глава 11)_

## Кластеризация и отказоустойчивость

**Кластер (cluster)** — объединение нескольких нод Proxmox в единую систему с общим веб-интерфейсом, живой миграцией и HA. _(главы 15, 23)_

**Corosync** — протокол синхронизации состояния кластера; рассылает heartbeat между узлами и сообщает о выпадении ноды. _(главы 15, 23)_

**Кворум (quorum)** — минимальное число голосов нод (большинство), необходимое кластеру для принятия решений и предотвращения split-brain. _(главы 15, 23, 24)_

**Split-brain** — опасная ситуация, когда узлы потеряли связь, но каждый считает себя главным и запускает одни и те же VM, что ведёт к повреждению данных. _(главы 15, 23)_

**Голос (vote)** — единица в механизме кворума; обычно у каждой ноды один голос, у QDevice — отдельный. _(главы 15, 23)_

**Read-only режим** — состояние ноды, оставшейся в меньшинстве: она не принимает решений, чтобы не вызвать split-brain. _(глава 15)_

**Живая миграция (Live Migration)** — перенос работающей VM с одной ноды на другую без остановки; RAM синхронизируется по сети, переключение занимает доли секунды. _(главы 15, 25)_

**Флаг --online** — параметр `qm migrate`, включающий живую миграцию без остановки VM. _(глава 15)_

**High Availability (HA)** — автоматический перезапуск защищённых VM/LXC на оставшихся нодах при выходе одной из строя. _(главы 15, 23)_

**HA Manager** — компонент кластера, принимающий решение о переносе VM при падении ноды. _(глава 15)_

**HA Resources / Groups** — список защищаемых VM/LXC и группы узлов, на которых им разрешено работать. _(глава 15)_

**Heartbeat** — периодический сигнал «я жив» между узлами через Corosync; его пропадание трактуется как падение ноды. _(глава 15)_

**Fencing** — изоляция упавшего узла командой «выключись» (через IPMI/iDRAC/STONITH), чтобы «мёртвый» узел гарантированно не писал на диск. _(глава 15)_

**Общее хранилище (shared storage)** — хранилище, доступное всем нодам кластера; обязательное условие для живой миграции и HA (NFS, iSCSI, Ceph). _(главы 15, 24)_

**Репликация (ZFS replication)** — периодическая отправка снапшотов ZFS на другую ноду; способ обеспечить HA в двухнодовой схеме без общего хранилища. _(глава 23)_

**QDevice** — небольшая внешняя машина с `corosync-qnetd`, дающая дополнительный голос для кворума в двухнодовом кластере, но не хранящая VM и не являющаяся нодой. _(глава 23)_

**corosync-qnetd** — пакет, превращающий обычную Linux-машину (например, Raspberry Pi) в QDevice. _(глава 23)_

**Raspberry Pi** — одноплатный компьютер, удобный как дешёвый и экономичный носитель QDevice. _(глава 23)_

**pvecm** — утилита управления кластером: `pvecm create` создаёт кластер, `pvecm add` присоединяет ноду. _(глава 23)_

## Ceph

**Ceph** — встроенная в Proxmox распределённая отказоустойчивая система хранения: данные разбиваются на блоки и реплицируются по дискам нескольких нод. _(глава 24)_

**OSD (Object Storage Daemon)** — демон, управляющий одним физическим диском в Ceph; принимает чтение и запись. _(глава 24)_

**Monitor (MON)** — процесс-арбитр Ceph: хранит карту кластера и голосует за кворум. _(глава 24)_

**Manager (MGR)** — процесс Ceph, собирающий метрики и отдающий данные в дашборд Proxmox. _(глава 24)_

**Ceph Pool** — виртуальное хранилище поверх OSD, из которого VM берут диски; задаёт число реплик (`size`). _(глава 24)_

**RBD (RADOS Block Device)** — блочное устройство Ceph, используемое как диск VM/LXC. _(глава 24)_

**CRUSH** — алгоритм Ceph, определяющий, на каких именно OSD разместить каждый блок данных. _(глава 24)_

**size (число реплик)** — параметр пула Ceph: сколько копий блока хранить (например, `size=2` — две копии на разных нодах). _(глава 24)_

**CephFS** — распределённая файловая система Ceph, удобная как общее хранилище для ISO и бэкапов. _(глава 24)_

**Cluster network** — выделенная (желательно 10 Гбит) сеть под внутренний трафик репликации Ceph, отделённая от VM-трафика. _(глава 24)_

## SDN

**SDN (Software Defined Networking)** — встроенный в Proxmox «виртуальный коммутатор с мозгами»: топология сети описывается в интерфейсе, а Proxmox разворачивает её сам. _(глава 22)_

**Зона (Zone)** — тип и правила изоляции SDN-сети; бывает Simple, VLAN, QinQ, VXLAN, EVPN. _(глава 22)_

**Vnet (виртуальная сеть)** — виртуальный мост внутри зоны, к которому подключаются VM вместо `vmbr0`. _(глава 22)_

**Subnet (подсеть)** — диапазон IP для Vnet: шлюз, DHCP-диапазон, маршруты. _(глава 22)_

**Simple-зона** — простейшая SDN-зона: изолированная сеть со своим DHCP и SNAT в интернет, настраивается без терминала. _(глава 22)_

**VLAN-зона** — SDN-зона, работающая поверх физических VLAN. _(глава 22)_

**IPAM (IP Address Management)** — учёт IP-адресов в SDN: какие адреса заняты и кем. _(глава 22)_

**SNAT / MASQUERADE** — подмена адреса источника, позволяющая VM из изолированной SDN-сети выходить в интернет через хост. _(глава 22)_

**dnsmasq** — лёгкий DNS/DHCP-сервер; Proxmox запускает отдельный его экземпляр под каждую SDN-зону с DHCP. _(глава 22)_

**FRR (Free Range Routing)** — пакет маршрутизации, нужный SDN для связности между сетями и внешним миром. _(глава 22)_

## Cloud-Init

**Cloud-Init** — стандартный механизм первоначальной настройки ОС при первом запуске: имя хоста, пользователь, пароль, SSH-ключи, сеть. _(глава 21)_

**Cloud-Init диск** — специальный диск с данными настройки, который Proxmox подкладывает VM; гостевая ОС читает его при старте. _(глава 21)_

**machine-id** — уникальный идентификатор системы; перед созданием шаблона его сбрасывают, чтобы клоны не получили одинаковый ID. _(глава 21)_

## Управление, автоматизация, диагностика

**Proxmox Datacenter Manager (PDM)** — отдельный продукт-агрегатор, дающий обзорную картину по нескольким серверам и кластерам и позволяющий мигрировать VM между ними. _(глава 25)_

**pvesh** — CLI-обёртка над Proxmox API для скриптов и автоматизации. _(глава 14)_

**Proxmox API** — REST-интерфейс Proxmox, через который выполняются все действия панели; основа автоматизации. _(глава 14)_

**/etc/pve** — кластерная конфигурационная файловая система (pmxcfs) Proxmox; её хранение в git превращает конфиги в IaC. _(глава 14)_

**IaC (Infrastructure as Code)** — подход, при котором инфраструктура описывается кодом/конфигами и воспроизводится автоматически. _(глава 14)_

**Ansible (community.general.proxmox)** — система управления конфигурациями; модуль для декларативного создания VM/LXC в Proxmox. _(глава 14)_

**Terraform** — инструмент декларативного управления инфраструктурой; в книге упоминается как направление для роста. _(глава 14)_

**Idempotent-скрипт** — скрипт, дающий одинаковый результат при повторном запуске: уже существующее не дублируется. _(главы 14, 20)_

**Community Scripts** — набор готовых скриптов сообщества для быстрой установки сервисов в LXC («магазин приложений» для Proxmox). _(главы 6, приложение B)_

**qm** — CLI-утилита управления виртуальными машинами (`qm migrate`, `qm start` и т.п.). _(главы 15, 21)_

**pct** — CLI-утилита управления LXC-контейнерами. _(главы 3, 13)_

**pvesm** — CLI-утилита управления хранилищами Proxmox (`pvesm status`). _(глава 7)_

**Netdata** — лёгкий инструмент мониторинга хоста в реальном времени. _(глава 13)_

**Uptime Kuma** — сервис мониторинга доступности служб с уведомлениями (в книге — в связке с Telegram). _(глава 19)_

**fail2ban** — служба, автоматически блокирующая IP после серии неудачных попыток входа (защита от брутфорса). _(глава 17)_

**TFA / 2FA (двухфакторная аутентификация)** — дополнительный фактор входа поверх пароля для защиты веб-интерфейса. _(глава 17)_

**Zero-trust** — подход «не доверяй по умолчанию»: в книге реализован через VLAN-сегментацию сети на изолированные зоны. _(глава 17)_

**PCI Passthrough** — проброс физического PCI-устройства (например, GPU) напрямую в VM/LXC для прямого доступа к железу. _(глава 10)_

**IOMMU** — аппаратная технология (VT-d/AMD-Vi), необходимая для безопасного PCI Passthrough; включается в BIOS и GRUB. _(глава 10)_

**VFIO** — драйверный механизм Linux, через который устройство «отдаётся» виртуальной машине при passthrough. _(глава 10)_

**Аппаратный транскодинг** — перекодирование видео силами GPU (например, для Jellyfin), доступное через passthrough. _(главы 10, приложение C)_

**journalctl vacuum** — операция очистки системного журнала systemd для освобождения места. _(глава 19)_

**GRUB** — загрузчик; при проблемах после обновления Proxmox позволяет загрузиться со старого ядра. _(глава 19)_
