# Глава 1: Установка Proxmox VE

> **Что вы узнаете:**
> - какое железо нужно для Proxmox и что будет если не хватает ресурсов;
> - как записать ISO на флешку и пройти установку шаг за шагом;
> - как попасть в веб-интерфейс и что сделать сразу после первого входа;
> - как отключить платный репозиторий и не получать ошибки при обновлении.

---

## 1.1 Системные требования

Proxmox устанавливается на реальное железо — это гипервизор типа 1, он сам и есть операционная система. Виртуалбокс или VMware на него сверху не нужны.

**Минимум для старта:**

| Компонент | Минимум | Рекомендуется |
|-----------|---------|---------------|
| CPU | 64-bit, 2 ядра | 4+ ядра, поддержка VT-x/AMD-V |
| RAM | 2 GB | 8–16 GB |
| Диск | 32 GB | 128+ GB SSD |
| Сеть | 1 сетевой интерфейс | 1 GbE и выше |

**Про RAM честно:** 2 GB — это только чтобы Proxmox загрузился. Если планируешь запускать хотя бы 2–3 контейнера, нужно минимум 4 GB. Для домашнего сервера с Nextcloud, Home Assistant и парой Docker-сервисов — 8–16 GB.

**Про диск:** Proxmox сам занимает ~4–5 GB. Остальное место уходит под диски контейнеров и VM. На 32 GB поместится разве что сам хост и пара лёгких LXC. Для нормальной работы — SSD от 128 GB.

**Про процессор:** обязательно нужна аппаратная виртуализация. Intel называет это VT-x, AMD — AMD-V. Без неё KVM VM не запустятся вообще. LXC-контейнеры работают и без неё, но это крайний случай. Как проверить и включить — в разделе 1.6.

**Что подходит для домашнего сервера:**
- Старый десктоп или ноутбук с 8+ GB RAM.
- Мини-ПК: Intel NUC, Beelink, TRIGKEY — популярный выбор.
- Б/у серверное железо: Dell PowerEdge R720, HP ProLiant DL380 — мощно, но шумно.
- Raspberry Pi 5 — не подходит, там нет аппаратной виртуализации KVM.

## 1.2 Скачать ISO и записать на флешку

Качать официальный ISO с сайта Proxmox:

```
https://www.proxmox.com/en/downloads/proxmox-virtual-environment/iso
```

Берём последнюю версию — на момент написания это Proxmox VE 8.x. Файл называется примерно `proxmox-ve_8.3-1.iso`, весит около 1.3 GB.

### Записать на флешку — Windows

Используй **Rufus** (`https://rufus.ie`):
1. Вставь флешку (минимум 2 GB).
2. В поле "Device" выбери флешку.
3. В поле "Boot selection" нажми "SELECT" и укажи ISO.
4. Partition scheme: GPT, Target system: UEFI (или MBR + BIOS для старого железа).
5. Нажми "START", подтверди что данные на флешке сотрутся.

### Записать на флешку — Linux/macOS

Используй **balenaEtcher** (`https://etcher.balena.io`) — визуально, просто, без ошибок.

Или через командную строку:

```bash
# Найти устройство флешки (смотреть по размеру)
lsblk

# Записать ISO — замени /dev/sdX на своё устройство
# ОСТОРОЖНО: dd затирает без предупреждения
dd if=proxmox-ve_8.3-1.iso of=/dev/sdX bs=4M status=progress && sync
```

Флешка готова. Теперь загружаемся с неё.

## 1.3 Установка шаг за шагом

Вставь флешку, перезагрузи сервер, зайди в BIOS и выбери загрузку с USB. Обычно это F2, F12, DEL или Escape при старте — зависит от материнской платы.

**Шаг 1 — выбор установщика**

Появится меню. Выбираем:
```
Install Proxmox VE (Graphical)
```

Текстовый режим `Terminal UI` есть для серверов без графики, но графический работает через VNC и подойдёт в большинстве случаев.

**Шаг 2 — лицензионное соглашение**

EULA. Нажми "I agree".

**Шаг 3 — выбор диска**

```
Target Harddisk: /dev/sda (или sdb, nvme0n1 — смотри по размеру)
```

Нажми "Options" — здесь можно выбрать файловую систему:
- **ext4** — проще, быстрее для начала, без снапшотов на уровне хоста.
- **ZFS (RAID0)** — один диск с ZFS. Даёт снапшоты и проверку целостности данных, но требует больше RAM (~1 GB на 1 TB данных).
- **ZFS (RAID1)** — зеркало из двух дисков. Выбирать только если есть два одинаковых диска.

Для начала — **ext4**. ZFS изучим в главе 7.

**Важно:** установщик сотрёт весь диск. Убедись что выбрал правильный диск. Проверь размер — не перепутай с флешкой.

**Шаг 4 — страна, timezone, раскладка**

```
Country: Russia (или свою страну)
Time zone: Europe/Moscow (или свою)
Keyboard Layout: Russian (или English — как удобно)
```

**Шаг 5 — пароль и email**

```
Password: <придумай надёжный пароль для root>
Confirm: <повторить>
Email: admin@example.com (используется для уведомлений, можно любой)
```

Пароль будет у пользователя `root` — и для SSH, и для веб-интерфейса.

**Шаг 6 — сетевые настройки**

```
Management Interface: enp3s0 (или eth0 — выбирай тот, что подключён к роутеру)
Hostname (FQDN): proxmox.local
IP Address (CIDR): 192.168.1.100/24
Gateway: 192.168.1.1
DNS Server: 192.168.1.1
```

Выбирай статический IP — он не должен меняться после перезагрузок. Возьми адрес из диапазона своей сети, который роутер не выдаёт по DHCP (обычно .100 и выше безопасно).

**Шаг 7 — обзор и установка**

Появится итоговая сводка. Проверь IP и имя хоста. Нажми "Install".

Установка занимает 3–5 минут. После — система попросит убрать флешку и перезагрузиться.

**Шаг 8 — готово**

После перезагрузки увидишь текстовую консоль с сообщением:

```
Welcome to the Proxmox Virtual Environment. Please use your web browser to
configure this server - connect to:

  https://192.168.1.100:8006/
```

Это твой адрес для входа в веб-интерфейс.

## 1.4 Первый вход в веб-интерфейс

Открой браузер и перейди по адресу:

```
https://192.168.1.100:8006
```

Здесь тебя встретит предупреждение браузера: **"Соединение не защищено"** или **"Your connection is not private"**. Это нормально — Proxmox использует самоподписанный сертификат, браузер его не знает.

**Как добавить исключение:**
- Chrome/Edge: нажми "Дополнительно" → "Перейти на сайт 192.168.1.100 (небезопасно)"
- Firefox: нажми "Дополнительно..." → "Принять риск и продолжить"
- Safari: нажми "Дополнительно" → "Всё равно посетить сайт"

После добавления исключения браузер запомнит его — больше предупреждение не появится.

Форма входа:
```
User name: root
Password: <пароль который ввёл при установке>
Realm: Linux PAM standard authentication
```

Нажми "Login". Если появилось всплывающее окно про подписку — закрой его крестиком. Это реклама платного плана.

Ты в веб-интерфейсе Proxmox. В следующей главе разберём что здесь и где находится. Сначала — обязательные действия после установки.

## 1.5 Отключить платный репозиторий, подключить бесплатный

Proxmox — продукт с открытым исходным кодом, но компания предлагает платную подписку. Без неё enterprise-репозиторий недоступен, и при каждом `apt update` ты будешь получать ошибку:

```
E: Failed to fetch https://enterprise.proxmox.com/debian/pve/dists/bookworm/InRelease
   401 Unauthorized [IP: 45.83.104.1 443]
```

Это не критично для работы, но раздражает. Плюс — без бесплатного репозитория обновления вообще не будут приходить.

Открой **Shell** прямо в веб-интерфейсе: выбери свой узел в левой панели → вкладка "Shell". Или подключись по SSH:

```bash
ssh root@192.168.1.100
```

Выполни три команды:

```bash
# Отключить enterprise репозиторий (платный)
# Просто комментируем строку — файл не удаляем
sed -i 's/^deb/#deb/' /etc/apt/sources.list.d/pve-enterprise.list

# Отключить Ceph enterprise репозиторий (тоже платный, появился в PVE 8)
sed -i 's/^deb/#deb/' /etc/apt/sources.list.d/ceph.list 2>/dev/null || true

# Добавить бесплатный репозиторий (без подписки)
echo "deb http://download.proxmox.com/debian/pve bookworm pve-no-subscription" \
  > /etc/apt/sources.list.d/pve-no-subscription.list

# Обновить систему
apt update && apt full-upgrade -y
```

После `apt update` ты должен увидеть список пакетов без ошибок 401.

`apt full-upgrade` вместо `apt upgrade` — это важно. Proxmox обновляет ядро и системные компоненты, которые требуют `full-upgrade` для корректного разрешения зависимостей. Обычный `upgrade` может пропустить важные пакеты.

После обновления перезагрузись — особенно если обновилось ядро:

```bash
reboot
```

## 1.6 Типичные ошибки при установке

### Веб-интерфейс не открывается

**Симптом:** браузер пишет "Сайт недоступен" или "Соединение отклонено".

Проверь с сервера:
```bash
# Проверить что pveproxy запущен
systemctl status pveproxy

# Если не запущен — запустить
systemctl start pveproxy

# Проверить что порт слушается
ss -tlnp | grep 8006
```

Если `pveproxy` работает, но браузер не открывает — проблема в сети. Проверь что:
- Ты в той же сети что и сервер.
- IP правильный — посмотри в консоли сервера командой `ip a`.
- Ты используешь `https://`, а не `http://`.

### BIOS: не включена виртуализация

**Симптом:** при попытке создать KVM VM появляется ошибка:
```
KVM virtualisation configured, but not available. Either disable in VM configuration or enable in BIOS.
```

**Решение:** зайти в BIOS/UEFI (при загрузке нажать F2, DEL или F10 — зависит от материнской платы) и найти раздел CPU, Virtualization или Advanced.

Включить:
- **Intel:** Intel Virtualization Technology (VT-x) или Intel VT-x
- **AMD:** AMD Virtualization (AMD-V) или SVM Mode

Сохранить и перезагрузить.

Проверка что виртуализация доступна:
```bash
# На хосте Proxmox
egrep -c '(vmx|svm)' /proc/cpuinfo
# Результат > 0 — всё в порядке
# Результат = 0 — виртуализация отключена в BIOS
```

### Браузер блокирует self-signed сертификат

Если браузер не даёт добавить исключение (например корпоративная политика), можно временно использовать `curl`:

```bash
curl -k https://192.168.1.100:8006
```

Флаг `-k` игнорирует проверку сертификата. Для постоянной работы — лучше выпустить нормальный сертификат через Let's Encrypt (разберём в главе 12).

### Ошибка 401 при apt update после установки

Уже описано в разделе 1.5. Если после выполнения команд ошибка всё ещё есть — проверь что файл был изменён:

```bash
cat /etc/apt/sources.list.d/pve-enterprise.list
# Строка должна начинаться с #deb, а не с deb
```

### Установка зависла на "Formatting disk"

Бывает на медленных дисках или при проблемах с SMART. Подожди 5–10 минут. Если не помогает — проверь диск:

```bash
# После загрузки с Live USB или через rescue
smartctl -H /dev/sda
```

## 1.7 Проверка после установки

Выполни в Shell веб-интерфейса или по SSH:

```bash
# Версия Proxmox
pveversion
# Пример вывода:
# pve-manager/8.3-1/something (running kernel: 6.8.12-1-pve)

# Статус всех сервисов Proxmox
systemctl status pveproxy pvedaemon pvestatd
# Все три должны быть active (running)

# Состояние хранилищ
pvesm status
# local     dir      active   79    55      24   69.52%
# local-lvm lvmthin  active  127     0     127    0.00%

# Версия ядра
uname -r
# 6.8.12-1-pve  ← должно быть pve-ядро, не стандартный debian
```

Если всё зелёное — установка прошла успешно.
