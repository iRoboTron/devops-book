## Главная идея

LLM — это ещё один сервис. Со своим API, портом, логами и требованиями к ресурсам.

Человек который умеет деплоить Docker-контейнеры и настраивать Nginx уже умеет 80% того что нужно для запуска локальной языковой модели.

```
Без понимания:           С пониманием:
ChatGPT = магия          LLM = модель + сервер + API
нельзя контролировать    можно деплоить, мониторить, интегрировать
платишь за чужое         используешь своё
```

**Ключевое понимание, которое должна сформировать книга:**
- Модель — это файл. Сервер — это процесс. API — это HTTP.
- Ollama делает запуск модели таким же простым как `docker run`.
- Локальные модели — не замена облачным везде, а дополнение там где нужна приватность, скорость или автономность.
- `curl` к Ollama API — то же самое что `curl` к любому REST API.

**Цель:** читатель понимает что происходит, когда он пишет ChatGPT сообщение.

Объяснить:
- Что такое языковая модель в двух словах (предсказание следующего токена)
- Чем отличаются модели по размеру: 7B, 13B, 70B — что это значит практически
- Почему большая модель не всегда лучше для конкретной задачи

- Что такое контекстное окно и почему оно важно
- Quantization: почему модель 7B помещается в 4GB RAM
- Что такое inference (вывод): модель не думает, она вычисляет

Таблица: сравнение подходов

| Подход | Приватность | Стоимость | Скорость | Когда выбирать |
|---|---|---|---|---|
| ChatGPT / Claude API | Низкая | За токен | Высокая | Лучшее качество |
| Локальная модель (CPU) | Полная | Электричество | Медленнее | Приватность, автономность |
| Локальная модель (GPU) | Полная | Электричество | Высокая | Есть GPU |
| Self-hosted API proxy | Средняя | За токен | Высокая | Контроль + качество |

### Глава 1: Ollama — установка и первая модель

**Цель:** читатель запускает языковую модель за 10 минут.

- Что такое Ollama и зачем он нужен
- Установка: Linux (нативная и Docker)
  ```bash
  # Нативная установка
  curl -fsSL https://ollama.com/install.sh | sh
  systemctl status ollama

  # Или Docker
  docker run -d -v ollama:/root/.ollama -p 11434:11434 \
    --name ollama ollama/ollama
  ```
- Скачать первую модель:
  ```bash
  ollama pull llama3.2:3b
  # Что происходит: скачивается файл модели в ~/.ollama/models
  ```
- Первый диалог:
  ```bash
  ollama run llama3.2:3b
  >>> Привет! Ты кто?
  ```
- Посмотреть скачанные модели:
  ```bash
  ollama list
  ```
- Удалить модель:
  ```bash
  ollama rm llama3.2:3b
  ```

**Объяснить:** что происходит под капотом — модель загружается в RAM, остаётся там пока не тайм-аут, отвечает на запросы.

### Глава 2: Выбор модели — что скачать

**Цель:** читатель умеет выбирать модель под задачу, не скачивая всё подряд.

Объяснить семейства моделей:

| Модель | Размер | RAM | Для чего |
|---|---|---|---|
| llama3.2:3b | ~2 GB | 4 GB | Тест, слабый сервер |
| llama3.2:8b | ~5 GB | 8 GB | Общие задачи |
| mistral:7b | ~4 GB | 8 GB | Код, инструкции |
| gemma2:9b | ~6 GB | 10 GB | Хорошее качество |
| qwen2.5-coder:7b | ~5 GB | 8 GB | Код, DevOps-скрипты |
| deepseek-r1:7b | ~5 GB | 8 GB | Аналитика, рассуждения |

Как проверить ресурсы сервера:
```bash
free -h           # RAM
df -h             # диск
nproc             # CPU
cat /proc/cpuinfo | grep "model name" | head -1
```

Правило выбора:
```
RAM 4 GB  → 3b модели, не больше
RAM 8 GB  → 7-8b модели, комфортно
RAM 16 GB → 13b модели
GPU VRAM  → смотреть отдельно
```

**Практика:** выбрать модель для своего сервера и запустить.

### Глава 3: Ollama API — модель как сервис

**Цель:** читатель понимает что Ollama — это HTTP API и умеет с ним работать через curl.

- Ollama запускает HTTP сервер на `localhost:11434`
- API совместим с OpenAI API (важно для интеграций)

Основные эндпоинты:

```bash
# Список моделей
curl http://localhost:11434/api/tags

# Генерация ответа (streaming)
curl -X POST http://localhost:11434/api/generate \
  -H "Content-Type: application/json" \
  -d '{
    "model": "llama3.2:3b",
    "prompt": "Что такое Docker?",
    "stream": false
  }'

# Chat (с историей)
curl -X POST http://localhost:11434/api/chat \
  -H "Content-Type: application/json" \
  -d '{
    "model": "llama3.2:3b",
    "messages": [
      {"role": "user", "content": "Объясни что такое systemd"}
    ],
    "stream": false
  }'
```

Разобрать ответ JSON:
```json
{
  "model": "llama3.2:3b",
  "response": "...",
  "done": true,
  "total_duration": 12345678,
  "eval_count": 150
}
```

OpenAI-совместимый эндпоинт (для программ которые ожидают OpenAI формат):
```bash
curl http://localhost:11434/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "llama3.2:3b",
    "messages": [{"role": "user", "content": "Hello"}]
  }'
```

**Практика:** написать bash-скрипт который задаёт вопрос модели и выводит ответ.

### Глава 4: Open-WebUI — браузерный интерфейс

**Цель:** читатель поднимает веб-интерфейс для работы с моделями через браузер.

- Что такое Open-WebUI: веб-интерфейс к Ollama (и другим LLM)

```bash
# docker-compose.yml
services:
  open-webui:
    image: ghcr.io/open-webui/open-webui:main
    container_name: open-webui
    volumes:
      - open-webui:/app/backend/data
    ports:
      - "127.0.0.1:3000:8080"
    environment:
      - OLLAMA_BASE_URL=http://ollama:11434
    depends_on:
      - ollama
    restart: unless-stopped

  ollama:
    image: ollama/ollama
    container_name: ollama
    volumes:
      - ollama:/root/.ollama
    ports:
      - "127.0.0.1:11434:11434"
    restart: unless-stopped

volumes:
  open-webui:
  ollama:
```

Запуск и проверка:
```bash
docker compose up -d
docker compose ps
curl -f http://localhost:3000
```

Настройка в UI:
- Подключить Ollama
- Скачать модель через UI
- Первый чат

**Практика:** поднять стек, скачать модель через интерфейс, провести тестовый диалог.

### Глава 5: Nginx перед Open-WebUI

**Цель:** читатель открывает доступ к своему AI через красивый URL с HTTPS.

Это применение знаний из книги 02 (Nginx) к новому сервису.

```nginx
server {
    listen 80;
    server_name ai.myserver.local;
    return 301 https://$server_name$request_uri;
}

server {
    listen 443 ssl;
    server_name ai.myserver.local;

    ssl_certificate /etc/ssl/certs/myserver.crt;
    ssl_certificate_key /etc/ssl/private/myserver.key;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;

        # WebSocket нужен для streaming ответов
        proxy_read_timeout 300s;
        proxy_send_timeout 300s;
    }
}
```

Обязательно объяснить:
- Почему нужен `proxy_read_timeout 300s`: модель отвечает медленнее чем обычный сервис
- Почему нужен WebSocket (`Upgrade`): для streaming ответов в реальном времени
- Как не открывать Ollama API публично напрямую

**Безопасность:** Open-WebUI должен требовать аутентификацию. Настроить первого пользователя-администратора.

### Глава 6: Python и bash скрипты с Ollama API

**Цель:** читатель умеет вызывать модель из своих скриптов.

**Bash + curl:**
```bash
#!/bin/bash
# ask-ollama.sh — простой способ спросить модель
MODEL="${1:-llama3.2:3b}"
PROMPT="${2:-Привет}"

curl -sf -X POST http://localhost:11434/api/generate \
  -H "Content-Type: application/json" \
  -d "{\"model\": \"$MODEL\", \"prompt\": \"$PROMPT\", \"stream\": false}" \
  | python3 -c "import sys,json; print(json.load(sys.stdin)['response'])"
```

**Python:**
```python
import requests

def ask_ollama(prompt: str, model: str = "llama3.2:3b") -> str:
    response = requests.post(
        "http://localhost:11434/api/generate",
        json={"model": model, "prompt": prompt, "stream": False}
    )
    response.raise_for_status()
    return response.json()["response"]

# Пример использования
answer = ask_ollama("Объясни разницу между TCP и UDP в двух предложениях")
print(answer)
```

Практические сценарии:
- Скрипт который анализирует лог файл и объясняет ошибки
- Скрипт который генерирует commit message по `git diff`
- Скрипт который проверяет конфиг файл и находит проблемы

### Глава 7: GPU vs CPU — когда и что нужно

**Цель:** читатель понимает разницу, не преувеличивает сложность.

Объяснить честно:
- CPU: медленнее, но работает на любом сервере, хватает для 7b моделей
- GPU: быстрее в 10–50 раз, нужна VRAM, NVIDIA лучше поддержана
- Для большинства задач автоматизации CPU достаточно

Скорость ответа в реальных цифрах:
```
CPU (4 ядра, 8 GB RAM):
  7b модель: ~5-15 токен/сек
  Простой вопрос: 10-30 сек

GPU (NVIDIA RTX 3080, 10GB VRAM):
  7b модель: ~50-100 токен/сек
  Простой вопрос: 1-3 сек
```

Когда GPU оправдан:
- Интерактивный чат с маленькой задержкой
- Много параллельных запросов
- Модели 30b+

Когда CPU достаточно:
- Автоматизация (скрипты не торопятся)
- Редкие запросы
- Маленький сервер или VPS

**Ollama + GPU:**
```bash
# Если есть NVIDIA GPU, Ollama использует его автоматически
nvidia-smi  # проверить GPU
docker run --gpus all -d ...  # для Docker версии
```

### Глава 8: Безопасность — не светить AI в интернет

**Цель:** читатель понимает что неправильно настроенный Ollama — это дыра.

Проблемы по умолчанию:
```bash
# Опасно: Ollama слушает на 0.0.0.0
curl http://ВАШ_ПУБЛИЧНЫЙ_IP:11434/api/tags
# Если открыт — любой может скачать модель, делать запросы
```

Правильная настройка:

```bash
# Ollama слушает только localhost
# В systemd service override:
Environment="OLLAMA_HOST=127.0.0.1:11434"

# Или в docker-compose:
ports:
  - "127.0.0.1:11434:11434"  # только localhost
  # НЕ:
  # - "11434:11434"           # 0.0.0.0 — опасно
```

Open-WebUI:
- Всегда требует регистрации/логина
- Первый пользователь становится администратором — сделать это сразу
- Не открывать без HTTPS

Firewall:
```bash
# ufw: закрыть прямой доступ к Ollama и WebUI
sudo ufw deny 11434
sudo ufw deny 3000
# Доступ только через Nginx (443)
```

### Глава 9: Когда локальная модель, а когда облачная

**Цель:** честная картина, без фанатизма в обе стороны.

Локальная лучше когда:
- Приватные данные (логи сервера, внутренние документы)
- Нужна автономность (нет интернета или не хочешь зависеть)
- Много однотипных запросов (дешевле)
- Задержка не критична (скрипты, автоматизация)

Облачная лучше когда:
- Нужно лучшее качество (GPT-4o, Claude)
- Мало RAM/CPU на сервере
- Интерактивный чат с быстрым ответом
- Сложные задачи рассуждения

Паттерн: использовать оба
```
Задача с приватными данными → локальная модель
Задача где нужно лучшее качество → облачная API
Тест/прототип → локальная
Продакшн → зависит от задачи
```

## Особые требования

### Про ресурсы
В начале каждой практики указывай минимальные требования:
```
Минимум для этой главы:
  RAM: 8 GB
  Диск: 10 GB свободно
  CPU: 4 ядра
```

### Про скорость
Предупреждай честно: на слабом сервере первый запрос может занять 30–60 секунд. Это нормально, не ошибка.

### Про модели
Не называй конкретную модель «лучшей» — ситуация меняется быстро. Давай принципы выбора, а не жёсткие рекомендации.

### Не делать
- Не углубляться в обучение (fine-tuning) — это отдельная тема
- Не описывать все возможные параметры API — только нужные
- Не сравнивать все существующие модели — только семейства
- Не пугать сложностью GPU-настройки без необходимости
