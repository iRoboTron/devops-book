# Глоссарий

> Термины и выражения книги «Экосистема Podman». В скобках — главы, где термин вводится или активно используется.

---

**Podman** — контейнерный движок от Red Hat: запускает OCI-контейнеры без демона и по умолчанию в rootless-режиме, совместим с командами Docker. _(главы 0, 3, 4)_

**Docker** — первый массовый контейнерный инструмент: формат образа, рантайм, демон, реестр и сборщик в одной программе; в книге служит точкой отсчёта для сравнения. _(главы 0, 4)_

**OCI (Open Container Initiative)** — организация под Linux Foundation и набор её спецификаций, стандартизирующих контейнеры независимо от инструмента. _(главы 0, 1)_

**OCI Image Spec** — спецификация формата образа: слои, манифест, конфигурация, layout на диске. _(глава 1)_

**OCI Runtime Spec** — спецификация запуска контейнера: namespaces, cgroups, жизненный цикл; её эталонная реализация — `runc`. _(главы 1, 2)_

**OCI Distribution Spec** — спецификация HTTP API реестров: позволяет push/pull между любыми совместимыми реестрами одной командой. _(глава 1)_

**OCI-образ** — образ, собранный по Image Spec; запускается в Docker, Podman и containerd без конвертации (Docker-образ = OCI-образ с 2017 года). _(главы 0, 1)_

**Слой (layer)** — `tar.gz`-архив с изменениями файловой системы; слои накладываются друг на друга через union filesystem (overlay). _(глава 1)_

**Манифест (manifest)** — JSON, описывающий образ: список слоёв, ссылка на конфигурацию (config.json с CMD/ENV/ENTRYPOINT), медиатипы и платформа. _(глава 1)_

**Digest** — SHA256-хеш содержимого объекта; адресация по содержимому, неизменная — в отличие от тега (человекочитаемой ссылки на digest вроде `nginx:latest`, которая может переехать на новый digest). _(глава 1)_

**runc** — низкоуровневый рантайм, эталонная реализация Runtime Spec; общий для Docker, Podman и containerd. _(главы 0, 1, 2)_

**crun** — альтернативный низкоуровневый рантайм на C, совместимый с Runtime Spec; быстрее и легче runc (есть и аналог на Rust — youki). _(глава 1)_

**containerd** — высокоуровневый рантайм с поддержкой CRI; используется большинством managed-Kubernetes (GKE, EKS, AKS). _(глава 2)_

**CRI-O** — минимальный CRI-рантайм от Red Hat специально для Kubernetes; основа OpenShift. _(глава 2)_

**CRI (Container Runtime Interface)** — gRPC API между kubelet (агентом K8s на ноде) и рантаймом; включает RuntimeService и ImageService. _(глава 2)_

**dockershim** — устаревший адаптер внутри Kubernetes, переводивший CRI-запросы в Docker API; удалён в K8s 1.24. _(главы 0, 2)_

**ctr / crictl** — низкоуровневые CLI для диагностики на ноде: `ctr` работает с containerd напрямую, `crictl` — с любым CRI-рантаймом, когда `kubectl` недоступен. _(глава 2)_

**Демон (daemon)** — постоянно запущенный фоновый процесс; у Docker это `dockerd` под root, единая точка отказа и риска. _(главы 0, 4)_

**Daemonless (бездемонный)** — архитектура Podman без постоянного фонового процесса: каждый контейнер запускается отдельно, поэтому нет SPOF (единой точки отказа), как `dockerd` в Docker. _(главы 0, 4)_

**Fork-exec модель** — способ запуска контейнеров в Podman: `podman run` порождает монитор и завершается, без долгоживущего демона. _(глава 4)_

**conmon** — лёгкий монитор контейнера (один на контейнер): держит процесс живым после завершения `podman run`, собирает логи. _(глава 4)_

**Docker-in-Docker (DinD)** — запуск Docker внутри контейнера через монтирование socket или `--privileged`; распространённый риск безопасности в CI. _(главы 0, 12)_

**Docker socket** — `/var/run/docker.sock`, прямой доступ к демону; его монтирование равно выдаче root на хосте. _(главы 0, 4)_

**Docker-совместимый сокет** — Podman-сокет (`/run/user/UID/podman/podman.sock`) с эмуляцией Docker API для инструментов вроде Portainer и Testcontainers; на него направляют переменной `DOCKER_HOST`. _(главы 4, 12)_

**Rootless (запуск без root)** — режим Podman по умолчанию: контейнеры работают от обычного пользователя без привилегий root на хосте (противоположность — rootful через `sudo podman`). _(главы 0, 3, 5)_

**User namespace** — механизм ядра Linux (с 3.8), позволяющий иметь собственный UID 0 внутри namespace, отображённый на непривилегированного пользователя снаружи. _(главы 3, 5)_

**UID mapping (маппинг UID)** — отображение идентификаторов внутри контейнера на диапазон UID хоста через subuid/subgid. _(главы 3, 5)_

**/etc/subuid и /etc/subgid** — файлы, задающие диапазон UID/GID, зарезервированный для маппинга каждого пользователя (формат `имя:начало:количество`). _(главы 3, 5)_

**newuidmap / newgidmap** — setuid-утилиты пакета `uidmap`, настраивающие маппинги UID/GID от имени непривилегированного пользователя; маппинг можно проверить через `podman unshare`. _(главы 3, 5)_

**--userns=keep-id** — опция, маппирующая UID текущего пользователя как тот же UID внутри контейнера; решает проблему прав на тома. _(глава 5)_

**SELinux метка :z / :Z** — суффикс монтирования тома, перемаркирующий SELinux-контекст: `:z` для общего тома, `:Z` для приватного. _(главы 5, 6)_

**Pod** — нативная группа контейнеров Podman (и Kubernetes), разделяющих сетевое пространство (один IP, localhost) и опционально PID namespace; network namespace удерживает служебный инфра-контейнер. _(главы 6, 7)_

**podman-compose** — Python-утилита (отдельный проект от Podman), читающая стандартный `docker-compose.yml` и запускающая стек через Podman без изменений файла. _(глава 6)_

**slirp4netns / pasta** — userspace-реализации сети для rootless Podman: безопасны, но медленнее bridge и без broadcast/multicast (`pasta` в Podman 5+ — замена `slirp4netns`). _(главы 4, 6)_

**netavark** — сетевой бэкенд Podman 4.0+, пришедший на смену CNI; управляет сетями и DNS контейнеров. _(главы 4, 13)_

**fuse-overlayfs** — реализация overlay через FUSE для rootless, когда ядро не даёт обычный overlay непривилегированному пользователю. _(глава 5)_

**podman kube generate** — экспорт Pod или контейнера в K8s YAML (всегда `kind: Pod`, требует адаптации в Deployment). _(глава 7)_

**podman kube play** — локальный «K8s-симулятор»: запускает K8s YAML без кластера для тестирования конфигурации. _(глава 7)_

**kind: Pod vs kind: Deployment** — Pod подходит для локального теста, Deployment нужен для продакшна (репликация, rolling update, восстановление). _(главы 7, приложение D)_

**Реестр (registry)** — хранилище образов; кроме Docker Hub — Quay.io, GHCR, ECR, GCR/Artifact Registry, ACR, registry.k8s.io, Harbor. _(глава 8)_

**Rate limit Docker Hub** — ограничение pull-запросов (100 анонимно / 200 для залогиненных за 6 часов); проблема для CI. Учётные данные после `podman login` хранятся в `~/.config/containers/auth.json` (base64-кодирование, не шифрование). _(глава 8)_

**registry:2 (Docker Distribution)** — лёгкий self-hosted реестр, поднимаемый одним `podman run` для разработки и зеркал. _(глава 8)_

**Harbor** — корпоративный self-hosted реестр с RBAC, сканированием уязвимостей, репликацией и подписью образов. _(глава 8)_

**skopeo** — инструмент работы с образами на уровне реестров: inspect, copy реестр→реестр, sync для air-gap — без скачивания и запуска. _(главы 1, 8)_

**buildah** — инструмент сборки OCI-образов без демона; `podman build` использует его под капотом (через `buildah bud` — Build Using Dockerfile), но buildah можно вызывать напрямую. _(главы 1, 10)_

**buildah from / run / copy / config / commit** — низкоуровневые шаги сборки без Dockerfile: создать рабочий контейнер, выполнить команды, скопировать файлы, задать метаданные, зафиксировать образ. _(глава 10)_

**BUILDAH_ISOLATION=chroot** — режим изоляции buildah без вложенных user namespaces; вместе с `STORAGE_DRIVER=vfs` (драйвер без kernel-overlay) позволяет собирать образы в CI-контейнере без `--privileged`. _(главы 10, 12)_

**systemd** — система инициализации и менеджер сервисов Linux; управляет автозапуском, перезапуском и логами контейнеров Podman. _(глава 9)_

**podman generate systemd** — классический (устаревающий, deprecated в Podman 5.x) способ создать systemd unit из запущенного контейнера. _(глава 9)_

**Quadlet** — декларативный генератор systemd unit-файлов из конфигов `.container`, `.pod`, `.volume`, `.network`, `.image`, `.kube` (Podman 4.4+). _(глава 9)_

**.container файл** — декларативное описание контейнера для Quadlet с секциями `[Unit]`, `[Container]`, `[Service]`, `[Install]`. _(глава 9)_

**daemon-reload** — `systemctl --user daemon-reload`; обязателен после правки `.container`, иначе Quadlet не перечитает конфиг. _(главы 9, 13)_

**loginctl enable-linger** — включение linger: пользовательские systemd-сервисы работают без активного сеанса и стартуют при загрузке. _(глава 9)_

**AutoUpdate=registry** — параметр Quadlet для автообновления: Podman сравнивает digest в реестре с локальным и перезапускает сервис при изменении; запускается по `podman-auto-update.timer`. _(глава 9)_

**Testcontainers** — библиотека интеграционных тестов, поднимающая зависимости в контейнерах; с Podman работает через `DOCKER_HOST` и отключённый Ryuk (cleanup-демон, не работающий в rootless — `TESTCONTAINERS_RYUK_DISABLED=true`). _(главы 4, 12)_

**registries.conf / unqualified-search-registries** — конфиг списка реестров и их параметров (insecure, поиск по короткому имени); без `unqualified-search-registries` команда `podman pull nginx` не резолвится. _(главы 3, 6, 8, 13)_

**graphRoot** — корневая директория хранилища образов (задаётся в `storage.conf`); в rootless по умолчанию `~/.local/share/containers/storage`. После обновления Podman или правки subuid/subgid хранилище приводит в порядок `podman system migrate`. _(главы 3, 4, 13)_

**Привилегированные порты (< 1024)** — порты, которые непривилегированный процесс не может слушать в rootless; обход через 8080+, sysctl или CAP_NET_BIND_SERVICE. _(главы 4, 5)_

**cgroups v2** — версия механизма ограничения ресурсов ядра, полноценно поддерживаемая rootless Podman (cgroups v1 на старых системах даёт ограничения). _(главы 5, 13)_

**Container escape** — выход процесса за пределы контейнера на хост; в rootless ущерб ограничен правами одного непривилегированного пользователя, а не root. _(глава 5)_

**Podman Machine** — виртуальная машина для запуска Podman на Windows и macOS (ядро Linux нужно даже rootless-контейнерам). _(главы 0, 11, приложение E)_
