## Главная идея

Hardening — это не список магических команд. Это систематическое уменьшение поверхности атаки.

```
Без системы:               С системой:
«команды из туториала»     1. Что защищаем
→ непонятно зачем          2. От кого
→ непонятно что осталось   3. Что уже защищено
→ непонятно что сломалось  4. Что добавить
                           5. Как проверить
```

**Ключевое понимание:**
- Идеально защищённый сервер — это выключенный сервер. Цель — разумный баланс.
- Лучший hardening — убрать лишнее, а не добавить больше ограничений.
- Изменение без проверки = надежда, а не безопасность.
- lynis покажет что проверить. Понять почему — задача этой книги.

### Глава 0: Threat model — от чего мы защищаемся

**Цель:** читатель думает системно, а не применяет команды вслепую.

Объяснить:
- Что такое threat model простыми словами: кто атакует, как, что хочет
- Три реальных сценария для домашнего/VPS сервера:
  ```
  1. Автоматические боты (masscan, shodan-сканеры)
     Что делают: сканируют все IP, пробуют дефолтные пароли, известные CVE
     Как часто: постоянно, 24/7
     Защита: закрыть ненужные порты, обновления, fail2ban

  2. Целенаправленная атака на сервис
     Что делают: ищут уязвимости в конкретном ПО (Nextcloud, Nginx)
     Как часто: редко, если ты не цель
     Защита: обновления, минимальная поверхность

  3. Утечка учётных данных
     Что делают: пробуют SSH с украденными паролями
     Как часто: постоянно после любой утечки
     Защита: ключи вместо паролей, fail2ban
  ```
- Что НЕ входит в модель угроз для домашнего сервера (не быть параноиком)
- Понятие «поверхность атаки»: каждый открытый порт, каждый запущенный сервис — это вход

**Практика:** описать свою threat model: что стоит на сервере, что открыто наружу, что будет если сервер взломают.

### Глава 1: SSH hardening

**Цель:** SSH настроен правильно — главный вход защищён.

SSH — самый важный вектор. Рассмотреть каждый параметр:

```bash
# /etc/ssh/sshd_config — разбираем построчно

# Отключить вход по паролю (только ключи)
PasswordAuthentication no
# Почему: пароли перебирают боты. Ключи не перебираются.

# Отключить root login
PermitRootLogin no
# Почему: если взломали пользователя — нет прямого root

# Разрешить только конкретных пользователей
AllowUsers yourusername
# Почему: даже если создан лишний пользователь — не зайдут

# Изменить порт (неоднозначный совет — объяснить tradeoffs)
Port 22
# Изменение на нестандартный порт снижает шум в логах,
# но не является реальной защитой

# Таймаут неактивных соединений
ClientAliveInterval 300
ClientAliveCountMax 2
# Почему: зависшие сессии освобождаются

# Отключить X11 и agent forwarding если не нужны
X11Forwarding no
AllowAgentForwarding no

# Только современные алгоритмы (для Ubuntu 22+)
# Дефолты уже хорошие, явно указывать не нужно
```

Порядок безопасного применения:
```bash
# 1. Проверить синтаксис ДО перезапуска
sudo sshd -t

# 2. Открыть второй SSH сеанс — не закрывать первый
# (страховка если что-то пошло не так)

# 3. Перезапустить
sudo systemctl restart sshd

# 4. В новом окне проверить вход
ssh user@server

# 5. Только потом закрывать первый сеанс
```

### Глава 2: Пользователи и права — принцип минимальных привилегий

**Цель:** только нужные пользователи с нужными правами.

Проверить текущее состояние:
```bash
# Пользователи с uid < 1000 (системные) и > 1000 (реальные)
awk -F: '$3 >= 1000 && $1 != "nobody" {print $1, $3}' /etc/passwd

# Пользователи в группе sudo
getent group sudo

# Последние логины
last -n 20

# Неудачные попытки входа
lastb -n 20
```

Правила:
- Один пользователь для работы — не работать под root
- sudo вместо su — каждая команда аудируется
- Сервисные пользователи без shell:
  ```bash
  # Проверить у каких системных пользователей есть shell
  awk -F: '$3 >= 100 && $3 < 1000 && $7 != "/usr/sbin/nologin" && $7 != "/bin/false" {print $1, $7}' /etc/passwd
  ```

### Глава 3: Firewall — ufw глубоко

**Цель:** понять и настроить ufw правильно, не просто «открыть 80 и 443».

Аудит текущих правил:
```bash
sudo ufw status verbose
sudo ufw status numbered

# Что реально слушает на всех интерфейсах
sudo ss -tlnp
sudo ss -ulnp
```

Принцип: default deny:
```bash
# Сначала закрыть всё
sudo ufw default deny incoming
sudo ufw default allow outgoing

# Потом открыть только нужное
sudo ufw allow 22/tcp     # SSH
sudo ufw allow 80/tcp     # HTTP
sudo ufw allow 443/tcp    # HTTPS
sudo ufw allow 51820/udp  # WireGuard (если есть)
```

Rate limiting для SSH:
```bash
# Вместо просто allow — с ограничением частоты
sudo ufw limit 22/tcp
# Блокирует IP после 6 неудачных попыток за 30 сек
```

Ограничить доступ к сервисам по IP (для внутренних сервисов):
```bash
# Например Grafana — только с VPN IP
sudo ufw allow from 10.0.0.0/24 to any port 3000
sudo ufw deny 3000
```

### Глава 4: Системные параметры — sysctl

**Цель:** читатель понимает зачем нужен sysctl и применяет разумный набор параметров.

Объяснить что такое sysctl: настройки ядра Linux во время работы.

```bash
# Посмотреть текущие значения
sysctl -a | grep -E "forward|syncook|redirect"
```

Создать файл `/etc/sysctl.d/99-hardening.conf`:

```ini
# Защита от IP spoofing
net.ipv4.conf.default.rp_filter = 1
net.ipv4.conf.all.rp_filter = 1

# Защита от SYN flood
net.ipv4.tcp_syncookies = 1

# Не принимать ICMP redirects (защита от man-in-the-middle)
net.ipv4.conf.all.accept_redirects = 0
net.ipv6.conf.all.accept_redirects = 0
net.ipv4.conf.all.send_redirects = 0

# Не принимать source routing
net.ipv4.conf.all.accept_source_route = 0

# Логировать подозрительные пакеты
net.ipv4.conf.all.log_martians = 1

# ASLR — рандомизация адресного пространства
kernel.randomize_va_space = 2
```

Применить и проверить:
```bash
sudo sysctl -p /etc/sysctl.d/99-hardening.conf
sudo sysctl net.ipv4.tcp_syncookies  # проверить конкретный параметр
```

Для каждого параметра — объяснение простыми словами. Не просто скопировать список.

### Глава 5: Обновления — автоматически и правильно

**Цель:** сервер получает патчи безопасности без ручного труда.

```bash
# Включить unattended-upgrades
sudo apt install unattended-upgrades
sudo dpkg-reconfigure -plow unattended-upgrades
```

Настроить `/etc/apt/apt.conf.d/50unattended-upgrades`:
```
// Только security обновления автоматически
Unattended-Upgrade::Allowed-Origins {
    "${distro_id}:${distro_codename}-security";
};

// Удалять лишние пакеты
Unattended-Upgrade::Remove-Unused-Dependencies "true";

// Перезагружать только если нужно (для патчей ядра)
Unattended-Upgrade::Automatic-Reboot "false";
// Если хочешь авторебут ночью:
// Unattended-Upgrade::Automatic-Reboot "true";
// Unattended-Upgrade::Automatic-Reboot-Time "03:00";
```

Проверить что работает:
```bash
# Тестовый запуск
sudo unattended-upgrade --dry-run -v

# Посмотреть логи
cat /var/log/unattended-upgrades/unattended-upgrades.log
```

### Глава 6: Логи и аудит

**Цель:** читатель знает куда смотреть и что искать.

Основные места:
```bash
# Попытки входа по SSH
journalctl -u ssh --since "1 hour ago"
grep "Failed password\|Invalid user" /var/log/auth.log | tail -20

# Успешные входы
grep "Accepted" /var/log/auth.log | tail -10

# Что слушает прямо сейчас
ss -tlnp

# Какие процессы открыли сетевые соединения
ss -tp

# Кто сейчас подключён
who
w
```

fail2ban — быстрая настройка:
```bash
sudo apt install fail2ban

# /etc/fail2ban/jail.local
[sshd]
enabled = true
port = 22
maxretry = 5
bantime = 3600
findtime = 600
```

Проверить:
```bash
sudo fail2ban-client status sshd
sudo fail2ban-client banned
```

### Глава 7: lynis — автоматический аудит

**Цель:** читатель умеет запускать lynis и понимать его вывод.

```bash
# Установка
sudo apt install lynis

# Запуск аудита системы
sudo lynis audit system
```

Разобрать структуру отчёта:
```
[+] Boot and services   ← что запускается при старте
[+] Kernel              ← параметры ядра
[+] Users, Groups       ← пользователи и группы
[+] Authentication      ← SSH, PAM
...

Hardening index : 65 [##############      ]
                  ↑
                  Твой текущий счёт (выше = лучше)
```

Типичные предупреждения и что с ними делать:
- `BOOT-5122` — bootloader не защищён паролем (для домашнего сервера обычно не нужно)
- `SSH-7408` — параметры SSH можно улучшить
- `PKGS-7370` — устаревшие пакеты
- `FIRE-4512` — firewall не настроен

Сохранить отчёт:
```bash
sudo lynis audit system --report-file /tmp/lynis-report.dat
```

**Важно:** lynis показывает возможности, не обязательства. Для домашнего сервера score 65–75 — нормально. 90+ — если сервер в продакшне с реальными пользователями.

### Глава 8: Docker hardening

**Цель:** контейнеры не добавляют новых векторов атаки.

Типичные проблемы с Docker по умолчанию:
```bash
# Проверить: контейнеры запущены как root?
docker inspect <container> | grep -A5 "User"

# Docker добавляет свои правила iptables — ufw их не видит
sudo iptables -t nat -L -n | grep DOCKER
```

Основные правила:

```yaml
# docker-compose.yml — безопасная конфигурация
services:
  myapp:
    image: myapp:latest
    # Запускать не под root
    user: "1000:1000"
    # Только нужные capabilities
    cap_drop:
      - ALL
    cap_add:
      - NET_BIND_SERVICE  # если нужен порт < 1024
    # Только чтение корневой файловой системы
    read_only: true
    # Только localhost
    ports:
      - "127.0.0.1:8080:8080"
    # Не добавлять новые привилегии
    security_opt:
      - no-new-privileges:true
```

Проверить образы на уязвимости через trivy (подробнее в книге 26):
```bash
docker run --rm aquasec/trivy image myapp:latest
```

## Обязательные сравнения

1. SSH ключи vs пароли — почему ключи лучше математически (кратко)
2. ufw vs iptables напрямую — когда ufw достаточно
3. fail2ban vs другие решения — почему fail2ban для VPS достаточно
4. lynis score 65 vs 90 — что реально нужно для домашнего сервера

## Особые требования

### Про «не сломать сервер»
Перед каждым изменением которое может заблокировать SSH — напоминать открыть второй сеанс. Это критично.

### Про прогрессивный подход
Не применять всё сразу. Порядок: SSH → firewall → fail2ban → sysctl → обновления → lynis.

### Не делать
- Не рекомендовать SELinux/AppArmor глубоко — это отдельная тема
- Не уходить в kernel hardening (grsecurity) — слишком сложно
- Не пугать: цель книги — понимание, не паранойя
