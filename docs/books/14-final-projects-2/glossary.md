# Глоссарий

> Термины и выражения итоговых проектов Модуля 2. В скобках — где встречается.

---

**Terraform** — инструмент Infrastructure as Code: описывает облачные ресурсы (VM, сети, диски) в коде и создаёт их командой `terraform apply`. _(проект 1)_

**Ansible** — инструмент управления конфигурацией: настраивает уже созданный сервер через плейбуки (`ansible-playbook setup-server.yml`). _(проект 1)_

**Playbook** — в Ansible YAML-файл с описанием шагов настройки; в книге также обозначает пошаговый план выполнения проекта. _(проект 1)_

**Infrastructure as Code (IaC)** — подход, при котором инфраструктура описана в версионируемом коде, а не настраивается вручную. _(проект 1)_

**Kubernetes (K8s)** — оркестратор контейнеров: запускает, масштабирует и перезапускает Pod'ы в кластере. _(проект 1)_

**kubectl** — CLI-утилита для управления кластером Kubernetes. _(проект 1)_

**Helm** — пакетный менеджер для Kubernetes; устанавливает приложения как чарты (`helm install`). _(проект 1)_

**Helm chart** — пакет с шаблонами Kubernetes-манифестов и значениями (`values.yaml`). _(проект 2)_

**Pod** — минимальная единица запуска в Kubernetes: один или несколько контейнеров с общей сетью. _(проект 1)_

**Deployment** — объект Kubernetes, поддерживающий заданное число реплик Pod'ов и выполняющий rolling update. _(проект 1)_

**StatefulSet** — контроллер Kubernetes для приложений с состоянием (PostgreSQL, Redis): стабильные имена Pod'ов и привязка к PVC. _(проект 1)_

**PVC (PersistentVolumeClaim)** — запрос на постоянный том хранения; переживает перезапуск Pod'а. _(проект 1)_

**Service** — стабильная внутренняя точка доступа к набору Pod'ов в кластере. _(проект 1)_

**Ingress** — точка входа HTTP/HTTPS-трафика из интернета в кластер с маршрутизацией по путям и хостам. _(проект 1)_

**ConfigMap** — объект Kubernetes для хранения неконфиденциальной конфигурации. _(проект 1)_

**Secret** — объект Kubernetes для хранения чувствительных данных (пароли, токены). _(проект 1)_

**HPA (Horizontal Pod Autoscaler)** — автомасштабирование числа реплик по нагрузке (например, 2-8). _(проект 1)_

**Liveness probe** — проверка живости контейнера; при провале Kubernetes перезапускает Pod. _(проект 1)_

**Readiness probe** — проверка готовности; пока не пройдена, Service не направляет трафик на Pod. _(проект 1)_

**ResourceQuota** — лимит на суммарные ресурсы (CPU, память, число Pod'ов) в namespace. _(проект 4)_

**LimitRange** — дефолтные requests/limits для контейнеров в namespace. _(проект 4)_

**Resource limits / requests** — заявленные (requests) и предельные (limits) ресурсы контейнера. _(проект 1)_

**NetworkPolicy** — правило сетевой изоляции Pod'ов: разрешает трафик только между указанными компонентами. _(проект 1)_

**PodSecurity (restricted)** — встроенный стандарт безопасности Pod'ов; уровень `restricted` запрещает привилегии и root. _(проект 4)_

**ServiceAccount** — идентичность Pod'а внутри кластера для RBAC и доступа к API. _(проект 2)_

**RBAC (Role-Based Access Control)** — управление доступом в Kubernetes по ролям; например, разработчик видит только свой namespace. _(проект 4)_

**namespace** — логический раздел кластера для изоляции ресурсов (`prod`, `monitoring`, `tenant`). _(проект 1)_

**ArgoCD** — GitOps-контроллер: синхронизирует состояние кластера с Git-репозиторием. _(проект 1)_

**GitOps** — модель, где Git — единственный источник истины об инфраструктуре, а агент приводит кластер к описанному состоянию. _(проект 1)_

**ArgoCD Application** — объект ArgoCD, связывающий путь в Git-репозитории с целевым namespace кластера. _(проект 1)_

**ApplicationSet** — генератор, создающий множество ArgoCD Application по шаблону (например, по списку сервисов). _(проект 2)_

**selfHeal** — режим ArgoCD, автоматически откатывающий ручные изменения в кластере к состоянию из Git. _(проект 1)_

**prune** — режим ArgoCD, удаляющий из кластера ресурсы, которых больше нет в Git. _(проект 2)_

**sync** — операция приведения кластера к состоянию из Git (`argocd app sync`). _(проект 1)_

**rollback** — откат приложения к предыдущей ревизии (`argocd app rollback`, `kubectl rollout undo`). _(проект 3)_

**CI/CD** — непрерывная интеграция и доставка: автоматический pipeline test → build → deploy. _(проект 1)_

**GitHub Actions** — CI/CD-сервис GitHub, выполняющий пайплайны по событиям репозитория. _(проект 1)_

**GitLab CI** — CI/CD-система GitLab; пайплайны описываются в `.gitlab-ci.yml`. _(проект 4)_

**CI template** — переиспользуемый шаблон пайплайна, подключаемый через `include`. _(проект 4)_

**ghcr.io** — GitHub Container Registry, реестр Docker-образов. _(проект 1)_

**Image tag** — конкретная версия Docker-образа; деплой использует фиксированные теги, не `latest`. _(проект 1)_

**Dockerfile** — описание сборки образа; `USER nonroot` запускает контейнер без root. _(проект 1)_

**Prometheus** — система сбора метрик по pull-модели (scrape целей). _(проект 1)_

**Grafana** — система визуализации метрик и логов в дашбордах. _(проект 1)_

**Loki** — система агрегации логов, интегрированная с Grafana. _(проект 1)_

**RED-метрики** — Rate, Errors, Duration: базовый набор метрик для сервисов. _(проект 1)_

**ServiceMonitor** — объект, указывающий Prometheus, какой сервис собирать; в Platform-шаблоне включён по умолчанию. _(проект 4)_

**Alertmanager** — компонент Prometheus-стека для маршрутизации алертов (например, в Telegram). _(проект 1)_

**kube-prometheus-stack** — Helm-чарт с Prometheus, Grafana, Alertmanager и экспортёрами. _(проект 1)_

**Disaster Recovery (DR)** — восстановление сервиса после сбоя по заранее проверенным процедурам. _(проект 3)_

**RTO (Recovery Time Objective)** — целевое максимальное время восстановления после сбоя. _(проект 3)_

**RPO (Recovery Point Objective)** — целевой максимальный объём потерянных данных (выраженный во времени). _(проект 3)_

**Runbook** — пошаговая инструкция действий при инциденте. _(проект 3)_

**Velero** — инструмент бэкапа и восстановления ресурсов Kubernetes и томов. _(проект 3)_

**pg_dump** — утилита логического бэкапа PostgreSQL. _(проект 3)_

**Remote state** — Terraform-состояние, хранимое в удалённом backend, а не локально. _(проект 1)_

**CrashLoopBackOff** — статус Pod'а, который постоянно падает и перезапускается. _(проект 3)_

**ImagePullBackOff** — статус Pod'а, когда не удаётся скачать образ (например, несуществующий тег). _(проект 3)_

**Rolling update** — обновление Deployment без даунтайма: новые Pod'ы поднимаются до удаления старых. _(проект 1)_

**Graceful shutdown** — корректное завершение Pod'а без потери обрабатываемых запросов. _(проект 2)_

**Canary deploy** — выкатка новой версии на часть трафика перед полным переключением. _(проект 4)_

**Sealed Secrets** — механизм шифрования Secret'ов для безопасного хранения в Git. _(проект 4)_

**trivy** — сканер уязвимостей образов, запускаемый в CI. _(проект 4)_

**Guardrails** — ограничения платформы (квоты, политики, security), не дающие командам выйти за безопасные рамки. _(проект 4)_

**Golden path** — рекомендованный платформой шаблонный путь создания сервиса (шаблонный Helm-чарт). _(проект 4)_

**Self-service** — модель, при которой разработчик сам выводит сервис в production без участия DevOps. _(проект 4)_

**Tenant** — изолированная команда/окружение в кластере со своим namespace и квотами. _(проект 4)_

**Foundation** — базовое состояние платформы после проекта 1, от которого стартуют проекты 2-4. _(проект 1)_
