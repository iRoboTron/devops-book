# Глоссарий

> Термины и выражения книги «Docker для DevOps». В скобках — главы, где термин вводится или активно используется.

---

**Image (образ)** — неизменяемый read-only шаблон из слоёв, в котором упакованы приложение, его зависимости и настройки. Из образа создаются контейнеры. _(главы 0, 2, 3)_

**Container (контейнер)** — запущенный экземпляр образа: изолированный процесс на хосте со своей файловой системой. Из одного образа можно запустить много контейнеров. _(главы 0, 1)_

**Layer (слой)** — часть образа, соответствующая одной инструкции Dockerfile. Слои read-only и переиспользуются (делятся) между образами и контейнерами. _(главы 2, 3)_

**Copy-on-Write (CoW)** — механизм, при котором контейнер читает данные из read-only слоёв образа, а все изменения пишет в свой верхний read-write слой. _(глава 2)_

**Read-Write слой (Container Layer)** — верхний изменяемый слой контейнера, куда идёт вся запись. Исчезает при удалении контейнера (`docker rm`). _(главы 2, 4)_

**Dockerfile** — текстовый файл-рецепт с инструкциями для сборки образа. Каждая инструкция создаёт слой. _(главы 0, 3)_

**Build (сборка)** — процесс создания образа из Dockerfile командой `docker build`. Контекст сборки (обычно `.`) — это директория, содержимое которой передаётся демону и доступно инструкциям `COPY`. _(глава 3)_

**Build cache (кэш слоёв)** — механизм Docker, переиспользующий ранее собранные слои. Изменение одного слоя инвалидирует все слои ниже, поэтому порядок инструкций влияет на скорость сборки. _(глава 3)_

**Multi-stage build (многоэтапная сборка)** — Dockerfile с несколькими стадиями `FROM`, когда артефакты копируются из стадии сборки в лёгкий рантайм-образ, уменьшая итоговый размер. _(приложение C)_

**FROM** — инструкция Dockerfile, задающая базовый образ, с которого начинается сборка. _(глава 3)_

**WORKDIR** — инструкция Dockerfile, создающая рабочую директорию и переходящая в неё; влияет на все последующие команды. _(глава 3)_

**COPY** — инструкция Dockerfile, копирующая файлы из контекста сборки в образ. _(глава 3)_

**RUN** — инструкция Dockerfile, выполняющая команду во время сборки образа (один раз). _(глава 3)_

**CMD** — инструкция Dockerfile, задающая команду по умолчанию при запуске контейнера; может быть переопределена аргументами `docker run`. _(глава 3)_

**ENTRYPOINT** — инструкция Dockerfile, задающая основную команду контейнера, которая не переопределяется аргументами `docker run` (только флагом `--entrypoint`). _(глава 3)_

**ENV** — инструкция Dockerfile, устанавливающая переменную окружения внутри образа. _(глава 3)_

**EXPOSE** — инструкция Dockerfile, документирующая порт приложения; сама порт не открывает — для проброса нужен `-p`. _(глава 3)_

**.dockerignore** — файл со списком путей, которые не попадают в контекст сборки и в образ (например `.git`, `__pycache__`, `.env`). _(главы 3, приложение B)_

**Registry (реестр)** — хранилище образов, откуда их скачивают (`pull`) и куда загружают (`push`). Docker Hub — публичный реестр по умолчанию, есть и приватные (например GHCR, `ghcr.io`). _(главы 0, 2)_

**Docker Hub** — публичный реестр образов (hub.docker.com) с официальными образами `python`, `nginx`, `postgres` и др., лежащими в пространстве `library/`. _(главы 0, 2)_

**Tag (тег)** — метка версии образа в формате `имя:версия-вариант-основа` (например `python:3.12-slim`). _(глава 2)_

**latest** — тег по умолчанию, указывающий на «последнюю» версию; непредсказуем, поэтому в продакшене теги фиксируют. _(глава 2)_

**slim** — облегчённый вариант образа (например `python:3.12-slim`) — золотая середина по размеру для большинства задач. _(глава 2)_

**Alpine** — минимальный Linux-дистрибутив (~5 МБ) на musl libc; основа для очень лёгких образов, но возможны проблемы совместимости библиотек. _(главы 1, 2)_

**Image ID / Digest** — уникальный хэш образа (полный `sha256`-дайджест или короткий ID), по которому образ можно адресовать вместо тега. _(глава 2)_

**Dangling image (висячий образ)** — образ без тега (обычно промежуточный), удаляемый через `docker image prune`. _(глава 2)_

**docker pull / push** — команды скачивания образа из реестра (докачивает только недостающие слои) и загрузки образа в реестр. _(главы 0, 2)_

**docker run** — команда, которая скачивает образ (если нужно), создаёт контейнер и запускает его. _(глава 1)_

**docker exec** — команда выполнения команды (например `bash`) внутри уже работающего контейнера. _(глава 1)_

**docker ps / logs** — команды просмотра контейнеров (`-a` — включая остановленные) и их stdout/stderr (`-f` — следить в реальном времени). _(глава 1)_

**Lifecycle (жизненный цикл)** — последовательность состояний контейнера: created → running → exited/paused → removed. _(глава 1)_

**Detached / Interactive mode** — режимы запуска: `-d` (в фоне, терминал свободен) и `-it` (`-i` открытый stdin + `-t` псевдо-терминал) для работы внутри контейнера. _(глава 1)_

**`--rm`** — флаг `docker run`, удаляющий контейнер автоматически сразу после остановки. _(глава 1)_

**Port mapping (проброс портов, `-p`)** — публикация порта контейнера на порт хоста в формате `хост:контейнер` (например `-p 8080:80`). _(главы 1, 5)_

**Volume (том)** — управляемое Docker хранилище данных (`/var/lib/docker/volumes/`), переживающее удаление контейнера; рекомендуется для баз данных. _(главы 0, 4)_

**Bind mount** — монтирование конкретной директории хоста внутрь контейнера; удобно для кода в разработке и конфигов. Суффиксы `:ro` / `:rw` задают режим только-чтение или чтение-запись. _(главы 4, 8)_

**tmpfs** — хранилище данных только в оперативной памяти; исчезает при остановке контейнера, подходит для временных файлов и секретов. _(глава 4)_

**Бэкап тома** — архивирование данных volume через временный контейнер, монтирующий том на чтение и пишущий tar-архив на хост. _(глава 4)_

**Network (сеть)** — виртуальная сеть Docker, определяющая, как контейнеры видят друг друга и внешний мир. _(главы 0, 5)_

**bridge** — сеть Docker по умолчанию: контейнеры видят друг друга только по IP, без DNS по имени. _(глава 5)_

**custom bridge** — пользовательская bridge-сеть со встроенным DNS, где контейнеры обращаются друг к другу по имени; рекомендуется для multi-container приложений. _(глава 5)_

**host / none (сети)** — режим `host`: контейнер использует сеть хоста напрямую, без изоляции и проброса портов; режим `none`: без сети, только loopback (максимальная изоляция). _(глава 5)_

**Docker DNS** — встроенный в custom-сеть резолвер, превращающий имя сервиса/контейнера в его IP (например `app` → IP); имя контейнера служит сетевым hostname. _(главы 5, 8)_

**Network segmentation (сегментация сетей)** — разделение сервисов по сетям (frontend/backend), чтобы база данных не была доступна из интернета. _(главы 5, 8)_

**ufw и Docker** — нюанс: Docker управляет iptables напрямую и обходит правила ufw, поэтому проброшенный порт может быть открыт несмотря на ufw. _(глава 5)_

**Docker daemon (dockerd)** — фоновый процесс, выполняющий реальную работу: управляет образами, контейнерами, сетями и томами. Команды ему отправляет Docker CLI — клиент командной строки (`docker`). _(глава 0)_

**Container runtime (containerd + runc)** — нижний слой, непосредственно запускающий контейнеры поверх ядра Linux; соответствует стандарту OCI (Open Container Initiative). _(глава 0)_

**overlay2** — стандартный storage driver Docker, реализующий слоистую файловую систему из слоёв образа. _(глава 0)_

**Группа docker** — системная группа, членство в которой даёт root-эквивалентные права на работу с Docker без `sudo`. _(глава 0)_

**docker-compose / docker compose** — инструмент оркестрации нескольких контейнеров через один YAML-файл; `docker compose` (без дефиса) — актуальная версия v2. _(главы 0, 6)_

**docker-compose.yml** — YAML-файл, описывающий весь стек: сервисы, тома и сети. _(глава 6)_

**Service (сервис)** — описание одного контейнера в `docker-compose.yml` (его образ/сборка, переменные, сети). _(глава 6)_

**YAML** — человекочитаемый формат данных, используемый в Compose; требует отступов пробелами (не табами). _(глава 6)_

**image vs build** — в Compose сервис либо берёт готовый образ (`image:`), либо собирается из Dockerfile (`build:`). _(главы 6, приложение B)_

**depends_on** — директива Compose, задающая порядок запуска сервисов; сама по себе ждёт лишь старта контейнера, не готовности приложения. _(глава 6)_

**healthcheck** — проверка готовности сервиса (например `pg_isready`) по интервалу, таймауту, числу попыток и `start_period`. _(главы 6, 8)_

**condition: service_healthy** — условие `depends_on`, заставляющее сервис ждать, пока зависимость не станет «здоровой». _(глава 6)_

**docker compose up / down** — поднять (`up -d` в фоне) и остановить с удалением контейнеров (`down`); `down -v` также удаляет тома. _(глава 6)_

**Переменная окружения** — пара ключ=значение, передаваемая в контейнер (через `-e`, `environment:` или `env_file:`). _(главы 1, 3, 7)_

**.env** — файл с переменными и секретами рядом с `docker-compose.yml`; автоматически читается Compose и всегда добавляется в `.gitignore`. _(глава 7)_

**.env.example** — шаблон `.env` с пустыми значениями, который можно коммитить в репозиторий. _(главы 7, 9)_

**env_file** — директива Compose, передающая все переменные из указанного файла в контейнер. _(глава 7)_

**${VAR} / ${VAR:-default}** — подстановка переменной в Compose с приоритетом «хост > .env > default» и опциональным значением по умолчанию. _(глава 7)_

**docker compose config** — команда вывода итогового конфига с подставленными переменными (показывает секреты — осторожно). _(глава 7)_

**Reverse proxy (обратный прокси)** — роль Nginx: принимает запросы извне и проксирует их в app-контейнер через `proxy_pass http://app`. _(глава 8)_

**upstream** — блок Nginx, задающий адрес backend-сервиса по имени (`server app:8000;`). _(глава 8)_

**SSL termination** — расшифровка HTTPS на Nginx (порт 443) с дальнейшим проксированием по HTTP внутри Docker-сети. _(глава 8)_

**ACME challenge / Certbot** — механизм выпуска Let's Encrypt-сертификатов: Certbot проверяет домен через файлы по пути `/.well-known/acme-challenge/` на порту 80. _(глава 8)_

**restart policy** — политика перезапуска контейнера: `no`, `always`, `unless-stopped`, `on-failure`; для продакшена обычно `unless-stopped`. _(глава 8)_

**Makefile** — файл с короткими целями (`make up`, `make logs`, `make db-shell`), оборачивающими длинные команды `docker compose`; требует табов перед командами. _(глава 9, приложение B)_

**prune / docker system df** — семейство команд очистки неиспользуемых ресурсов (`container/image/volume/network prune`, `system prune -a`); `docker system df` показывает занятое Docker место. _(главы 1, 2, 4, приложение A)_
