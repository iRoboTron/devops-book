# Глоссарий

> Термины и выражения книги «Безопасность облака и контейнеров». В скобках — главы, где термин вводится или активно используется.

---

**Threat model (модель угроз)** — структурированное представление о том, какие активы есть, где их границы доверия и какие классы атак наиболее вероятны. _(глава 0)_

**Trust boundary (граница доверия)** — линия, на которой меняется уровень доверия к данным или субъекту: между интернетом и периметром, между сервисом и control plane. _(главы 0, 1)_

**Control plane** — управляющий слой инфраструктуры (IAM, Kubernetes API, cloud API), компрометация которого даёт власть над всей средой. _(главы 0, 7)_

**Поверхность атаки (attack surface)** — всё, что доступно атакующему: открытые порты, endpoints, пакеты в образе, capabilities контейнера. Цель hardening — её сократить. _(главы 0, 4)_

**Shared responsibility (модель ответственности)** — разделение зон безопасности между облачным провайдером и пользователем: провайдер отвечает за инфраструктуру, пользователь — за конфигурацию, доступ и данные. _(глава 1)_

**Cloud perimeter (облачный периметр)** — внешняя граница защиты в облаке, размазанная по слоям: security groups, публичные IP, load balancer, WAF, reverse proxy, host firewall. _(глава 1)_

**Security group** — облачный firewall уровня инстанса или подсети, разрешающий трафик по портам и CIDR. _(главы 1, 9)_

**Public / private subnet** — разделение сети на публичную зону (с выходом в интернет) и приватную (только внутренний доступ). _(глава 1)_

**Reverse proxy** — промежуточный сервер перед приложением, выполняющий маршрутизацию, TLS termination и фильтрацию запросов. _(глава 1)_

**WAF (Web Application Firewall)** — фильтр на уровне HTTP, отсеивающий вредоносные запросы к веб-приложению. _(глава 1)_

**TLS termination** — точка, где зашифрованное TLS-соединение расшифровывается (LB, proxy или приложение); важно знать, кто именно её выполняет. _(глава 1)_

**Host firewall** — firewall на самом хосте (ufw, nftables), работающий как дополнительный слой к облачным правилам. _(главы 1, 9)_

**IAM (Identity and Access Management)** — система управления идентичностями и правами доступа в облаке. _(главы 2, 9)_

**Least privilege (минимальные права)** — принцип выдачи субъекту ровно тех прав, что нужны для задачи, и не больше. _(главы 2, 7)_

**Service account** — нечеловеческая идентичность для сервиса или пода, от имени которой выполняются действия в облаке или кластере. _(главы 2, 7)_

**Long-lived static keys** — постоянные ключи доступа (например `AWS_ACCESS_KEY_ID`), которые при утечке живут неделями и не требуют интерактивного входа. _(глава 2)_

**Effective permissions** — реальные права субъекта с учётом всех allow и deny; проверяются на практике (например `iam simulate-principal-policy`). _(глава 2)_

**Audit trail (журнал аудита)** — запись о том, кто, когда и какие привилегированные действия выполнял (например CloudTrail). _(главы 2, 6)_

**Secret (секрет)** — чувствительное значение (токен, пароль, ключ, DSN), требующее отдельного жизненного цикла, ротации и контроля доступа. _(глава 3)_

**Secret manager** — выделенное хранилище секретов с контролем доступа, версионированием и ротацией. _(главы 3, 9)_

**Ротация (rotation)** — регулярная или аварийная замена секрета с обновлением во всех потребителях. _(глава 3)_

**Baked-in secret** — секрет, зашитый в image layer (через ENV или COPY) и уезжающий в registry вместе с образом. _(глава 3)_

**Image (образ)** — программный артефакт, попадающий в production; его состав определяет поверхность атаки runtime. _(главы 4, 6)_

**Base image** — исходный образ в `FROM`, на котором строится сборка; его уязвимости наследуются приложением. _(главы 4, 6)_

**Image hardening** — уменьшение поверхности атаки образа: pinned base, multi-stage, non-root, минимальный состав, `.dockerignore`. _(глава 4)_

**Multi-stage build** — сборка в несколько стадий, где build tools остаются в build stage, а в runtime попадают только артефакты. _(глава 4)_

**Non-root / rootless** — запуск контейнера от непривилегированного пользователя, чтобы побег из контейнера не давал сразу root на хосте. _(главы 4, 5)_

**`.dockerignore`** — список того, что не попадает в build context (`.git`, `.env`, тестовые данные), снижая риск утечки. _(глава 4)_

**Image scanning** — анализ образа на известные уязвимости и секреты сканером (например trivy). _(главы 4, 6, 8)_

**SBOM (Software Bill of Materials)** — перечень всех компонентов и зависимостей образа или приложения, упрощающий аудит и реакцию на уязвимости. _(главы 4, 6)_

**CVE (Common Vulnerabilities and Exposures)** — публичный идентификатор известной уязвимости (например `CVE-2024-0727`). _(главы 6, 8)_

**Severity (CRITICAL / HIGH / LOW)** — степень критичности уязвимости, определяющая приоритет исправления. _(главы 6, 8)_

**Runtime security** — защита уже запущенного контейнера: ограничение capabilities, mounts, сети и привилегий. _(глава 5)_

**Capabilities** — гранулярные Linux-привилегии; безопасная практика — `cap_drop: ALL` и добавление только нужных. _(глава 5)_

**`--privileged`** — флаг, дающий контейнеру почти хостовый уровень власти; опасен и почти никогда не нужен. _(глава 5)_

**docker.sock** — сокет Docker daemon; смонтированный в контейнер, он позволяет управлять всем Docker и хостом. _(глава 5)_

**Read-only root filesystem** — режим, при котором корневая ФС контейнера недоступна для записи, что затрудняет закрепление атакующего. _(главы 5, 7)_

**`no-new-privileges`** — опция, запрещающая процессам в контейнере повышать привилегии (например через setuid). _(глава 5)_

**seccomp** — механизм фильтрации системных вызовов ядра, ограничивающий, что контейнер может запросить у хоста. _(глава 5)_

**AppArmor** — мандатный профиль контроля доступа (MAC) в Linux, ограничивающий действия процесса. _(глава 5)_

**Registry (реестр)** — хранилище образов и точка доверия: кто пушит, какой образ идёт в production, как откатываться. _(глава 6)_

**Supply chain (цепочка поставки)** — путь артефакта от исходного кода через build, scan, sign и registry до deploy; каждое звено — потенциальный риск. _(глава 6)_

**Digest (`@sha256:...`)** — неизменяемый контентный идентификатор образа; деплой по digest гарантирует точные биты. _(глава 6)_

**Immutable tag** — тег, который запрещено перезаписывать, что делает откат и аудит предсказуемыми. _(глава 6)_

**Signing / cosign** — криптографическая подпись образа для подтверждения его происхождения и целостности; cosign — инструмент проекта Sigstore. _(глава 6)_

**Provenance** — проверяемая информация о происхождении артефакта: из какого кода, каким pipeline и когда он собран. _(глава 6)_

**RBAC (Role-Based Access Control)** — управление доступом в Kubernetes через Role/ClusterRole и их Binding к субъектам. _(глава 7)_

**Namespace** — логическая изоляция ресурсов в кластере по средам и командам. _(глава 7)_

**Pod security context** — настройки безопасности пода/контейнера: `runAsNonRoot`, `readOnlyRootFilesystem`, `drop capabilities`, `allowPrivilegeEscalation`. _(глава 7)_

**Default service account** — учётка по умолчанию, которую под наследует автоматически; её токен даёт непредсказуемый blast radius. _(глава 7)_

**NetworkPolicy** — правило, ограничивающее east-west трафик между подами, который по умолчанию открыт. _(глава 7)_

**Admission controller** — компонент Kubernetes, проверяющий или изменяющий объекты при создании (например проверка подписи образа или политики). _(главы 6, 7)_

**Controlled validation** — безопасная проверка собственного стенда по циклу `scan -> fix -> redeploy -> verify`, без атак на чужие системы. _(главы 8, 9)_

**Defensive baseline** — минимально достаточный набор настроенных защит, доказуемо снижающий поверхность атаки. _(главы 8, 9)_

**Lab-only** — правило выполнять все проверки только на своих VM, контейнерах и тестовых доменах. _(вся книга)_
