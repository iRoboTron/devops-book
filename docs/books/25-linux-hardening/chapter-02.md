# Глава 2: Пользователи и права

> **Цель:** оставить только нужных пользователей с нужными правами.

---

## 2.1 Кто есть на сервере

```bash
awk -F: '$3 >= 1000 && $1 != "nobody" {print $1, $3, $7}' /etc/passwd
```

# Пример вывода:
```
deploy 1000 /bin/bash
maria 1001 /bin/bash
```

Это реальные пользователи с UID ≥ 1000. Если видишь незнакомое имя — это повод разобраться, когда и зачем он был создан.

```bash
getent group sudo
```

# Пример вывода:
```
sudo:x:27:deploy,maria
```

Перечислены все пользователи с правами sudo. Список должен быть минимальным.

```bash
last -n 20
```

# Пример вывода:
```
deploy   pts/0        93.184.216.34    Mon May  5 14:15   still logged in
deploy   pts/1        93.184.216.34    Mon May  5 11:02 - 12:45  (01:42)
maria    pts/0        10.0.0.5         Sun May  4 22:30 - 23:10  (00:39)
reboot   system boot  6.1.0-21-amd64   Sun May  4 20:00   still running
deploy   pts/0        185.220.101.42   Sun May  4 03:11 - 03:13  (00:02)

wtmp begins Thu May  1 00:00:01 2025
```

Обращай внимание на незнакомые IP, нестандартное время и короткие сессии от неизвестных адресов. Последняя строка с `185.220.101.42` в 3 ночи — повод насторожиться.

```bash
sudo lastb -n 20
```

`lastb` может требовать root и может не работать, если файл журнала отсутствует. Это нормально: фиксируй результат.

## 2.2 Принцип минимальных привилегий

> **Аналогия:** sudo-права — это как ключ от серверной комнаты. Не каждому сотруднику нужен ключ, даже если он хороший человек и давно работает. Доступ — только тому, кому он нужен для работы.

Правила:

- не работать под root ежедневно;
- sudo только тем, кому реально нужно;
- сервисные пользователи без shell;
- удалять или блокировать старые аккаунты;
- не использовать одного пользователя на всю команду.

Проверка системных пользователей с shell:

```bash
awk -F: '$3 >= 100 && $3 < 1000 && $7 != "/usr/sbin/nologin" && $7 != "/bin/false" {print $1, $7}' /etc/passwd
```

## 2.3 Если что-то пошло не так

> **Если что-то пошло не так:**
>
> **Симптом:** Случайно удалил себя из группы sudo — команды с `sudo` выдают `is not in the sudoers file. This incident will be reported.`
>
> **Шаги исправления:**
>
> **Вариант 1 — если есть графическая сессия или pkexec:**
> ```bash
> pkexec usermod -aG sudo yourusername
> ```
> После этого перелогинься.
>
> **Вариант 2 — recovery mode (только для физических машин или VPS с KVM-консолью):**
> 1. Зайди в консоль провайдера (VNC/KVM).
> 2. Перезагрузи сервер в recovery mode (в GRUB выбери `Advanced options → recovery mode`).
> 3. Выбери `root shell`.
> 4. Выполни: `usermod -aG sudo yourusername`
> 5. Перезагрузи нормально.
>
> **Вариант 3 — если есть другой пользователь с sudo:**
> ```bash
> sudo usermod -aG sudo yourusername
> ```
