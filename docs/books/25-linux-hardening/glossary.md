# Глоссарий

> Термины и выражения книги «Linux Hardening: укрепление и аудит своего сервера». В скобках — главы, где термин вводится или активно используется.

---

**Hardening (усиление)** — процесс уменьшения поверхности атаки сервера через отключение лишнего и ужесточение настроек с проверкой после каждого изменения. _(книга целиком, главы 0, 9)_

**Поверхность атаки (attack surface)** — совокупность всех точек, через которые систему можно атаковать: открытые порты, сервисы, аккаунты, права. Цель hardening — её сузить. _(главы 0, 9)_

**Baseline (базовый уровень)** — разумный набор минимальных мер безопасности для личного сервера или небольшой команды, ниже которого опускаться нельзя. _(главы 0, 9, приложение A)_

**Threat model (модель угроз)** — карта того, что ценного есть, кто может атаковать, каким способом и какие меры разумны. Составляется до изменения настроек. _(глава 0)_

**Актив (asset)** — то ценное, что защищаем: данные, доступ к серверу, работающие сервисы. _(глава 0)_

**Брутфорс (brute force)** — автоматический перебор паролей или логинов ботами. В логах виден как множество строк `Failed password` с одного IP. _(главы 0, 6)_

**Бот / сканер** — автоматическая программа, перебирающая пароли или ищущая открытые порты и уязвимые сервисы. Основная угроза для личного VPS. _(главы 0, 3, 6)_

**Эксплуатация сервиса** — атака на уязвимость веб-приложения или API, видна в логах как запросы к `/.env`, `/wp-admin`, `/../../../etc/passwd`. _(глава 0)_

**Утечка токена** — компрометация API-ключа или SSH-ключа, после которой злоумышленник входит легитимным путём с нового IP. _(глава 0)_

**SSH hardening** — укрепление главного входа на сервер: ключи вместо паролей, запрет root-логина, ограничение пользователей. _(глава 1)_

**sshd_config** — основной файл конфигурации SSH-сервера (`/etc/ssh/sshd_config`), где задаются правила аутентификации и доступа. _(глава 1, приложение A)_

**PasswordAuthentication no** — директива sshd, отключающая вход по паролю; оставляет только аутентификацию по ключу. _(главы 1, 9)_

**PermitRootLogin no** — директива sshd, запрещающая прямой вход пользователем root по SSH. _(главы 1, 7, 9)_

**AllowUsers** — директива sshd, разрешающая SSH-вход только перечисленным пользователям. Опасна при опечатке — можно заблокировать себе доступ. _(глава 1)_

**Аутентификация по ключу (publickey)** — вход по паре приватный/публичный ключ вместо пароля; в логах `Accepted publickey`. Надёжнее пароля. _(главы 1, 6)_

**Второй SSH-сеанс** — запасное открытое подключение, которое держат во время изменений SSH/firewall, чтобы не заблокировать себе доступ. _(главы 1, 9, приложение B)_

**Консоль провайдера (VNC/KVM)** — доступ к серверу в обход SSH через панель VPS-провайдера; способ восстановления при потере доступа. _(главы 1, 2, 3)_

**sshd -t** — команда проверки синтаксиса конфига SSH до перезапуска сервиса. Пустой вывод означает отсутствие ошибок. _(глава 1, приложение A)_

**Принцип минимальных привилегий (least privilege)** — давать каждому аккаунту и процессу ровно те права, что нужны для работы, и не больше. _(главы 2, 8)_

**sudo** — механизм временного выполнения команд с правами root. Доступ должен быть только у тех, кому он реально нужен. _(глава 2)_

**sudoers / группа sudo** — список пользователей, которым разрешено повышение прав через sudo. Должен быть минимальным. _(глава 2)_

**UID (User ID)** — числовой идентификатор пользователя. UID ≥ 1000 — обычно живые люди, 100–999 — системные/сервисные аккаунты. _(главы 2, 9)_

**Сервисный пользователь** — учётная запись для запуска сервиса, у которой не должно быть интерактивного shell (`nologin` или `/bin/false`). _(глава 2)_

**recovery mode** — режим загрузки с root-shell для восстановления доступа, например при потере sudo-прав. _(глава 2)_

**Firewall (межсетевой экран)** — фильтр входящего и исходящего трафика; пропускает только явно разрешённые порты. _(глава 3, приложение A)_

**ufw (Uncomplicated Firewall)** — простой интерфейс управления firewall в Ubuntu/Debian поверх iptables. _(глава 3, приложение A)_

**Default deny (политика «запретить по умолчанию»)** — базовое правило: всё входящее запрещено, кроме явно разрешённого. _(главы 3, 9)_

**ufw limit** — правило ufw, ограничивающее частоту новых подключений к порту (например, к SSH) для защиты от перебора. _(глава 3, приложение A)_

**Открытый порт** — сетевой порт, принимающий соединения. Каждый открытый наружу порт должен иметь понятную причину. _(главы 3, 9)_

**ss -tlnp** — команда просмотра слушающих TCP-портов и процессов за ними; показывает реальную картину открытых портов. _(главы 3, 9)_

**iptables** — низкоуровневая подсистема фильтрации пакетов в ядре Linux; ufw и Docker оба пишут в неё правила. _(главы 3, 8)_

**Цепочка DOCKER / DNAT** — правила, которые Docker добавляет в iptables напрямую, публикуя порты контейнеров в обход ufw. _(главы 3, 8)_

**Привязка к 127.0.0.1 (localhost)** — публикация сервиса или Docker-порта только на локальном интерфейсе, чтобы он не был доступен снаружи. _(главы 3, 8, 9)_

**sysctl** — механизм управления параметрами ядра Linux во время работы; влияет на сеть, маршрутизацию, VPN и контейнеры. _(глава 4)_

**tcp_syncookies** — параметр ядра, защищающий от SYN-flood за счёт «куки» при переполнении очереди соединений. _(главы 4, 9)_

**accept_redirects / send_redirects** — sysctl-параметры обработки ICMP-redirect; их жёсткое отключение может сломать Docker bridge-сеть. _(глава 4)_

**ip_forward (IP forwarding)** — параметр ядра, разрешающий маршрутизацию пакетов между интерфейсами; нужен для WireGuard и Docker NAT. _(глава 4)_

**rp_filter (reverse path filter)** — проверка обратного пути пакета; применять осторожно при наличии VPN и нескольких интерфейсов. _(глава 4)_

**randomize_va_space (ASLR)** — рандомизация адресного пространства, усложняющая эксплуатацию уязвимостей памяти. _(глава 4)_

**unattended-upgrades** — пакет автоматической установки security-обновлений в Debian/Ubuntu. _(глава 5, приложение A)_

**Security update (патч безопасности)** — обновление, закрывающее известную уязвимость; важнее экзотических средств защиты. _(главы 5, 7)_

**Dry-run** — пробный запуск (например `unattended-upgrade --dry-run`), показывающий, что произойдёт, без внесения изменений. _(глава 5, приложение A)_

**Reboot policy** — политика перезагрузок после обновлений; для личного сервера часто безопаснее ручной reboot в удобное время. _(глава 5)_

**auth.log** — системный журнал событий аутентификации, где видны попытки входа по SSH (Failed/Accepted). _(главы 0, 6)_

**journalctl** — инструмент просмотра журналов systemd, включая логи службы SSH. _(главы 1, 6)_

**fail2ban** — сервис, который читает логи, замечает повторяющиеся неудачные входы и временно банит атакующий IP в firewall. _(глава 6, приложение A)_

**jail (тюрьма)** — настроенный в fail2ban набор фильтра и действия для конкретного сервиса, например `[sshd]`. _(глава 6)_

**maxretry / findtime / bantime** — параметры jail: число попыток, окно их подсчёта и срок бана IP. _(глава 6)_

**ignoreip (белый список)** — список адресов в fail2ban, которые никогда не банятся (например, свой собственный IP). _(глава 6)_

**Lynis** — инструмент аудита безопасности Linux, выдающий список предупреждений и рекомендаций, а не «магический рейтинг». _(глава 7)_

**Hardening index** — итоговый числовой показатель Lynis (0–100); для домашнего сервера значение 65–70 считается нормой. _(глава 7)_

**Warning vs Suggestion** — в выводе Lynis `!` (Warning) серьёзнее, чем `*` (Suggestion); Warnings закрывают приоритетно. _(глава 7)_

**CIS / контрол (control ID)** — идентификатор проверки безопасности (например `SSH-7412`), по которому ищут документацию и способ исправления. _(глава 7)_

**Docker hardening** — укрепление контейнеров: запуск не от root, отказ от лишних capabilities, привязка портов к localhost, read-only ФС. _(глава 8)_

**Capabilities (привилегии ядра)** — дробные права root в Linux; `cap_drop: ALL` убирает все, `cap_add` возвращает только необходимые. _(глава 8)_

**cap_drop / cap_add** — параметры Docker для удаления всех capabilities и точечного добавления нужных (например `NET_BIND_SERVICE`). _(глава 8)_

**no-new-privileges** — опция безопасности контейнера, запрещающая процессам повышать свои привилегии (например через setuid). _(глава 8)_

**read_only + tmpfs** — запрет записи в файловую систему контейнера с выделением временного хранилища в памяти (tmpfs) для нужных каталогов. _(глава 8)_

**MAC (Mandatory Access Control)** — обязательное управление доступом (SELinux, AppArmor); в этой книге упоминается как продвинутая тема за рамками базового baseline. _(глава 7)_

**SELinux / AppArmor** — системы принудительного контроля доступа в ядре Linux; для личного VPS относятся к необязательным, продвинутым мерам. _(глава 7)_

**План отката (rollback)** — заранее записанный способ вернуть систему в рабочее состояние, если изменение сломало доступ или сервис. _(главы 9, приложение B)_

**Red flag (красный флаг)** — признак, что менять настройки сейчас опасно: нет второго сеанса, нет консоли провайдера, SSH и firewall меняются одновременно. _(приложение B)_

**HARDENING-LOG.md** — документ изменений, где для каждой правки записаны команда/файл, проверка и способ отката. _(глава 9)_
