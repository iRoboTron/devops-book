# Глоссарий

> Термины и выражения книги «Защита от внешних атак: периметр и Linux hardening». В скобках — главы, где термин вводится или активно используется.

---

**Поверхность атаки (attack surface)** — всё, что доступно атакующему снаружи или через доверенный путь: открытые порты, баннеры, веб-вход, панели, уязвимые зависимости. _(главы 0, 2)_

**Threat model (модель угроз)** — структурированное представление о том, что торчит наружу, кому это интересно и какие риски реальны для конкретного сервера. _(глава 0)_

**Периметр** — граница между внешней сетью и защищаемой инфраструктурой, на которой стоят фильтрующие и контролирующие слои. _(вся книга)_

**Defensive baseline** — минимально достаточный набор настроенных защит, который доказуемо уменьшает поверхность атаки и даёт сигнал защитнику. _(главы 0, 9)_

**Hardening** — дисциплина усиления системы: убрать лишние сервисы, закрыть порты, минимизировать пользователей и права. _(главы 2, 3)_

**Бот-сканирование** — постоянный фоновый шум интернета: автоматический перебор IP, поиск открытых портов, brute-force логинов. _(главы 0, 8)_

**Brute-force** — перебор паролей или имён пользователей в надежде угадать рабочую комбинацию. _(главы 3, 6)_

**Router (роутер)** — устройство, соединяющее сети, делающее NAT и port forwarding; часто имеет лишь базовые firewall-функции. _(глава 1)_

**Firewall (фаервол)** — фильтр, который разрешает и запрещает трафик по правилам на уровне адресов и портов (L3/L4). _(главы 1, 4)_

**UTM / NGFW** — тяжёлый класс устройств с DPI, IDS/IPS, application awareness, VPN и централизованными security-функциями; уровень small business и enterprise. _(глава 1)_

**Reverse proxy** — сервис перед приложением, который завершает TLS, скрывает backend, нормализует HTTP и даёт rate limiting и единое логирование. _(главы 1, 5)_

**WAF (web application firewall)** — фильтр уровня HTTP/HTTPS (L7), отлавливающий подозрительные запросы и типовые payload-паттерны (SQLi, XSS). Не заменяет firewall. _(главы 1, 5, 8)_

**Anti-DDoS / scrubbing** — внешний слой (провайдер или CDN), очищающий поток от мусорного трафика до того, как он дойдёт до origin. _(главы 1, 8)_

**CDN (content delivery network)** — сеть доставки контента перед origin-сервером, скрывающая исходный хост и дающая базовую защиту от части атак. _(глава 8)_

**Порт** — числовой идентификатор сетевого сервиса; открытый порт — потенциальная точка входа. _(главы 0, 1, 2)_

**Bind address** — сетевой адрес, на котором сервис принимает подключения: `127.0.0.1` (только локально) против `0.0.0.0` (все интерфейсы). _(глава 2)_

**0.0.0.0 vs 127.0.0.1** — слушать на всех интерфейсах (публично) против loopback-адреса (только локально); для внутренних сервисов правильный выбор — `127.0.0.1`. _(главы 1, 2, 5)_

**NAT (network address translation)** — подмена адресов при прохождении трафика через router/gateway; включает проброс портов (port forwarding) на внутренние хосты. _(глава 1)_

**UPnP** — протокол автоматического проброса портов на роутере; на периметре обычно стоит отключать. _(глава 1)_

**SSH** — протокол и сервис администраторского доступа к серверу; ключевая «дверь», которую усиливают в первую очередь. _(главы 0, 3)_

**SSH-ключи (key-based auth)** — вход по криптографической паре ключей вместо пароля; основа безопасного SSH. _(глава 3)_

**PermitRootLogin / PasswordAuthentication** — параметры `sshd_config`: запрет прямого входа под root и отключение входа по паролю. _(глава 3)_

**MaxAuthTries** — лимит попыток аутентификации в одной SSH-сессии; сокращает окно brute-force. _(глава 3)_

**Bastion / jump host** — единственный публично доступный хост, через который (механизм `ProxyJump` в SSH) идёт доступ к скрытым внутренним серверам. _(главы 3, приложение B)_

**Allowlist (whitelist)** — список явно разрешённых адресов или сущностей; всё остальное запрещено. _(главы 3, 4)_

**Deny by default (default deny)** — политика firewall, при которой запрещено всё, что не разрешено явно. _(глава 4)_

**Ingress / egress (incoming / outgoing)** — входящий и исходящий трафик; для входящего обычно ставят `deny incoming`, исходящий чаще разрешён по умолчанию. _(глава 4)_

**ufw (uncomplicated firewall)** — упрощённый интерфейс к host firewall на Linux. _(главы 0, 4)_

**Правило (rule)** — отдельная запись политики firewall (allow/deny для порта, адреса или сервиса). _(глава 4)_

**Host firewall** — фаервол на самом Linux-хосте, фильтрующий трафик на сервере. _(главы 1, 4)_

**Edge / cloud firewall (security group)** — фильтр на границе сети или у облачного провайдера, отсекающий трафик ещё до хоста. _(главы 1, 4)_

**Эшелонированная защита (defense in depth)** — несколько независимых слоёв, где ошибка в одном не открывает всё сразу. _(главы 0, 1, 4)_

**DMZ (демилитаризованная зона)** — изолированный сегмент для публичных сервисов между внешней и внутренней сетью; компрометация сервиса не даёт прямого доступа внутрь. _(главы 0, 1, 9)_

**Сегментация** — разделение сети на зоны с осознанными правилами «кто куда может ходить» вместо плоской сети «всё всем». _(главы 0, 9)_

**VPN** — защищённый туннель для административного доступа вместо открытого наружу SSH или панелей. _(главы 1, 3)_

**Rate limiting** — ограничение частоты запросов с одного источника (с допустимым всплеском `burst`); режет шумных ботов и brute-force на чувствительных endpoint'ах. _(главы 5, 8)_

**Security headers** — HTTP-заголовки ответа (`X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`, `Strict-Transport-Security`/HSTS), централизуемые на reverse proxy. _(глава 5)_

**TLS termination (завершение TLS)** — расшифровка HTTPS на reverse proxy, после чего к backend трафик идёт по локальному каналу. _(главы 1, 5)_

**fail2ban** — инструмент, который читает логи, считает повторяющиеся ошибки и через firewall банит шумные IP на время. _(главы 6, 9)_

**CrowdSec** — современная платформа реакции на события с community threat intelligence; оправдана при нескольких узлах и HTTP-сценариях. _(глава 6)_

**jail (fail2ban)** — отдельный набор правил наблюдения за конкретным логом/сервисом с параметрами `bantime`, `findtime`, `maxretry` (например, `[sshd]`, `[nginx-http-auth]`). _(глава 6)_

**Самоблокировка (lockout)** — классическая ошибка: заблокировать собственный административный доступ при настройке fail2ban или firewall; защита от неё — `ignoreip`/allowlist доверенных адресов. _(главы 4, 6)_

**Threat intelligence** — внешние данные о вредоносных источниках, используемые для упреждающей блокировки (есть у CrowdSec). _(глава 6)_

**IDS (intrusion detection system)** — система обнаружения вторжений: наблюдает копию трафика сбоку и сигнализирует, но сама не блокирует. _(глава 7)_

**IPS (intrusion prevention system)** — система предотвращения вторжений: стоит inline в потоке и может блокировать трафик. _(глава 7)_

**Suricata / Snort / Zeek** — инструменты сетевого анализа: сигнатурные IDS/IPS (Suricata, Snort) и телеметрия/forensics (Zeek). _(глава 7)_

**Сигнатура (signature)** — шаблон известной атаки, по которому сигнатурный движок IDS/IPS распознаёт вредоносный трафик. _(глава 7)_

**Triage** — процесс разбора и приоритизации срабатываний; без него IDS/IPS создаёт больше шума, чем пользы. _(глава 7)_

**False positive (ложное срабатывание)** — корректный трафик, ошибочно помеченный как вредоносный; риск при агрессивных правилах WAF/IPS/rate limit. _(главы 5, 7)_

**SYN / port scan** — пакеты с флагом SYN к множеству портов за короткое время; типовой рисунок сканирования (reconnaissance) в `tcpdump`. _(глава 7)_

**Application-layer flood** — поток HTTP-запросов к сайту или login-endpoint, перегружающий приложение на уровне L7. _(глава 8)_

**Volumetric DDoS** — объёмная атака, забивающая канал или edge раньше, чем сервер успевает осмыслить трафик; не решается локальным firewall. _(глава 8)_

**Controlled check / controlled load test** — безопасная проверка защиты только на своих системах, не превращающаяся во вредоносную нагрузку. _(главы 0, 8, 9)_

**Baseline (срез состояния) / snapshot** — зафиксированный эталон открытых портов, сервисов и настроек и сохранённое состояние VM для отката перед опасными шагами hardening. _(главы 0, 2, 9)_

**Zero trust** — модель, в которой ни один сегмент или хост не считается доверенным по умолчанию; доступ проверяется на каждом шаге. _(главы 0, 9)_
