# Глоссарий

> Термины и выражения книги «Git — практический минимум». В скобках — главы, где термин вводится или активно используется.

---

**Git** — распределённая система контроля версий: хранит историю изменений файлов. _(глава 0)_

**Репозиторий (repo)** — папка проекта под управлением Git (со скрытой `.git/`). _(главы 2, 5)_

**Рабочая директория** — твои файлы в текущем виде, с которыми ты работаешь. _(глава 2)_

**Индекс / staging area** — промежуточная область, куда `git add` помещает изменения перед коммитом. _(главы 2, 3)_

**Коммит** — зафиксированный снимок изменений с автором, датой и сообщением. _(главы 2, 3)_

**SHA / хеш коммита** — уникальный идентификатор коммита (длинная hex-строка). _(глава 2)_

**HEAD** — указатель на текущий коммит/ветку, где ты находишься. _(главы 2, 8)_

**`git add` / `git commit`** — добавить изменения в индекс и зафиксировать их в историю. _(глава 3)_

**`git log` / `git diff`** — посмотреть историю коммитов и различия между состояниями. _(глава 3)_

**Ветка (branch)** — независимая линия разработки; по сути подвижный указатель на коммит. _(глава 4)_

**`git checkout` / `git switch`** — переключение между ветками/коммитами. _(глава 4)_

**Merge (слияние)** — объединение изменений одной ветки в другую. _(главы 4, 7)_

**Fast-forward** — слияние без отдельного merge-коммита, простым перемещением указателя. _(главы 4, 7)_

**Merge-коммит** — коммит с двумя родителями, фиксирующий слияние веток. _(главы 4, 7)_

**Конфликт слияния** — ситуация, когда Git не может сам объединить правки одних и тех же строк. _(глава 6)_

**Маркеры конфликта (`<<<<<<<`, `=======`, `>>>>>>>`)** — границы конфликтующих версий, которые правят руками. _(глава 6)_

**Rebase** — перенос коммитов на новое основание; делает историю линейной. _(глава 7)_

**Remote (удалённый репозиторий)** — копия репозитория на сервере (GitHub/GitLab). _(глава 5)_

**origin** — стандартное имя основного удалённого репозитория. _(глава 5)_

**`git clone`** — скачать удалённый репозиторий целиком. _(глава 5)_

**`git fetch` / `git pull`** — забрать изменения с remote (fetch — только скачать, pull — скачать и слить). _(глава 5)_

**`git push`** — отправить свои коммиты в удалённый репозиторий. _(глава 5)_

**Upstream / tracking branch** — удалённая ветка, за которой следит локальная. _(глава 5)_

**`git reset`** — сдвинуть HEAD/ветку; `--soft`/`--mixed`/`--hard` по-разному трогают индекс и файлы. _(глава 8)_

**`git revert`** — отменить изменения новым «обратным» коммитом, не переписывая историю. _(глава 8)_

**`git stash`** — временно отложить незакоммиченные изменения и вернуться к чистому состоянию. _(глава 8)_

**`git amend`** — изменить последний коммит (сообщение или содержимое). _(глава 9)_

**`.gitignore`** — файл со списком путей, которые Git должен игнорировать. _(глава 9)_

**Атомарный коммит** — коммит, делающий одно логическое изменение; основа хороших практик. _(глава 9)_

**SSH-ключ** — пара ключей для доступа к GitHub/GitLab без пароля. _(глава 10)_

**GitHub / GitLab** — платформы хостинга Git-репозиториев с CI/CD и ревью. _(глава 10)_

**Pull Request / Merge Request (PR/MR)** — запрос на вливание ветки с код-ревью. _(главы 10, 11)_

**Trunk-based development** — стратегия с короткоживущими ветками и частыми вливаниями в main. _(глава 11)_

**Git Flow / GitHub Flow** — модели ветвления для команды (тяжёлая с release-ветками vs лёгкая с PR). _(глава 11)_

**Tag (тег)** — именованная метка коммита, обычно для версий релизов (`v1.2.0`). _(глава 12)_

**Git hook** — скрипт, запускаемый Git на событие (pre-commit, post-receive). _(глава 12)_

**Detached HEAD** — состояние, когда HEAD указывает на коммит, а не на ветку. _(глава 8)_

**cherry-pick** — перенос отдельного коммита из одной ветки в другую. _(глава 8)_

**Squash** — объединение нескольких коммитов в один. _(главы 7, 11)_
