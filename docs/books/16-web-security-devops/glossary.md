# Глоссарий

> Термины и выражения книги «Веб-безопасность». В скобках — главы, где термин вводится или активно используется.

---

**Threat model (модель угроз)** — структурированный взгляд на активы, границы доверия и вероятные классы атак до включения защиты. _(глава 0)_

**Trust boundary (граница доверия)** — место, где данные переходят из менее доверенной зоны в более доверенную и где их нельзя принимать «как есть». _(главы 0, 4, 6)_

**Актив (asset)** — то, что приложение защищает: учётные данные, сессии, PII, секреты, доступ к админке. _(глава 0)_

**Defensible baseline** — минимально достаточный набор защит, который можно показать и обосновать перед релизом. _(главы 0, 9)_

**Аутентификация** — проверка того, что пользователь действительно тот, за кого себя выдаёт. _(глава 1)_

**Авторизация** — проверка прав уже аутентифицированного пользователя на конкретное действие. _(главы 1, 4)_

**Сессия (session)** — серверное состояние входа пользователя, связанное с браузером через session id. _(главы 1, 8)_

**Session cookie** — cookie с идентификатором сессии; должна иметь флаги HttpOnly, Secure, SameSite и разумный TTL. _(главы 1, 8)_

**HttpOnly** — флаг cookie, запрещающий чтение её из JavaScript и снижающий эффект кражи через XSS. _(главы 1, 3, 8)_

**Secure (флаг cookie)** — флаг, при котором браузер отправляет cookie только по HTTPS. _(главы 1, 6, 8)_

**SameSite** — атрибут cookie (Lax/Strict/None), управляющий отправкой cookie в cross-site запросах; часть защиты от CSRF. _(главы 1, 4, 8)_

**Password reset flow** — отдельный протокол сброса пароля с одноразовым короткоживущим токеном, сгорающим после использования. _(глава 1)_

**User enumeration** — утечка факта существования учётной записи через различающиеся ответы или тайминги логина. _(главы 1, 8)_

**Rate limiting** — ограничение частоты запросов (например, к /login и /password-reset) для борьбы с перебором. _(главы 1, 8)_

**Хэширование паролей** — хранение паролей через стойкие функции (argon2id, bcrypt), а не в открытом виде. _(глава 1)_

**JWT (JSON Web Token)** — самодостаточный токен; требует контроля срока жизни и отзыва, не является «магической» защитой. _(глава 1)_

**Токен (token)** — выдаваемый сервером идентификатор доступа (сессионный, reset, API), который нужно валидировать и инвалидировать. _(главы 1, 4)_

**SQL injection (SQLi)** — внедрение SQL-кода через ввод, когда данные смешиваются с синтаксисом запроса. _(главы 2, 8)_

**Параметризованный запрос (prepared statement)** — запрос с placeholder, где драйвер передаёт ввод как данные отдельно от структуры SQL. _(глава 2)_

**Allowlist (белый список)** — явный список допустимых значений (колонок сортировки, схем, хостов, origin) вместо запрета «всего лишнего». _(главы 2, 4, 5)_

**ORM** — слой объектно-реляционного отображения; закрывает базовые инъекции, но не отменяет review raw SQL и динамических фрагментов. _(глава 2)_

**Least privilege (минимальные привилегии)** — выдача приложению только нужных прав БД (readonly/readwrite), а не суперпользователя. _(глава 2)_

**XSS (Cross-Site Scripting)** — внедрение скрипта в страницу, исполняемого в браузере жертвы, когда ввод попадает в DOM как HTML. _(главы 3, 8)_

**DOM-based XSS** — разновидность XSS, возникающая в клиентском коде через небезопасные DOM API (innerHTML и т.п.). _(глава 3)_

**Output encoding (контекстное экранирование)** — преобразование вывода по месту (HTML, attribute, JS, URL), чтобы данные не стали кодом. _(глава 3)_

**Санитизация (sanitization)** — очистка rich content (HTML, markdown) от опасных элементов перед выводом. _(глава 3)_

**CSP (Content-Security-Policy)** — заголовок-политика, ограничивающий источники скриптов; работает вторым слоем, а не заменой экранирования. _(главы 3, 8)_

**CSRF (Cross-Site Request Forgery)** — атака, использующая автоматически приложенную браузером cookie для выполнения действия от лица жертвы. _(главы 4, 8)_

**CSRF token** — непредсказуемый токен в state-changing запросе, подтверждающий, что запрос инициирован своим приложением. _(глава 4)_

**CORS (Cross-Origin Resource Sharing)** — механизм, регулирующий, какому чужому origin браузер разрешает читать ответ. _(главы 4, 8)_

**Same-origin policy** — базовое правило браузера: страница по умолчанию не читает ответы с другого origin. _(глава 4)_

**Origin** — комбинация схемы, хоста и порта; единица доверия в CORS и same-origin policy. _(глава 4)_

**State-changing endpoint** — endpoint, меняющий данные (POST/PUT/PATCH/DELETE); требует CSRF-защиты. _(главы 4, 8)_

**X-Forwarded-* / forwarded headers** — заголовки прокси (Proto, For, Host); им можно доверять только от известного reverse proxy. _(главы 4, 6)_

**Reverse proxy** — узел (nginx, caddy, traefik), завершающий TLS и формирующий доверенную границу перед приложением. _(главы 4, 6)_

**SSRF (Server-Side Request Forgery)** — принуждение backend сделать исходящий запрос на внутренний адрес из доверенной позиции. _(главы 5, 8)_

**Metadata endpoint** — внутренний сервис облака (например, 169.254.169.254), частая цель SSRF; должен быть запрещён. _(глава 5)_

**File upload risks** — класс рисков загрузки: подмена MIME, исполняемые типы, oversized файлы, path traversal, хранение в web-root. _(глава 5)_

**MIME type** — заявленный тип содержимого; client content-type нужно проверять против реального типа на сервере. _(главы 5, 8)_

**Secret hygiene** — дисциплина обращения с секретами: отдельный .env, права 600, отсутствие в Git, логах и шаблонах. _(глава 6)_

**.env** — файл переменных окружения с секретами; должен жить вне Git, с владельцем-приложением и правами `-rw-------`. _(глава 6)_

**.env.example** — шаблон конфигурации с плейсхолдерами вместо реальных ключей. _(глава 6)_

**HSTS (Strict-Transport-Security)** — заголовок, заставляющий браузер ходить на сайт только по HTTPS. _(глава 6)_

**TLS termination** — завершение TLS на reverse proxy; после него backend должен понимать, что исходный запрос был HTTPS. _(глава 6)_

**Security headers (заголовки безопасности)** — набор защитных заголовков: CSP, X-Content-Type-Options, X-Frame-Options, HSTS, Referrer-Policy. _(главы 3, 6, 8)_

**X-Content-Type-Options: nosniff** — заголовок, запрещающий браузеру угадывать MIME-тип ответа. _(главы 3, 6)_

**Supply chain risk (риск цепочки поставки)** — угрозы через чужие зависимости: CVE, typosquatting, install scripts, непинованные версии. _(глава 7)_

**Lock-файл** — файл с зафиксированными версиями зависимостей (package-lock.json, poetry.lock, go.sum) для воспроизводимой сборки. _(глава 7)_

**SCA / dependency audit** — анализ состава зависимостей и поиск уязвимостей (pip-audit, npm audit, trivy). _(глава 7)_

**SBOM (Software Bill of Materials)** — инвентаризация компонентов проекта; полезна даже в небольшом сервисе. _(глава 7)_

**CVE** — публичный идентификатор известной уязвимости в пакете или образе. _(глава 7)_

**Typosquatting** — публикация вредоносного пакета с именем, похожим на популярный, в расчёте на опечатку. _(глава 7)_

**Controlled check** — безопасная проверка защиты только на своей lab без offensive-эксплуатации. _(главы 8, 9)_

**Lab-only** — принцип: все демонстрации проводятся только на своих VM, контейнерах и тестовых доменах. _(главы 0, 8)_

**OWASP Top 10** — общепринятый перечень наиболее критичных классов веб-рисков, лежащий в основе тем книги (XSS, SQLi, SSRF и др.). _(главы 0–8)_
