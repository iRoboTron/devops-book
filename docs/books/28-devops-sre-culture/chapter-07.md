# Глава 7: Инциденты и postmortem без поиска виноватых

> **Цель:** научиться превращать падения в улучшения системы.

---

## 7.1 Что такое инцидент

Инцидент — это событие, которое ухудшило сервис для пользователя или могло ухудшить.

Примеры:

- сайт отдаёт 502;
- бот не отвечает;
- база недоступна;
- кончился диск;
- backup не создавался неделю;
- деплой выкатил пустой `.env`.

Не каждый инцидент — катастрофа. Но каждый серьёзный инцидент должен чему-то научить.

---

## 7.2 Blameless не значит безответственно

Blameless postmortem — это не "никто не виноват, забыли". Это разбор без охоты на человека.

Плохой вопрос:

```text
кто сломал?
```

Хороший вопрос:

```text
почему наша система позволила ошибке дойти до пользователя?
```

Человек мог ошибиться, но задача — сделать процесс устойчивее к такой ошибке.

Главное отличие blameless-разбора — куда идёт стрелка после вопроса «почему». Не в человека, а в систему, которая потом становится крепче:

```mermaid

    A["Инцидент\nсбой у пользователя"] --> B["Восстановление\nсервиса"]

    C --> D["Action items\nв систему, не в людей"]
```

## 7.3 Сквозной сценарий

```text
03:14 — uptime-check присылает алерт: сайт недоступен
03:15 — curl показывает Connection refused
03:17 — docker ps: контейнер app в состоянии restarting
03:19 — docker logs app: DATABASE_URL пустой
03:22 — причина: деплой перезаписал .env пустым шаблоном
03:25 — исправление: восстановить .env, перезапустить app
03:27 — сайт работает. Длительность: 13 минут
```

---

## 7.4 Postmortem

```markdown
# Incident report: пустой .env после деплоя

## Что случилось
После деплоя приложение потеряло переменную DATABASE_URL и не смогло подключиться к БД.

## Влияние
Сайт был недоступен 13 минут. Пользователи видели 502.

## Timeline
03:14 alert
03:17 найден restarting контейнер
03:22 найдена причина
03:27 восстановлено

## Причина
Deploy script копировал `.env.example` поверх `.env`.

## Что помогло
Был uptime-check и доступ к логам контейнера.

## Что мешало
Не было проверки переменных перед restart. Не было backup `.env`.

## Action items
- Исправить deploy script: не перезаписывать `.env`.
- Добавить preflight-check обязательных env.
- Добавить smoke-test после деплоя.
```

---

## 7.5 Практика

Напиши postmortem по этому сценарию, но добавь:

- владельца каждого action item;
- срок выполнения;
- как проверить, что задача закрыта.

Проверка: в отчёте не должно быть фразы "Петя виноват". Должны быть изменения в системе.
