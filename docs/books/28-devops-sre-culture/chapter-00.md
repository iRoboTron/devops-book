# Глава 0: Почему "просто задеплоить" недостаточно

> **Запомни:** продакшен — это не место, куда копируют файлы. Это место, где пользователи зависят от твоего сервиса.

---

## 0.1 История обычного учебного проекта

Представь простой сайт. Ты написал код, проверил у себя на компьютере, потом зашёл на сервер и вручную обновил файлы. Сначала всё выглядело нормально. Через десять минут кто-то пишет: "сайт не открывается".

Ты заходишь на сервер и видишь:

- Nginx отдаёт 502;
- контейнер приложения перезапускается;
- в логах ошибка подключения к базе;
- точного списка изменений нет;
- отката нет;
- backup есть "наверное";
- пользователи ждут ответа.

Это не редкая авария. Это нормальное последствие процесса, где всё держится на ручной памяти.

---

## 0.2 Почему "работает у меня" не результат

"Работает у меня" означает только одно: в одной среде, при одном наборе условий, один раз всё запустилось. Продакшен требует большего:

| Вопрос | Почему важен |
|---|---|
| Как повторить деплой? | чтобы не зависеть от памяти человека |
| Как проверить результат? | чтобы не ждать жалоб пользователя |
| Как откатиться? | чтобы ошибка не жила часами |
| Где логи? | чтобы искать причину, а не гадать |
| Кто отвечает? | чтобы не терять время на споры |

DevOps и SRE появляются именно из этих вопросов.

---

## 0.3 Продакшен — это отдельная реальность

На локальном компьютере у тебя обычно один пользователь — ты. В продакшене есть сеть, DNS, сертификаты, база, диск, память, пользователи, время, деньги и ожидания.

Даже маленький сервис имеет жизненный цикл:

```text
написать -> проверить -> выкатить -> наблюдать -> чинить -> обновить -> восстановить
```

Если ты умеешь только "выкатить", ты видишь только середину процесса.

---

## 0.4 Что меняет инженерный подход

Плохой процесс:

```text
изменил код -> вручную залил -> надеюсь, работает
```

Хороший процесс:

```text
изменил код -> тесты -> деплой по чеклисту -> smoke-check -> мониторинг -> rollback plan
```

Это не обязательно Kubernetes, Terraform и корпоративный отдел SRE. Для одного человека достаточно простого deploy script, README, backup, healthcheck и привычки писать, что изменилось.
