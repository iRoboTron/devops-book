# Глоссарий

> Термины и выражения книги «Продвинутый Kubernetes». В скобках — главы, где термин вводится или активно используется.

---

**Ingress** — объект K8s, описывающий правила HTTP(S)-маршрутизации внешнего трафика к Service по hostname и path. _(глава 1)_

**Ingress Controller** — программа (Traefik, Nginx), которая читает объекты Ingress и реально применяет правила маршрутизации. Сам Ingress без контроллера ничего не делает. _(глава 1)_

**ingressClassName** — поле в манифесте Ingress, указывающее, какой именно Ingress Controller должен обслуживать эти правила (например `traefik`). _(глава 1)_

**Traefik** — Ingress Controller, встроенный в k3s по умолчанию. _(глава 1)_

**pathType** — тип сопоставления пути в Ingress (`Prefix`, `Exact`, `ImplementationSpecific`). _(глава 1)_

**Host-based routing** — маршрутизация трафика к разным Service по доменному имени (заголовок `Host`). _(глава 1)_

**Path-based routing** — маршрутизация к разным Service по URL-пути в пределах одного домена (`/` → frontend, `/api` → api). _(глава 1)_

**TLS** — шифрование трафика (HTTPS); в Ingress задаётся через `spec.tls` и секрет с сертификатом. _(глава 1)_

**cert-manager** — контроллер, автоматически выпускающий и обновляющий TLS-сертификаты в кластере. _(глава 1)_

**ClusterIssuer** — объект cert-manager, описывающий источник сертификатов (например Let's Encrypt) на уровне всего кластера. _(глава 1)_

**Let's Encrypt** — бесплатный центр сертификации, выдающий TLS-сертификаты через протокол ACME. _(глава 1)_

**ACME / HTTP-01 challenge** — протокол и способ проверки владения доменом при автоматическом выпуске сертификата. _(глава 1)_

**HPA (HorizontalPodAutoscaler)** — объект, автоматически изменяющий число реплик Deployment по метрикам (обычно загрузка CPU). _(глава 2)_

**metrics-server** — компонент, собирающий метрики CPU/RAM с Pod'ов; без него HPA и `kubectl top` не работают. _(глава 2)_

**averageUtilization** — целевой процент загрузки ресурса (например CPU 70%), к которому HPA подгоняет число реплик. _(глава 2)_

**minReplicas / maxReplicas** — нижняя и верхняя границы числа реплик, в которых HPA имеет право масштабировать. _(глава 2)_

**Stabilization window** — задержка перед уменьшением числа реплик, чтобы HPA не «дёргал» масштаб при кратких всплесках. _(глава 2)_

**requests** — объём ресурсов (CPU/память), который Scheduler резервирует под Pod; основа для размещения и для работы HPA. _(главы 2, 3)_

**limits** — максимум ресурсов для контейнера: превышение CPU вызывает throttling, превышение памяти — OOMKilled. _(глава 3)_

**milliCPU (m)** — единица измерения CPU: `1000m` = 1 ядро, `100m` = 0.1 ядра. _(глава 3)_

**Throttling** — принудительное замедление контейнера при достижении CPU-limit (процесс не убивается). _(глава 3)_

**OOMKilled** — убийство контейнера ядром при превышении лимита памяти с последующим перезапуском. _(глава 3)_

**LimitRange** — объект, задающий значения resources по умолчанию для Pod'ов в namespace. _(глава 3)_

**ResourceQuota** — объект, ограничивающий суммарное потребление CPU/памяти и число объектов (Pod и др.) в namespace. _(глава 3)_

**StatefulSet** — контроллер для приложений с состоянием: стабильные имена Pod'ов, строгий порядок старта и отдельный том на каждую реплику. _(глава 4)_

**Deployment** — контроллер для stateless-приложений с взаимозаменяемыми Pod'ами и случайными именами. _(главы 0, 4)_

**volumeClaimTemplates** — шаблон в StatefulSet, по которому каждому Pod'у создаётся собственный PVC (`pgdata-postgres-0` и т.д.). _(глава 4)_

**Headless Service** — Service с `clusterIP: None`, дающий стабильные DNS-имена отдельным Pod'ам StatefulSet. _(глава 4)_

**PVC (PersistentVolumeClaim)** — запрос на постоянное хранилище заданного размера и режима доступа. _(главы 0, 4)_

**PV (PersistentVolume)** — фактический том в кластере, к которому привязывается PVC. _(глава 4)_

**StorageClass** — класс хранилища, определяющий, как динамически создаются PV под PVC. _(приложение)_

**ReadWriteOnce** — режим доступа тома: может быть смонтирован на чтение-запись только одной нодой. _(глава 4)_

**NetworkPolicy** — объект-фаервол на уровне Pod'ов, разрешающий или запрещающий трафик по label-селекторам и портам. _(глава 5)_

**podSelector** — селектор по меткам, выбирающий Pod'ы, к которым применяется политика или от которых разрешён трафик. _(глава 5)_

**policyTypes** — указание, какие направления контролирует NetworkPolicy: `Ingress` (входящий) и/или `Egress` (исходящий). _(глава 5)_

**Deny-all** — базовая политика с пустым `podSelector: {}`, блокирующая весь трафик; затем точечно открывают нужное. _(глава 5)_

**CNI (Container Network Interface)** — плагин сети кластера; NetworkPolicy работает только если CNI её поддерживает (Calico, Cilium, kube-router). _(глава 5)_

**Flannel** — простой CNI (по умолчанию в k3s); сам по себе политики не реализует, в k3s enforcement даёт встроенный kube-router. _(глава 5)_

**Calico / Cilium** — CNI-плагины с полноценной поддержкой NetworkPolicy и расширенных сетевых возможностей. _(глава 5)_

**RBAC (Role-Based Access Control)** — модель управления правами в кластере на основе ролей. _(глава 6)_

**ServiceAccount** — учётная запись для Pod'а или процесса («кто» обращается к API). _(глава 6)_

**Role** — набор разрешений (verbs над resources) в пределах одного namespace. _(глава 6)_

**ClusterRole** — набор разрешений на уровне всего кластера (например доступ к nodes). _(глава 6)_

**RoleBinding** — объект, связывающий субъект (ServiceAccount/пользователя) с Role в namespace. _(глава 6)_

**ClusterRoleBinding** — связывание субъекта с ClusterRole на уровне всего кластера. _(глава 6)_

**verbs** — действия, разрешённые правилом RBAC: `get`, `list`, `watch`, `create`, `delete` и т.д. _(глава 6)_

**apiGroups / resources** — группа API и тип объектов, к которым применяется правило RBAC (`""` — core-группа, `pods`, `pods/log`). _(глава 6)_

**kubectl auth can-i** — команда проверки, разрешено ли субъекту выполнить действие. _(глава 6)_

**Принцип минимальных привилегий** — выдавать ровно те права, что нужны для задачи, и не больше. _(глава 6)_

**Helm** — пакетный менеджер Kubernetes: упаковывает набор манифестов в один управляемый артефакт. _(главы 7, 8, 9)_

**Chart** — пакет Helm: каталог с `Chart.yaml`, `values.yaml` и шаблонами в `templates/`. _(главы 7, 8)_

**values.yaml** — файл значений по умолчанию для шаблонов chart; переопределяется через `-f` или `--set`. _(главы 8, 9)_

**Шаблон (template)** — манифест с подстановками Go-template (`{{ .Values.replicaCount }}`, `{{ .Release.Name }}`), из которого рендерится финальный YAML. _(глава 8)_

**Release** — конкретная установка chart в кластере под именем; у неё своя история ревизий. _(главы 8, 9)_

**helm template** — команда рендера шаблонов в готовый YAML без применения к кластеру (для проверки). _(глава 8)_

**helm install / upgrade / uninstall** — установка, обновление и удаление release. _(глава 8)_

**helm rollback** — откат release к предыдущей ревизии по `helm history`. _(глава 9)_

**Tiller-less** — архитектура Helm 3 без серверного компонента Tiller: клиент общается с API напрямую. _(глава 8)_

**Dependencies / subchart** — зависимые chart'ы, подключаемые в `Chart.yaml` и подтягиваемые через `helm dependency update`. _(глава 9)_

**Bitnami** — популярный публичный репозиторий готовых charts (PostgreSQL, Redis и др.). _(глава 9)_
