## Для кого эта книга

Для человека, который хочет перестать жить с паролями "как получится".

Книга полезна:

- школьнику или студенту, у которого уже есть много аккаунтов;
- начинающему программисту;
- владельцу GitHub, VPS, домена или хостинга;
- семье, где есть общие доступы;
- маленькой команде, которая пока отправляет пароли в чат;
- любому человеку, который боится потерять доступ к почте, банку или рабочим аккаунтам.

## Предварительные требования

Нужны:

- компьютер или ноутбук;
- телефон;
- браузер;
- доступ к своей почте;
- готовность создать тестовые записи и потренироваться без реальных секретов.

Опционально:

- Linux-виртуалка из первой части курса;

Книга не требует знания DevOps. Если появляются Linux-команды, они объясняются заново.

## Главная идея

Хранение паролей — это не один совет, а система:

```text
Уникальные пароли
  -> менеджер паролей
  -> мастер-пароль
  -> MFA / passkeys
  -> recovery codes
  -> backup
  -> emergency plan
  -> регулярная проверка
```

Без менеджера паролей трудно иметь уникальные пароли.
Без MFA один украденный пароль может открыть важный аккаунт.
Без recovery можно самому потерять доступ навсегда.
Без backup менеджер паролей превращается в одну точку отказа.

## Как пользоваться книгой

1. Не начинай с переноса всех паролей.
2. Сначала сделай карту аккаунтов.
3. Потом выбери менеджер паролей.
4. Затем настрой MFA и recovery для самых важных сервисов.
5. Только после этого постепенно меняй старые пароли.
6. Все учебные действия сначала делай на тестовых записях.

---

## Важная рамка безопасности

В книге нельзя использовать реальные пароли в примерах, скриншотах, командах или учебных файлах.

Все примеры должны быть тестовыми:

- `correct-horse-test-2026`
- `demo-email-password`
- `github-test-token`
- `bank-example-do-not-use`

Цель книги — защита своих аккаунтов и восстановление доступа, а не подбор, кража или обход чужих доступов.

## Итоговый проект

Читатель выбирает один сценарий:

- **Один человек:** личная система паролей и восстановления.
- **Семья:** shared vault, emergency access и правила общих аккаунтов.
- **Программист:** GitHub, SSH, tokens, `.env`, backup и recovery.
- **Маленькая команда:** shared collections, offboarding и владелец recovery.

Финальный результат должен быть не "я поставил приложение", а:

- я знаю, где мои важные доступы;
- у меня уникальные пароли;
- у меня включён MFA;
- я понимаю, как восстановиться;
- у меня есть backup;
- я знаю, что делать при потере телефона;
- я могу объяснить свою систему другому человеку.
