# Приложение A: Шпаргалка выбора

> **Назначение:** быстро выбрать подходящий вариант хранения паролей без перечитывания всей книги.

---

## A.1 Если ты совсем начинаешь

Выбор:

- Bitwarden;
- 1Password, если готов платить за удобство;
- Proton Pass, если уже пользуешься Proton;
- браузерный менеджер как временный первый шаг.

Минимум:

- уникальные пароли;
- MFA на почте;
- MFA на менеджере паролей;
- recovery codes;
- backup.

Не начинай с self-hosted для реальных паролей.

---

## A.2 Если ты школьник или студент

Главные аккаунты:

- основная почта;
- Apple/Google account;
- мессенджеры;
- учебные сервисы;
- GitHub, если программируешь;
- банк, если есть.

Что сделать первым:

1. поставить менеджер паролей;
2. поменять пароль почты;
3. включить MFA на почте;
4. сохранить recovery codes;
5. перенести 10 важных аккаунтов.

---

## A.3 Если ты программист

Выбор:

- Bitwarden или 1Password как основной vault;
- KeePassXC, если нужен local-first;
- hardware key для GitHub и критичных сервисов;
- отдельное правило для tokens и `.env`.

Обязательно:

- MFA на GitHub/GitLab;
- `.env` в `.gitignore`;
- tokens с минимальными правами;
- recovery codes;
- backup vault;
- проверка SSH keys.

---

## A.4 Если нужна семейная схема

Выбор:

- family plan в Bitwarden/1Password/другом менеджере;
- shared vault для общих записей;
- личные vault не смешивать.

Что хранить в shared vault:

- семейные подписки;
- Wi-Fi;
- домен/хостинг, если есть;
- общие сервисы;
- emergency instructions.

Что не делать:

- не отправлять пароли в чат;
- не держать всё у одного человека;
- не заставлять всех видеть личные пароли друг друга.

---

## A.5 Если маленькая команда

Нужны:

- shared collections;
- роли;
- MFA;
- offboarding;
- два владельца критичных сервисов;
- правила для tokens;
- журнал изменений доступа.

Личный бесплатный vault владельца — плохая командная система.

---

## A.6 Bitwarden vs KeePassXC

| Критерий | Bitwarden | KeePassXC |
|---|---|---|
| Старт | Проще | Сложнее |
| Синхронизация | Встроенная | На пользователе |
| Offline | Частично | Отлично |
| Backup | Нужен export | Копия `.kdbx` |
| Семья | Удобнее | Сложнее |
| Контроль файла | Меньше | Больше |
| Риск новичка | Ниже | Выше без backup |

Вывод:

- большинству проще начать с Bitwarden;
- KeePassXC хорош, если ты понимаешь backup и хочешь local-first.

---

## A.7 Managed vs self-hosted

| Вопрос | Если ответ "нет" — self-hosted рано |
|---|---|
| Умею обновлять сервер? | Да/нет |
| Есть backup? | Да/нет |
| Проверял restore? | Да/нет |
| Понимаю HTTPS? | Да/нет |
| Понимаю firewall? | Да/нет |
| Знаю, где логи? | Да/нет |
| Есть план при падении VPS? | Да/нет |

Self-hosted полезен для обучения. Для реальных паролей он требует зрелой эксплуатации.

---

## A.8 SMS vs TOTP vs hardware key

| Вариант | Выбирай если | Не выбирай если |
|---|---|---|
| SMS | Другого MFA нет | Аккаунт критичный и есть TOTP |
| TOTP | Нужен хороший баланс | Не готов хранить recovery |
| Push | Сервис рабочий и удобный | Часто подтверждаешь не думая |
| Hardware key | Аккаунт критичный | Нет запасного ключа |
| Passkey | Сервис хорошо поддерживает | Не понимаешь recovery |

---

## A.9 Что делать первым

Если времени мало:

1. почта: уникальный пароль + MFA;
2. менеджер паролей: мастер-пароль + MFA;
3. recovery codes: сохранить;
4. GitHub/банк/Apple/Google: уникальный пароль + MFA;
5. backup vault.

---

## A.10 Чего лучше не делать

- один пароль на всё;
- пароли в чате;
- `passwords.txt`;
- self-hosted без backup;
- MFA без recovery codes;
- единственный hardware key без запасного пути;
- plain export в облаке;
- токены в README;
- `.env` в Git.
