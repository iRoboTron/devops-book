# Глава 4: Браузер, cloud, local и self-hosted

> **Запомни:** "где хранить пароли" — это выбор между удобством, контролем, риском потери доступа и ответственностью за backup.

---

## 4.1 Какие варианты вообще бывают

Есть несколько классов решений:

- браузерный менеджер;
- экосистемный менеджер Apple/Google/Microsoft;
- cloud password manager;
- local password manager;
- self-hosted password manager;
- командные инструменты для технических людей;
- бумажный recovery;
- плохие временные варианты вроде обычного `.txt`.

Не существует идеального варианта для всех.

---

## 4.2 Браузерный менеджер

Примеры:

- Chrome / Google Password Manager;
- Firefox Password Manager;
- Edge / Microsoft Passwords;
- Safari / iCloud Keychain.

Плюсы:

- уже есть;
- очень удобно;
- хорошо для старта;
- синхронизация часто включена;
- умеет предупреждать о слабых паролях.

Минусы:

- привязка к браузеру или экосистеме;
- меньше возможностей для семьи и команды;
- не всегда удобно хранить recovery notes;
- сложно отделить личные и рабочие доступы;
- всё сильно зависит от безопасности основного аккаунта.

Когда подходит:

- совсем простой старт;
- человек пользуется одной экосистемой;
- нет командных и семейных сценариев.

---

## 4.3 Cloud password manager

Примеры:

- Bitwarden;
- 1Password;
- Proton Pass.

Плюсы:

- отдельное приложение;
- расширения для разных браузеров;
- мобильные приложения;
- удобная синхронизация;
- family/team функции;
- генератор паролей;
- secure notes;
- иногда удобные passkeys и MFA-функции.

Минусы:

- нужно доверять сервису;
- нужен сильный мастер-пароль;
- нужен MFA на сам менеджер;
- подписка может стоить денег;
- при проблемах с аккаунтом нужен recovery-план.

Когда подходит:

- большинству людей;
- семье;
- программисту;
- маленькой команде, если выбран team/family plan.

---

## 4.4 Local password manager

Пример:

- KeePassXC.

Идея:

```text
Пароли лежат в локальном файле .kdbx
Ты сам решаешь, где этот файл хранить и как копировать
```

Плюсы:

- нет обязательного облачного аккаунта;
- файл под твоим контролем;
- хорош для offline-first подхода;
- можно хранить на флешке или в своём backup.

Минусы:

- backup полностью на тебе;
- синхронизация между устройствами сложнее;
- можно потерять файл;
- можно создать конфликт копий;
- семье и команде сложнее пользоваться.

Когда подходит:

- техническому человеку;
- человеку, который не хочет cloud;
- offline-сценариям;
- backup-дисциплинированным пользователям.

---

## 4.5 Self-hosted password manager

Пример:

- Vaultwarden.

Идея:

```text
Ты сам поднимаешь сервер менеджера паролей
Клиенты подключаются к твоему серверу
```

Плюсы:

- больше контроля;
- полезно для обучения;
- можно использовать знакомый Bitwarden-клиент;
- подходит для lab и некоторых маленьких команд.

Минусы:

- ты отвечаешь за сервер;
- ты отвечаешь за HTTPS;
- ты отвечаешь за обновления;
- ты отвечаешь за backup;
- ошибка на VPS может открыть критичную поверхность атаки;
- self-hosted не делает систему безопаснее автоматически.

Когда подходит:

- учебная лаборатория;
- технический человек с опытом серверов;
- маленькая команда с администратором;
- сценарий, где понятно, зачем нужен контроль.

Когда не подходит:

- новичку с реальными паролями;
- человеку без backup;
- серверу без обновлений;
- публичному VPS "поставил и забыл".

---

## 4.6 Командные варианты

Примеры:

- `pass`;
- `gopass`.

Они интересны техническим людям:

- используют GPG;
- хорошо живут в терминале;
- могут работать с Git;
- понятны тем, кто любит plain text workflow, но с шифрованием.

Минусы:

- новичку сложно;
- мобильный опыт хуже;
- recovery сложнее;
- ошибка с GPG-ключом может привести к потере доступа.

В этой книге они упоминаются как техническая ветка, а не основной путь.

---

## 4.7 Бумажный recovery

Бумага не подходит для хранения всех паролей.

Но она полезна для:

- аварийной подсказки;
- recovery codes;
- инструкции для близкого человека;
- места хранения backup-флешки;
- emergency kit.

Плюсы:

- не зависит от облака;
- не ломается от обновления приложения;
- не заражается malware.

Минусы:

- можно потерять;
- можно сфотографировать;
- можно забыть обновить;
- нужен физически безопасный дом.

---

## 4.8 Что точно плохо

Плохие варианты:

- `passwords.txt` на рабочем столе;
- заметка без шифрования;
- сообщение самому себе в Telegram;
- фото бумажки с паролями;
- один Excel-файл без защиты;
- одинаковый пароль на всё;
- "восстанавливаю через почту каждый раз".

Если сейчас у тебя так, это не повод ругать себя. Это стартовая точка для миграции.

## 4.9 Большое сравнение

| Вариант | Для кого | Удобство | Риск потери доступа | Риск облака | Backup | Комментарий |
|---|---|---|---|---|---|---|
| Браузер | Новичок | Высокое | Средний | Зависит от аккаунта | Обычно скрыт | Хороший первый шаг |
| Bitwarden | Один человек / семья | Высокое | Средний | Есть | Нужен export | Практичный старт |
| 1Password | Семья / команда | Очень высокое | Низкий при правильном recovery | Есть | Хорошие процессы | Платный, удобный |
| Proton Pass | Пользователь Proton | Высокое | Средний | Есть | Зависит от плана | Удобен в экосистеме |
| KeePassXC | Технический пользователь | Среднее | Высокий без backup | Нет обязательного | Полностью на тебе | Хороший local-first |
| Vaultwarden | Админ / lab | Среднее | Зависит от backup | Твой сервер | Полностью на тебе | Не для "поставил и забыл" |
| `pass`/`gopass` | Linux/CLI | Низкое для новичка | Высокий без GPG recovery | Нет обязательного | На тебе | Мощно, но сложно |
| Бумага | Recovery | Низкое | Низкий для аварийки | Нет | Физический | Не для всех паролей |

## 4.10 Что выбрать

### Один человек, обычный старт

Выбирай cloud password manager:

- Bitwarden;
- 1Password;
- Proton Pass, если уже живёшь в Proton.

### Семья

Лучше family plan:

- отдельные личные vault;
- общие записи;
- emergency access;
- понятное управление доступом.

### Программист

Подойдут:

- Bitwarden или 1Password как основной vault;
- KeePassXC как local-first, если понимаешь backup;
- отдельные правила для tokens и SSH.

### Маленькая команда

Не используй личный бесплатный vault как командную систему.

Нужны:

- роли;
- offboarding;
- shared collections;
- владелец recovery;
- аудит доступа.

### Self-hosted

Начинай с lab.

Не переноси реальные пароли, пока не проверил:

- обновление;
- backup;
- восстановление;
- HTTPS;
- доступы;
- логи.
