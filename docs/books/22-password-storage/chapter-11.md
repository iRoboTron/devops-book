# Глава 11: Backup хранилища паролей

> **Запомни:** облачная синхронизация — это не то же самое, что проверенный backup.

---

## 11.1 Зачем backup, если есть синхронизация

Синхронизация отвечает на вопрос:

> Как получить актуальные данные на разных устройствах?

Backup отвечает на другой вопрос:

> Как восстановиться, если данные удалены, повреждены или аккаунт недоступен?

Пример:

```text
Ты случайно удалил 50 записей.
Синхронизация быстро удалила их на всех устройствах.
```

Синхронизация сработала правильно. Но тебе нужен backup.

---

## 11.2 Что может случиться

Сценарии:

- случайное удаление;
- повреждение базы;
- блокировка cloud-аккаунта;
- потеря мастер-пароля;
- ошибка синхронизации;
- ransomware на компьютере;
- неудачная миграция;
- удаление организации или shared vault;
- потеря self-hosted сервера.

Backup нужен не каждый день. Он нужен в плохой день.

---

## 11.3 Export

Export — выгрузка данных.

Типы:

- plain CSV/JSON;
- encrypted export;
- нативный backup формат менеджера;
- копия `.kdbx` для KeePassXC;
- backup data directory для self-hosted.

Plain export опасен, потому что все данные могут быть открыты без пароля.

Если вынужден использовать plain export:

- делай это на чистом устройстве;
- не оставляй файл в Downloads;
- сразу шифруй или удаляй;
- проверь корзину;
- не загружай plain export в облако.

---

## 11.4 3-2-1 для паролей

Классическое правило:

```text
3 копии
2 разных типа носителей
1 копия отдельно
```

Для паролей это может быть:

```text
Основной vault в менеджере
Encrypted backup на внешнем диске
Recovery kit на бумаге
```

Или:

```text
KeePassXC .kdbx на ноутбуке
Копия .kdbx на USB
Копия .kdbx в облаке
```

Главное: backup должен быть защищён.

---

## 11.5 USB-флешка

Плюсы:

- физический контроль;
- можно хранить offline;
- удобно для emergency kit.

Минусы:

- можно потерять;
- может сломаться;
- можно забыть обновить;
- если backup не зашифрован, риск высокий.

Флешка — не магия. Её надо проверять.

---

## 11.6 Encrypted archive

Зашифрованный архив может быть промежуточным вариантом.

Идея:

```text
plain export
  -> зашифрованный архив
  -> удалить plain export
```

Важно:

- пароль архива должен быть сильным;
- пароль архива нельзя хранить рядом с архивом;
- надо проверить, что архив открывается;
- plain export после упаковки удалить.

---

## 11.7 GPG или age для технических людей

Если ты уже пользуешься Linux, можно изучить:

- `gpg`;
- `age`.

Но для обычного читателя это не обязательный путь.

Принцип:

```text
Файл export
  -> шифрование
  -> безопасное хранение
```

Не используй команды с реальными секретами, пока не потренировался на тестовом export.

---

## 11.8 Backup recovery codes

Recovery codes тоже нуждаются в backup.

Можно:

- распечатать;
- положить в сейф/папку документов;
- сохранить в secure note;
- хранить копию у доверенного человека в запечатанном конверте.

Нельзя:

- хранить только на телефоне;
- хранить только внутри аккаунта, для которого эти codes нужны;
- отправлять в чат.

---

## 11.9 Как часто обновлять backup

Простой график:

- после настройки менеджера;
- после добавления критичных аккаунтов;
- после включения MFA;
- раз в 3 месяца;
- перед крупной миграцией;
- после изменения emergency access.

Для активной команды — чаще.

---

## 11.10 Проверка восстановления

Backup считается рабочим только после restore test.

Проверь:

- файл есть;
- файл открывается;
- пароль подходит;
- внутри есть нужные записи;
- ты понимаешь, какая копия последняя;
- plain export не остался рядом.

---

## 11.11 Практика: backup тестового vault

Используй только тестовые данные.

### Задача 1: export

Сделай export тестового vault.

Запиши:

```text
Где лежит файл:
Формат:
Зашифрован ли:
Дата:
```

### Задача 2: защита

Если export plain:

- зашифруй его выбранным способом;
- или помести в защищённое хранилище;
- или удали после проверки.

### Задача 3: restore

Открой backup отдельно.

Проверь:

- записи на месте;
- файл не пустой;
- ты можешь восстановиться без основного устройства.

### Задача 4: cleanup

Удалить:

- plain export;
- временные копии;
- файлы в Downloads;
- лишние копии на рабочем столе.

---

## 11.12 Практика: календарь backup

Создай правило:

```text
Каждые 3 месяца:
  1. проверить critical accounts
  2. обновить export
  3. проверить restore
  4. проверить recovery codes
  5. записать дату
```

Это можно добавить в календарь.
