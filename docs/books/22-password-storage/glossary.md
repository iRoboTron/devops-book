# Глоссарий

> Термины и выражения книги «Хранение паролей». В скобках — главы, где термин вводится или активно используется.

---

**Система хранения доступов** — не одно приложение, а связка слоёв: список аккаунтов, уникальные пароли, менеджер паролей, мастер-пароль, MFA, recovery codes, backup и план восстановления. _(главы 0, 15)_

**Критичный аккаунт** — аккаунт, через который можно получить доступ к другим вещам или потерять деньги, документы и работу (почта, банк, менеджер паролей, домен). _(глава 0)_

**Inventory (карта аккаунтов)** — таблица аккаунтов без самих паролей, с указанием важности, наличия MFA и recovery. Первый шаг любой системы паролей. _(главы 0, 15)_

**Утечка базы паролей** — ситуация, когда данные пользователей сайта (email, логины, хэши или пароли) попадают в чужие руки. _(глава 1)_

**Хэш пароля** — преобразованное значение пароля, которое сайт хранит вместо самого пароля; при утечке слабый пароль из хэша могут восстановить быстрее. _(глава 1)_

**Повторное использование паролей** — один и тот же пароль на разных сайтах; делает утечку одного сервиса опасной для всех остальных. _(главы 0, 1)_

**Credential stuffing** — автоматический перебор украденных пар «email + пароль» на других сайтах в расчёте, что пароль где-то повторялся. _(глава 1)_

**Brute force (перебор)** — попытка угадать пароль автоматическим перебором вариантов; чем длиннее и непредсказуемее пароль, тем дольше это занимает. _(глава 2)_

**Phishing** — обман, при котором тебя убеждают самому ввести логин и пароль на поддельном сайте. _(главы 1, 3, 9)_

**Malware / keylogger** — вредоносная программа, способная украсть пароль прямо во время ввода; менеджер паролей не спасает от заражённого устройства. _(глава 1)_

**Shoulder surfing** — подсматривание пароля «через плечо» или при демонстрации экрана. _(глава 1)_

**SIM swap** — захват чужого номера телефона (через обман оператора), из-за чего SMS-MFA становится слабым звеном. _(главы 1, 8)_

**Пароль (password)** — обычная строка для входа; для рядовых сайтов её должен генерировать менеджер, а не запоминать человек. _(глава 2)_

**Passphrase (парольная фраза)** — пароль из нескольких случайных слов; длинный, запоминаемый, удобен как мастер-пароль. _(главы 2, 3)_

**Длина важнее сложности** — принцип, по которому длинная фраза из случайных слов надёжнее короткого пароля с заменами символов вроде `a → @`. _(глава 2)_

**Предсказуемые замены** — известные программам подбора подстановки (`a → @`, `o → 0`, `i → 1`), которые почти не добавляют стойкости. _(глава 2)_

**Личные ассоциации** — имена, даты, питомцы, город: делают фразу предсказуемой, поэтому в мастер-пароле их использовать нельзя. _(глава 2)_

**Мастер-пароль** — единственный пароль, который открывает менеджер паролей; его нельзя сбросить в серьёзных менеджерах и нельзя использовать больше нигде. _(главы 2, 3, 5)_

**Менеджер паролей** — зашифрованное хранилище, которое хранит, генерирует, автозаполняет пароли и держит secure notes. _(главы 0, 3, 4)_

**Vault (хранилище)** — зашифрованная база записей внутри менеджера; без ключа выглядит как бессмысленные данные. _(главы 3, 5)_

**Вывод ключа из мастер-пароля** — преобразование мастер-пароля в ключ шифрования на твоём устройстве; сервис хранит зашифрованный vault, но не знает мастер-пароль. _(глава 3)_

**Login vs Unlock** — login это вход в аккаунт менеджера (email + мастер-пароль + MFA), unlock это быстрая локальная разблокировка уже открытого приложения (PIN, биометрия). _(глава 3)_

**Генератор паролей** — функция менеджера, создающая длинный случайный пароль, который не нужно запоминать. _(главы 3, 5)_

**Автозаполнение** — подстановка логина и пароля по совпадению домена; защита от фишинга, потому что на чужом домене пароль не подставляется. _(главы 3, 5)_

**Browser extension** — расширение браузера для автозаполнения и сохранения логинов; ставить нужно только из официального источника. _(главы 3, 5)_

**Secure note** — защищённая заметка внутри менеджера для recovery codes, инструкций и лицензий. _(главы 3, 5)_

**Export** — выгрузка данных из менеджера для backup или миграции; бывает plain и encrypted. _(главы 3, 5, 11)_

**Plain export** — незашифрованная выгрузка (CSV/JSON), где все пароли открыты любому, кто получил файл; использовать только временно. _(главы 3, 11)_

**Encrypted export** — зашифрованная выгрузка, защищённая отдельным паролем; безопаснее plain export. _(главы 5, 11)_

**Браузерный менеджер** — встроенное в браузер хранилище паролей; удобный старт, но привязан к экосистеме и слабее для семьи и команды. _(главы 0, 4)_

**Cloud password manager** — облачный менеджер (Bitwarden, 1Password, Proton Pass) с синхронизацией; требует доверия сервису, сильного мастер-пароля и MFA. _(главы 4, 5)_

**Local password manager** — менеджер, хранящий пароли в локальном файле (KeePassXC); контроль выше, но backup полностью на пользователе. _(главы 4, 6)_

**Self-hosted менеджер** — менеджер на своём сервере (Vaultwarden); не безопаснее автоматически, добавляет ответственность за сервер, HTTPS, обновления и backup. _(главы 4, 7)_

**Bitwarden** — облачный менеджер паролей, выбранный в книге как практический пример настройки с MFA, extension и recovery. _(глава 5)_

**KeePassXC** — local-first менеджер, хранящий пароли в файле `.kdbx`. _(главы 4, 6)_

**`.kdbx`** — зашифрованный файл базы KeePassXC; главный объект, за backup которого отвечает сам пользователь. _(глава 6)_

**Key file** — дополнительный файл-ключ KeePassXC: усиливает защиту, но при потере делает базу недоступной. _(глава 6)_

**Vaultwarden** — лёгкая self-hosted реализация сервера, совместимая с клиентами Bitwarden. _(главы 4, 7)_

**Data directory (`./vw-data`)** — папка с данными Vaultwarden (база, attachments, конфиг); важнее контейнера, потеря папки означает потерю данных. _(глава 7)_

**Local-first** — подход, при котором главное хранилище лежит у тебя локально, а облако не обязательно. _(глава 6)_

**Конфликт копий** — расхождение версий базы, когда её редактировали одновременно на разных устройствах. _(глава 6)_

**MFA (multi-factor authentication)** — многофакторная аутентификация: для входа нужен не только пароль, но и второй фактор. _(главы 1, 8)_

**Фактор аутентификации** — способ доказать владение аккаунтом: что ты знаешь (пароль), что у тебя есть (телефон, ключ), кто ты (биометрия). _(глава 8)_

**SMS-MFA** — код по SMS; лучше, чем ничего, но уязвим к SIM swap и задержкам. _(главы 1, 8)_

**Email-код** — код подтверждения на почту; нормален как дополнительная проверка, но делает почту особо критичной. _(глава 8)_

**TOTP** — одноразовый код из приложения (Aegis, 2FAS, Google/Microsoft Authenticator), обновляемый каждые ~30 секунд; QR при настройке — это секрет. _(главы 5, 8)_

**Push-подтверждение** — запрос «это вы входите?» в приложении; удобно, но уязвимо к MFA fatigue. _(глава 8)_

**MFA fatigue** — усталость от частых push-запросов, из-за которой человек по привычке подтверждает чужой вход. _(глава 8)_

**Hardware security key** — физический ключ (YubiKey, Titan, SoloKeys) стандарта FIDO2/WebAuthn; сильная защита от фишинга, желательно иметь два. _(главы 8, 9)_

**Recovery (восстановление)** — план возврата доступа при потере пароля, телефона, ключа или почты; часть системы, а не её слабость. _(главы 8, 10)_

**Recovery codes** — одноразовые аварийные коды, выдаваемые при включении MFA; хранятся отдельно от устройства с TOTP. _(главы 5, 8, 10, 11)_

**Замкнутый круг recovery code** — ошибка хранения единственного аварийного кода внутри того же аккаунта, для входа в который он нужен. _(глава 5)_

**Backup email** — почта для восстановления аккаунта; должна быть защищена MFA и уникальным паролем, иначе становится дырой. _(глава 10)_

**Emergency access** — механизм передачи доступа доверенному лицу в чрезвычайной ситуации (болезнь, смерть, недоступность владельца). _(глава 10)_

**Recovery kit** — набор информации для восстановления (имя менеджера, email, где лежат codes и backup, кто trusted contact); не обязан содержать сам мастер-пароль. _(главы 10, 15)_

**Passkey** — вход без пароля на основе пары ключей: приватный остаётся на устройстве, публичный лежит на сервере. _(глава 9)_

**Приватный / публичный ключ** — пара ключей passkey: приватным устройство подписывает challenge, публичным сервер проверяет подпись. _(глава 9)_

**Challenge** — случайные данные плюс домен сайта, которые сервер присылает устройству для подписи; встроенный домен и даёт защиту от фишинга. _(глава 9)_

**Platform authenticator** — встроенный механизм устройства для passkeys (iCloud Keychain, Google Password Manager, Windows Hello, Touch ID). _(глава 9)_

**Roaming hardware key** — переносной физический ключ для passkeys/входа, не привязанный к одному телефону. _(глава 9)_

**WebAuthn / FIDO2** — стандарты, на которых работают passkeys и аппаратные ключи. _(главы 8, 9)_

**Синхронизация vs backup** — синхронизация повторяет любое изменение (включая удаление) на всех устройствах; backup это отдельная копия, к которой можно вернуться. _(глава 11)_

**Правило 3-2-1** — три копии, два типа носителей, одна копия отдельно; применимо и к хранилищу паролей. _(глава 11)_

**Restore test (проверка восстановления)** — открытие копии backup и проверка записей; без него backup это надежда, а не backup. _(главы 6, 7, 11)_

**3-2-1 для recovery codes** — хранение аварийных кодов в нескольких безопасных местах (печать, secure note, конверт у доверенного лица), но не только на телефоне и не в чате. _(главы 8, 11)_

**SSH-ключ** — пара private/public для доступа к серверам и GitHub; приватный ключ нельзя отдавать никому. _(главы 2, 12)_

**Passphrase на SSH-ключ** — пароль, защищающий приватный ключ: украденный файл сложнее использовать. _(главы 2, 12)_

**Personal Access Token (PAT)** — токен вместо пароля для сервиса; должен иметь минимальные права и срок жизни, может быть отозван. _(глава 12)_

**Принцип минимальных прав** — токен и доступ выдаются ровно под задачу, а не «full access forever». _(главы 12, 13)_

**`.env`** — файл с секретами проекта (DATABASE_URL, SECRET_KEY, токены); не коммитится, должен быть в `.gitignore`. _(глава 12)_

**`.env.example`** — шаблон `.env` с заглушками вместо реальных значений; его можно держать в репозитории. _(глава 12)_

**`git rm --cached`** — команда, прекращающая отслеживание файла в Git без удаления его с диска; нужна, если `.env` уже попал в репозиторий. _(глава 12)_

**Ротация секретов** — замена токенов, паролей и ключей при утечке или уходе сотрудника; удаление из истории Git её не заменяет. _(главы 12, 13)_

**CI/CD secrets** — секреты для деплоя и доступа к API в пайплайнах; не печатаются в лог, выдаются с минимальными правами. _(глава 12)_

**Shared vault** — общее хранилище выбранных записей для семьи или команды; личные пароли при этом остаются личными. _(глава 13)_

**Shared collections** — общие наборы записей с ролями и управляемым доступом в командном менеджере. _(глава 13)_

**Offboarding** — процедура отзыва всех доступов при уходе человека (shared vault, токены, SSH keys, ownership). _(глава 13)_

**Общий аккаунт** — один логин на всех; затрудняет MFA, аудит и отзыв доступа, поэтому предпочтительнее индивидуальные аккаунты. _(глава 13)_

**Миграция паролей** — постепенный перенос аккаунтов на новую систему по приоритету, а не за один вечер. _(глава 14)_

**Импорт из браузера** — массовый перенос паролей из браузера в менеджер; начало уборки, а не финал — требует последующей чистки. _(глава 14)_

**Reused passwords (повторяющиеся пароли)** — предупреждение менеджера об одинаковых паролях; исправляются по приоритету, начиная с критичных. _(глава 14)_

**Have I Been Pwned** — публичный сервис проверки email на присутствие в известных утечках; вводить туда (как и куда-либо ещё) реальный пароль нельзя. _(глава 1)_
