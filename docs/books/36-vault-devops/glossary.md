# Глоссарий

> Термины и выражения книги «HashiCorp Vault для DevOps». В скобках — главы, где термин вводится или активно используется.

---

**Vault** — система централизованного хранения секретов и управления доступом к ним. _(глава 0)_

**Секрет** — чувствительные данные: пароли, токены, ключи, сертификаты. _(глава 0)_

**Path (путь)** — адрес внутри Vault, по которому лежат секреты или смонтирован движок. _(глава 2)_

**Secrets Engine (движок)** — модуль, отвечающий за определённый тип секретов (KV, database, PKI, transit). _(главы 2, 3)_

**Mount (монтирование)** — подключение движка по заданному пути. _(глава 2)_

**Token (токен)** — идентификатор, по которому Vault определяет, кто ты и что тебе можно. _(главы 2, 5)_

**Lease (аренда)** — срок жизни секрета/токена, по истечении которого он отзывается. _(глава 2)_

**TTL** — время жизни lease/токена. _(глава 2)_

**KV Secrets Engine** — движок для хранения статических секретов «ключ-значение». _(глава 3)_

**Policy (политика)** — правила доступа: какие capabilities на какие пути. _(глава 4)_

**Capability** — разрешение на путь: `read`, `create`, `update`, `delete`, `list`. _(глава 4)_

**Auth Method (метод аутентификации)** — способ входа в Vault: Token, AppRole, UserPass, LDAP. _(глава 5)_

**AppRole** — машинный метод входа (role_id + secret_id) для приложений и CI. _(глава 5)_

**UserPass / LDAP** — вход по логину-паролю и через корпоративный каталог. _(глава 5)_

**Dynamic Secrets (динамические секреты)** — секреты, которые Vault создаёт по запросу и сам отзывает (например, временный пароль к БД). _(глава 6)_

**Database Secrets Engine** — движок, выдающий временные учётки к базам данных. _(глава 6)_

**Transit Engine** — «шифрование как сервис»: Vault шифрует/дешифрует данные, не храня их. _(глава 7b)_

**PKI Engine** — движок генерации TLS-сертификатов. _(глава 7)_

**Root / Intermediate CA** — корневой и промежуточный центры сертификации в PKI. _(глава 7)_

**Vault Agent** — сайдкар/демон, автоматически получающий и обновляющий секреты для приложения. _(глава 8)_

**Auto-auth** — автоматическая аутентификация Vault Agent без ручного ввода токена. _(глава 8)_

**Template (шаблон)** — рендеринг секрета в файл конфигурации приложения. _(глава 8)_

**Seal / Unseal** — «запечатанное» (зашифрованное) состояние Vault и процесс его «распечатывания». _(глава 11)_

**Shamir / unseal keys** — разделение мастер-ключа на части; для unseal нужно собрать кворум. _(глава 11)_

**Raft** — встроенное хранилище Vault с репликацией для отказоустойчивости (HA). _(глава 11)_

**HA (High Availability)** — режим из нескольких узлов Vault с автоматическим выбором лидера. _(глава 11)_

**Backup (snapshot)** — резервная копия хранилища Vault (Raft snapshot). _(глава 11)_

**Audit Device** — журнал всех обращений к Vault для аудита. _(глава 12)_

**Root Token** — всемогущий токен; используется только для первичной настройки и отзывается. _(главы 1, 12)_

**Revoke / Renew** — отзыв секрета/токена до срока и продление его lease. _(главы 2, 12)_

**Kubernetes Auth** — метод входа, при котором Pod аутентифицируется в Vault своим ServiceAccount. _(глава 10)_
